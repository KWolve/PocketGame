## 1. 数据来源（本板实测确认）

| 项 | 走哪 | 说明 |
|---|---|---|
| 电量/电压 | `AdcHelper`（底层 `/sys/class/gpadc/{adc_ch,adc_enable,adc_val}`） | **通道 0**；12bit（0~4096） |
| 已充满 | `GpioHelper::input("GPIO_135")` | 高有效 |
| 充电中 | `GpioHelper::input("GPIO_5")` | 高有效 |
| 低电 LED | `GPIO_136` | 参考工程会驱动，**本工程暂未启用**（见 §5） |
| 支持关机 | `soc@03000000:sysKeys/sys5v` 存在即可（写 `0` = 断电） | 参考工程的 `POWER_OFF_NODE`，本板同款 |

两个接口都来自 **`zkhardware` 包**（本工程 Manifest 已有该依赖），
直接 `#include "utils/AdcHelper.h"` / `#include "utils/GpioHelper.h"` 即可，
不需要自己写 sysfs 读写。

> ⚠️ **内核 DT 里没有电池/充电/ADC 的任何定义**（已逐项查过：
> `/sys/class/power_supply` 为空、无 iio、无 platform 电池设备）。
> 所以"哪个通道是电池、分压多少"这类信息**只能**来自参考工程，别自己猜。

## 2. 公式与节奏（一字不改照抄）

```cpp
ADC_REF_VOL    = 1800 mV      // ADC 参考电压
ADC_DIVIDER_R1 = 200 Ω        // 上分压
ADC_DIVIDER_R2 = 150 Ω        // 下分压（采样点）
BATTERY_V_MAX  = 4150 mV      // 满电
BATTERY_V_MIN  = 3380 mV      // 没电

voltage = value / 4096.0 * 1800 * (150 + 200) / 150          // mV
percent = clamp((voltage - 3380) / (4150 - 3380), 0, 1)*100  // 原文再 +0.005 取整
```

- **滤波 = 累计 5 次采样取平均**，**电量约每 30 秒才更新一次**；
- 充电状态约每 **500ms** 查一次，**判定顺序：先"已充满"，再"充电中"**，都不是 = 未充电；
- 低电阈值 **`BATTERY_LOW = 20`%**（参考工程客户模式是 9，本工程用默认值）；
- 开机**立刻读一次**并发布，避免前 30 秒没有值。

### 3.1 显示 = **一枚整图 = 一个完整状态**（2026-09-16 用户要求改版）

用户原话：**「电池图标不对。做成对应的图片直接贴就不存在错位了」**。

| 项 | 值 |
|---|---|
| 控件 | `ui/navibar.html` 的 **`ImgNbBatt`**（52×26 @ (378,13)，就这一个） |
| 素材 | `images/batt_<blue\|red\|amber>_<0..100 每 10 一档>.png` —— **3 色 × 11 档 = 33 张**，52×26 |
| 图内含 | 外壳圆角描边 + 正极头 + 电量条（内缩 3px，宽 = 40 × 档位%）+ **充电闪电**（只在 amber 档） |
| 运行时 | `navibar.cc` 只 `setBackgroundPic("images/batt_<色>_<档>.png")` —— **永不 setPosition** |

状态表现（色 + 长度 + 闪电，与旧版语义一致）：

| 状态 | 色档 | 闪电 |
|---|---|---|
| 未充电 | `blue`（`ACCENT`） | 无（烘在非 amber 档里） |
| 低电（≤`BATTERY_LOW`=20% 且没充电） | `red`（`DANGER`） | 无 |
| 充电中 / 已充满 | `amber`（`DATA`） | **有**（白色闪电烘在同一张图里） |
| 读不到电量 | `level 0`（空电池，只剩外壳） | 无 |

#### ⚠️⚠️ 为什么从"三控件拼"改成"一枚整图"（血案，别再改回去）

上一版是 **3 个控件拼**：外壳（静态图）+ 电量条（运行时 `setPosition(x, y, w, h)` 改宽度）
+ 闪电（`setVisible`）。电量条的 y 由 `navibar.cc` 的**常量**给，而源稿
`ui/navibar.html` 里声明的 y 是另一个值 ⇒ **两个来源必然漂**，实测电量条比外壳**高 11px、
顶出壳外** —— 那就是用户看到的"电池图标不对"。

⇒ 现在的判据：**任何"图 + 运行时定位"的组合，都换成"把几何烘进图里、运行时只换图"**。
   图与控件严格 1:1（52×26），框架不会缩放，也不存在对不齐。
   电量档取 10% 一档（`kBattStep`）：够用，且每档宽度是整数（10% → 4px），不出现半像素。
   ⚠️ 生成器里有**尺寸自检**（写盘后回读校验 52×26），因为"图尺寸 != 控件尺寸 ⇒ 框架缩放"
     这条铁律本工程已经栽过多次。

#### 低电 / 充电怎么复现（设备常年插着 USB，等不到低电）

```
echo 'battfake 12 0' > /tmp/pg_autostart     # 12% 未充电 → 红 + 短条
echo 'battfake 80 1' > /tmp/pg_autostart     # 80% 充电中 → 琥珀 + 闪电
echo 'battfake off'  > /tmp/pg_autostart     # 恢复真实读数
```
（`battfake <pct> <state>`，state：0=未充电 / 1=充电中 / 2=已充满 / 3=异常；
**只影响对外读数**，真实 ADC 采样与日志不受影响。见 `mainLogic.cc` 的 QA 表。）

⚠️ **只在"电量档或色档真的变了"时才写控件**：每帧无条件 `setBackgroundPic/setText`
会触发重绘风暴（本工程踩过：渲染线程自旋、CPU 127%、日志全停，看着像崩溃）。

⚠️ **只在"文案或颜色真的变了"时才写控件**：每帧无条件 `setText/setTextColor` 会触发
重绘风暴（本工程踩过：`R` 状态、渲染线程自旋、CPU 127%、日志全停，看着像崩溃）。

## 4. 真机验收（2026-09-13）

| 项 | 结果 |
|---|---|
| 自检命令 | `batt` → `电量 100% 电压 4175mV ADC 4072 状态 已充满 低电=0` |
| 原始 ADC | `battraw` → `4072 4072 4072 4072 4072 4073 4072 4072`（**抖动 ±1**） |
| 是否真实模拟量 | 抖动只有 ±1（悬空脚噪声更大）；**硬解播视频（高负载）时 4072 → 4074 略升** —— 符合"插着充电器把电压顶住" |
| 状态机 | 日志能看到充电芯片的真实翻转：`充电状态 充电中 → 已充满`（充满判定回跳是正常的） |
| 界面（`fb0` 截图 + `tools/battregion.py` 逐像素分类） | 图标五层**层级正确**（外壳框 46×26 / 挖空 / 电量条 / 闪电压在电量条上 / 右侧正极头 5×12），见下表 |

**界面图标四状态真机验收**（用 `battfake` 逐个伪造；判定 = 逐像素分类，不靠肉眼）：

| 伪造状态 | 电量条实测 | 颜色 | 闪电 | 结论 |
|---|---|---|---|---|
| 15% 未充电 | 6 px（= 40×15%） | **红** `#E4574C` | 无 | ✅ |
| 50% 未充电 | 20 px（= 40×50%） | **蓝** `#5CA8E2` | 无 | ✅ |

## 5. 待办 / 未做（如实说明）

1. **"真实放电"未验证**：设备一直插着 USB（充电中），所以只能读到"已充满"。
   要彻底闭环需**拔掉 USB** 看百分比下降 + 状态变"未充电"。
   已把设备开了 `adb tcpip 5555`（`192.168.0.125:5555`），**拔了 USB 也能继续读**。
2. **低电 LED（`GPIO_136`）未启用**：参考工程在低电时会驱动它闪烁，
   但本工程是另一个产品，无法确认该脚是否被别的东西占用，所以**没动它**。
   需要的话按参考工程写法加上（`output(LED_GPIO, blink)` / `input(LED_GPIO)` 悬空即灭灯）。
3. 电量只在**主界面**显示；游戏内/其它页面暂未显示（需要就说一声）。

## 6. QA 命令

| 命令 | 作用 |
|---|---|
| `batt` | 立刻刷新并打印 `电量% / 电压mV / 原始ADC / 充电状态 / 是否低电` |
| `battraw` | 连采 8 次原始 ADC 值（现场标定通道/分压用） |
| `battfake <电量> <状态>` | ⚠️ **仅自检**：伪造读数验收图标各状态（`0`=未充电 `1`=充电中 `2`=已充满；`off`=恢复）。只影响对外读数，不动真实采样 |

配套自检脚本：`python tools/battregion.py <截图.png>` —— 把电池图标那一小块做 1:1 分类渲染，
直接报"电量条几像素 / 什么颜色 / 有没有闪电"（AI 看不了图时的数值化验收手段）。
