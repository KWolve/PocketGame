## A · html2json（设计稿 → JSON 转换器）

### A1 · 字符黑名单静默丢符号　★★【改】
- **现象**：`⌫ ℃ ■ ● ‹ ＋ – … → ★ ◆ ▶ ▷ ①` 等写在 `data-caption` 里，**整字消失**（不是方框）。
- **根因**：html2json 有内置字符黑名单，命中即丢弃，**无任何 warning**。另叠加：字库缺字形的字符也是整字消失。
- **绕过**：改用图片素材或换字符。
- **建议**：① 黑名单改白名单（或至少放行全角常用符号）；② 转换期对"黑名单丢弃 + 字库无字形"统一输出 warning 清单。

### A2 · 纯黑 `#000000` 被当作"没设置"　★★【改】
- **现象**：`data-color="#000000"` 落地 JSON 变成 `#EEF2F6`（近白）→ 绿按钮成了"绿底白字"（对比度 1.44:1）。
- **根因**：转换器用 `0` 值判断"用户没写颜色"，而纯黑的数值就是 0。
- **绕过**：要纯黑写 `#010101`。
- **建议**：用"属性是否出现"而不是"值是否为 0"判断未设置。

### A3 · listview subItem 丢 `data-bg`、不能挂圆角图　★【改/文档】
- **实测**：subItem 既不挂圆角九宫格、`data-bg` 也被丢掉 ⇒ 行内做不出"带底色的块"；文字/图标直接画在行底上。
- **好处是天生没有黑角，代价是行内视觉受限**。行内多热区靠 `onListItemClick(view, index, id)` 的 `id` 分派可行（官方口径）。
- **建议**：subItem 支持 `data-bg`；或文档明示该限制。

### A4 · edittext 分支不生成 `touchable`/`visible`　★★【改】
- **现象**：输入框可见、有底色和提示文字，**点了完全没反应、IME 不弹出**（极易误判成"IME 没注册"）。
- **根因**：html2json 的 `edittext` 分支漏写 `touchable`（`button`/`subItem`/`seekbar` 分支都写了）。
- **绕过**：工程内 `tools/gen_ui.py::patch_edittexts()` 事后补字段。
- **建议**：对齐其他控件分支，补 `'touchable': True, 'visible': True`。

### A5 · 不支持 `data-visible`，初始显隐无入口　★【改】
- **实测**：html2json 不认识 `data-visible` ⇒ "某控件初始就该隐藏"只能靠运行时代码 patch，且控件名要在生成器 `HIDDEN_CONTROLS` 与 patch 逻辑**两处同步**，漏一处即静默失败。
- **建议**：支持 `data-visible` 直通到 JSON 的 `visible` 字段。

### A6 · 有图按钮不写 `bgColorTab`（挂图清成 -1）　★★【改】
- **现象**（P4 用户报障"图标角落都是黑的"）：带圆角九宫格的控件坐在卡片（非黑容器）上时，四角显示纯黑。
- **根因**：html2json 对有图的按钮干脆不写 `bgColorTab`（= -1），圆角外四角透出的是**窗口黑底**而不是它下面卡片的颜色。真机逐点：四角 `(0,0,0)` / 卡片 `(28,28,30)`。
- **绕过**：坐卡片上的底板一律"1:1 普通 PNG + 圆角外烘容器色"（如 `ha_domchip_64.png`）；静态九宫格烘透明底 + 运行时 `inject_rounded()` 按"几何包含它的最小有色控件"填 `bgColorTab`。
- **注意**：`bgColorTab` 只管最外 1px，圆角里侧 4~5px 的黑是图里的像素，补色救不回来。
- **建议**：html2json 保留源稿里 `data-bg` 语义到 `bgColorTab`；至少在文档里写清"圆角控件的底色由谁负责"。

### A7 · 嵌套控件不计入统计/测试脚本　★【改】
- **实测**：`ui_preview` 对 50 控件的页面报 `controls: 1`；`gen_ui_test(traverse)` 产出 0 个可测控件 —— 都只数根层。交互控件全在 window/card 里的页面（键盘页、弹窗）自动化遍历**完全覆盖不到**。
- **建议**：统计与脚本生成递归收集，或返回"根层 N / 嵌套 M"。

### A8 · 转换规则零文档、零 warning　★★【文档+改】
- **实测**：黑名单字符表、颜色默认值规则、哪些 `data-*` 属性被丢、`data-cols`/`data-row-spacing` 的计算公式……**全部只能靠真机反推**。本工程为此沉淀了整篇 `kb-html2json-static-art.md`。
- **建议**：① 官方出一份"html → json 转换规则"文档（属性直通表 / 丢弃表 / 默认值表）；② 转换器对"识别不了、丢弃了、替了默认值"的操作**统一打 warning**——这是性价比最高的一条改进。

## B · easyui 引擎运行时

### B1 · 运行时 `setBackgroundPic` 不保留 alpha　★★【文档/改】
- **实测**：静态 JSON 挂图路径做 alpha 合成（半透明遮罩 α=204 实测背景被压成"原色×0.2"），但**运行时换图那条路不保留 alpha** —— 透明底 PNG 直接变白块。
- **绕过**：素材分两套——静态套烘透明底、运行时套烘不透明底（四角烘容器色）。
- **建议**：两条渲染路径统一 alpha 语义；至少文档高亮。

### B2 · listview subItem 图片不按行区分　★★【改】
- **实测**：subItem 的图片所有行共用，做不到"每格不同图"（HA 磁贴 13 域 × 3 档只能改成**每格独立控件**，控件数量暴涨）。
- **建议**：支持 subItem 按数据行取图（文件名模板/回调均可）。

### B3 · 浮层吃触摸，"穿透"语义不存在　★★【文档】
- **实测**：`touchable=false` 的浮层**仍然挡住**下层点击；要能点的按钮**每层祖先都 `touchable=true`**。查"点了没反应"的固定顺序：查遮挡 → 查越界 → 注入定位（有 `touch:` 无 `click` = 有浮层在挡）。
- **建议**：文档明示浮层事件模型，避免使用者期待"透明即穿透"。

### B4 · textview 不自动省略　★【文档】
- **实测**：超长文本直接溢出/裁切，需按**像素宽**预截断（经验值 ASCII 0.55×字号 / CJK 1.0×字号）。
- **建议**：支持 `ellipsize` 属性。

### B5 · `setProgress()` 也会异步触发 `onProgressChanged`　★【文档】
- **实测**：代码设进度同样触发回调（异步）⇒ 回调里必须区分"用户拖动"与"程序设置"，否则死循环/状态抖动。
- **建议**：回调加来源参数，或文档明示。

### B6 · 程序化 `setText` 同步触发 `onEditTextChanged_*`　★【文档】
- **实测**：翻页回填/清空输入框会被当成"用户输入"（wifi 密码框、HA 命名页都踩过）⇒ 需静默标志位挡回调。
- **建议**：提供 `setText(silent=true)` 类 API。

### B7 · `showPage()` 收起背景页 → 弹层背景全黑　★★【文档/改】
- **实测**：普通 window 走 `showPage()` 会把背景页 `hideWnd()` ⇒ 半透明遮罩后面全黑。正解 = `class="modal"`（画在当前窗口之上、父页保持可见）+ 窗口背景透明 + 遮罩 α=204。
- **连带坑**：页面的隐藏窗口列表（工程侧 `HIDDEN_PAGE_WINDOWS`）会把窗口强制改回 `modal=false` ⇒ modal 弹层不能列进去；弹层时要先放背景页再放弹层。
- **建议**：官方文档收录"弹层三件套"（modal + 不铺黑 + 半透遮罩），并说明 showPage 与 modal 的相互作用。

### B8 · `hintSay()` 只写首页提示行　★【文档】
- **实测**：在二级页上提示用户 = 静默失败（写到首页去了）。每个二级页要有自己的反馈位。
- **建议**：`hintSay` 改为"写在当前前台页"，或提供 `hintSay(window)` 重载。

### B9 · ~~画布限制：`scale` 不能是变量、宽 ≤448px~~　【**已撤销 2026-09-30**】

> ⛔ **本条作废，不要修**。经复核（框架方 2026-09-30 两次更正 + 本工程溯源），这条**根本不是框架问题**：
>
> - 「`scale` 不能是变量」的真因是**我们的自研字库只预烘有限档**（`PG_FONT_MAX_N=5` / 大号数字 3），
>   档位必须是编译期常量，传任意值会走**位图放大 = 拉伸**（违反我们自己的“不许拉伸”要求）。
>   **FlyThings 画布/GUI 对 `scale` 没有任何上限**。
> - 「宽 ≤448px」是**本工程某 UI 的内容区宽**（480 − 2×16 的布局值），
>   **不是画布宽上限**。
>
> **教训（已写进本清单的使用说明）**：上报前必须能回答“**这条约束是谁定的**——
> 引擎 API / 我们的工具链 / 本 UI 布局”。答不出就不许写进缺陷清单——
> 否则会把自家工程约束推给框架组，浪费双方一轮。（本条已扩散到 MCP 知识库，
> 已由厂家侧新建 `devflow/render-extension-boundary.md` 更正。）
>
> **仍成立的画布限制只有两条**：动画计时必须用**绝对时钟**；**画布必须盖满面板**（否则露上一款应用的残留帧）。

## C · 素材与九宫格

### C1 · `.9.png` 经 `data-bgpic` 不剥最外 1px marker　★★【改】
- **现象**（用户报"列表背面有两条横线"）：marker 是不透明黑时，每张卡片四周多一圈 1px 黑边，上下相邻叠成 2px 黑缝。
- **根因**：九宫格标记线本应剥离，`data-bgpic` 路径没剥。
- **绕过**：坐卡片的底板改用 1:1 普通 PNG + 圆角外烘容器色；或 marker 直接画成容器色。
- **建议**：统一剥离 marker；审计工具 `tools/audit_resources.py` 已实现 marker 规范检查可参考。

### C2 · `.9.png` 有 1px 内缩 → 最外圈露 `bgColorTab`　★【文档】
- **实测**：内缩 1px 后露出的底色取 `bgColorTab`，所以它必须 = 圆角图底色（见 A6 的坑）。圆角黑角的真机判据：**量角的完整 8×8 邻域**，不是只量最外 1 个像素（只量外圈会得出"已修好"的假结论）。

## D · fun 工具链 / 部署与固化

### D1 · `fun build` 终端直跑挂 CMake　★★【改】
- **现象**：`ninja` 不在终端 PATH ⇒ `CMAKE_MAKE_PROGRAM-NOTFOUND`，构建挂死。
- **修法四步**：`pip install --user ninja` → 前置 PATH → 删 `.fun/v85x/CMakeCache.txt` → 手动补 configure。**别删 `.fun/v85x` 整目录**（工程无 git）。
- **建议**：fun 启动时自检 ninja 并给出上述指引；或 CMake 参数由 fun 自带绝对路径。

### D2 · `fun launch` 多设备必失败且输出被吞　★★【改】
- **现象**：USB + WiFi adb 同时在线时报 `more than one device`，**但输出被吞** ⇒ 表现为"命令成功但资源没推上去"，设备继续跑旧 ftu，极易误判成"改动没生效/控件没渲染"。
- **判据**：比对设备侧 `/tmp/ui/main.ftu` 字节数与本地。
- **建议**：fun 全家检测多设备时报错并要求 `-s`；**错误输出绝不允许吞**。

### D3 · `fun launch` 暂存 tmpfs → 大应用 OOM　★★【文档】
- **实测**：launch 把应用推到 tmpfs，大贴图/视频应用直接把 `zkgui_ui` OOM 杀掉 ⇒ **大应用必须用固化版验收**。
- **建议**：文档明示 launch 与固化两条验收路径的资源差异。

### D4 · 改 `resources/images` 的 PNG 后 build 不刷新 imgout　★【改】
- **实测**：图片改动不触发 imgout 重拷 ⇒ 改了素材跑旧图。需手动清 imgout。
- **建议**：图片加入构建增量监控。

### D5 · 打包产物不可复现　★【文档】
- **实测**：同参数连打两次 `update.img` 差 32 万字节（squashfs 重建带文件 mtime）⇒ **md5 不能判断"代码有没有变"**，要比就比 `libzkgui.so` 或直接验功能。
- **建议**：squashfs 打包固定 mtime（`SOURCE_DATE_EPOCH` 模式），产物即可复现。

### D6 · 固化后 ~3 分钟设备自重启、mtd3 squashfs superblock 丢失　★★【改】
- **现象**（P5 血案，两次复现）：升级脚本报"完成、/res 正常"，约 3 分钟后设备自己整机重启，起来后 `/res` 没挂上（`/proc/mounts` 无 mtd 条目）⇒ 应用起不来、QA 无响应。**判据 = `/proc/uptime` 只有 20 多秒**。
- **恢复**：原样重跑一次升级脚本（自带"卸载→擦→写→挂回"），实测一次成功；**绝不手工 mount/dd 回写**。同理**绝不可连着整机 reboot**（superblock 会丢）；重启应用用 `setprop ctl.restart zkswe`。
- **建议**：① 排查升级写入后 superblock 易丢的根因（疑与写后未稳定落盘/重复触发有关）；② 升级完成后脚本自动等待观察 3~5 分钟再报成功；③ 文档明示"固化完成 ≠ 结束"。

### D7 · `lib-no-link` 打包/运行时路径零文档　★【文档】
- **实测**：`fun pack` 把 `lib-no-link/*.so` 放进镜像 `lib/`（设备上即 `/res/lib/`），设备 `LD_LIBRARY_PATH` 本就含 `/res/lib` ⇒ 固化后直接可用；但 **`fun launch` 不推这个目录**（调试期要手动 push 到 `/data` 或 `/tmp`）；⚠️ 手推到 `/data` 会**遮蔽** `/res/lib` 的固化版（`/data` 在 ld 路径最前）→"升级了库却跑旧库，日志毫无异常"。
- **建议**：wiki 该小节补"打包到哪、运行时找不找得到"四行说明（见 MCP 清单 I4 补丁文本）。

## E · 系统层 / BSP

### E1 · rootfs 缺 coreutils　★★【改】
- **实测**：本板 shell **没有** `grep` / `head` / `tail` / `stat` / `awk` / `sleep` / `date` / `printf` / `which` / `dmesg`。最毒的组合：`printf 'x' > /tmp/f` **先把文件截空再报 not found**，而调用方只 capture stdout ⇒ stderr 被吞 ⇒ 静默失败（QA 一条没执行、画面不刷新，误判成"应用卡死"）。
- **绕过**：一律 `echo` 写文件；执行外部命令时 stderr 一起收；`pginj` 等工具放 `/data + chmod 755`（`/tmp` 下 Permission denied）。
- **建议**：rootfs 把 busybox 的这些 applet 链接补齐 —— 一条命令的成本，消除一整类静默失败。

### E2 · logcat 缓冲只十几行　★★【文档】
- **实测**：日志缓冲极小 ⇒ "定时器还在不在跑"这类问题在日志里**看不出来**。判据必须落文件（工程惯例：心跳文件 `/tmp/pg_ha_tick.txt` 持续增长即活着）；`/tmp` 重启即失。
- **建议**：默认 logcat 缓冲调大；或文档明示"判据落文件"纪律。

### E3 · 触摸注入的 MT-B 协议坑　★★【改】
- **实测**（`axs_ts` 面板，MT 协议 B，`ABS_X/ABS_Y` range = 0..0）：
  1. 注入发 type-A 的 `SYN_MT_REPORT` 在 B 设备上**整帧被判废**（内核 `dd` 抓得到、框架零响应）；
  2. `BTN_TOUCH` 必须与位置**同帧**，否则框架只给 DOWN+MOVE **永不给 UP**（第一次之后全部退化成 MOVE）；
  3. 抬起帧要带 `TRACKING_ID=-1`；
  4. 探测逻辑若要求"ABS_X 有有效 range 才可用"会直接放弃本板；报错文案 `open/probe failed: No error information`（errno=0）**实为探测不支持却复用 open 失败文案**，误导极强。
- **修复后注入完全可用**（工程 `tools/pginj.c`：`proto` 探协议 + `tap/press/swipe/key`）。
- **建议**：① `mt_test`/`ui_test` 按上述修；② 探测失败时打印**实际读到的能力位**并区分"open 失败 vs 协议不支持"；③ 文档补"探测失败的判别与替代方案"（判单点/MT → dd 确认内核收帧 → 怀疑协议而不是怀疑框架）。

### E4 · `ZKMediaPlayer` 在喇叭不在默认卡的板子上静音　★★【文档/改】
- **实测**：框架播放器走 eyesee-mpp AO，**AO 自己拼声卡设备名、不读 `/etc/asound.conf`** ⇒ 喇叭接在 codec（card0）而 AO 默认走 card1 的板子上**无声**（日志全正常）。硬判据：播放期看 `/proc/<pid>/fd` 里的 `pcmC?D?p` 指向哪张卡。正解 = 官方 `zk_audio_player`（参考工程 `libzkmedia.a`）或裸 ALSA；注意它与"常开 PCM 流"互斥。
- **建议**：① `multimedia/audio.md` 顶部加平台差异警示；② 播放器加"选卡"接口或读 asound.conf。

### E5 · 屏保抢前台、屏保中应用 timer 停　**【归属已重判：不是框架缺陷，是验收纪律】**
- ⚠️ **归属**：`screensaverTimeout=30` 是**我们工程自己设的值**（非框架默认/缺陷）⇒ 本条应从"框架缺陷"改判为
  **验收注意事项**（真正要收录进知识库的是后半段）。
- **实测**：adb 命令不算触摸 ⇒ 抓屏/验收前**必须先唤醒**（否则抓到屏保，白天背景主色 `(92,148,252)`、夜晚 `(16,26,58)`，会误判成渲染错乱）；屏保中应用的 timer 被停 ⇒ QA 通道也不执行；固化/重启后前台是启动器，进应用要先 `echo '<app>' > /tmp/pg_autostart`。
- **建议**：文档收录"自动化验收与屏保共存"的注意事项（无框架侧动作）。
