## 1. 事实更正（权威口径）

> **框架方 2026-09-30 两次更正**：「**scale 在 GUI 层没有限制**」；
> 「早年那个 448 限制是**误测，去掉**；全志平台就只有一个**视频图层尺寸不能超过屏幕区域**的问题」。

| 我原来的写法 | 正确口径 | 谁定的（归属） |
|---|---|---|
| 「画布文字 `scale` **不能是变量**」 | **FlyThings GUI 层对 scale 无限制**，按需求放大缩小即可。我们之所以要求"档位是编译期常量"，是因为**自研字库只预烘有限档**（`PG_FONT_MAX_N=5` / 大号数字 3），超出档位就走位图放大 = **拉伸**（违反本工程"不许拉伸"要求） | **我们的工具链/方案** |
| 「画布宽 ≤ **448px**」 | **不成立**。448 = 本工程某 UI 的**内容区宽**（480 − 2×16 的布局值） | **本 UI 布局值** |
| （无） | **全志平台唯一相关尺寸约束 = 视频图层尺寸不能超过屏幕区域**（定性口径，**不挂具体数值**） | **引擎/平台**（真限制） |
| 「动画必须用**绝对时钟**」 | 成立，但**措辞要改**：写"**绝对时间基准 / 单调时钟（时间戳差值）**"，别写"绝对时钟"——会与 `digitalclock` 数字时钟**控件**混淆 | 引擎/通用工程 |

## 6. 更正 B · "软渲染"表述（同日追加）

### 6.1 事实更正（作者 2026-09-30 口径）

> 「canvas 内存到实际屏幕内存，**芯片侧和 FlyThings 框架层是提供了 bitblt 和 alpha 混合的能力的**。
> 平台在**内存拷贝、透明混合、90° 旋转**上都是提供能力的。」

因此"**UI 层是 CPU 软渲染 / 硬件加速只在视频图层**"的说法**错误**，要按**两段**拆开讲：

| 段 | 由谁做 | 结论 |
|---|---|---|
| **绘制进内存画布**（画形状/文字/贴图到 `bitmap_t`） | **我们的实现**（本工程 `src/core/PgCanvas.*`：`blendPx/blendRect/drawSpriteA`） | 这一段是软件 —— 但那是**我们的选择/实现的代价**，不是平台上限 |
| **内存画布 → 屏幕**（上屏） | **框架 + 芯片** | **硬件加速**：内存拷贝(bitblt)、透明 α 混合、90° 旋转 |

### 6.2 我方代码实证（不是推测）

- `src/platform/PgDisplay.h`（文件头注释原文）：
  > `-> ZKTextView::setBackgroundBmp() 挂画布`　`-> 每帧 setInvalid(!isInvalid()) 触发刷新（**控件->屏幕走硬件加速**）`
  ⇒ **我们自己的代码早就写明了"上屏走硬件加速"**，是我后来写文档时把它漏掉了。
- `knowledge/devflow/reusable-components.md` §8（厂家侧）：
  平台**有** 90° 旋转（`misc::bitmap_rotate`，90° 整数倍）；**没有**任意角度旋转位图
  （`ZKPainter` 不画位图、`ZKImageAnim` 只吃 GIF/WebP）⇒ 任意角度才需自己逐帧算（先例 `components/vinyl`：
  320×320 定点后端 **6~12ms/帧**）。
- `knowledge/devflow/pixel-analysis-ai.md`：真需要透明装饰件用 **`button + picTab`**（**"alpha 混合正确"**）
  ⇒ 框架层面的 α 混合路径是现成的。
- `knowledge/devflow/custom-widget.md` §6：`bitmap_t`（`bmp->type |= 0x01` 透明）+ Region 脏区 +
  `setBackgroundBmp` 显图 ⇒ 内存画布 + 上屏的标准姿势。

### 6.4 新学到的能力清单（可直接用于设计决策）

| 能力 | 提供方 | API 主体（已核实） | 备注 |
|---|---|---|---|
| 内存拷贝 / blit 上屏 | 框架 + 芯片 | `setBackgroundBmp` + `setInvalid(!isInvalid())` | **走硬件加速** |
| 透明 α 混合 | 框架 | `button + picTab` 路径、`bitmap_t` 透明位（`type \|= 0x01`） | 静态渲染路径也做 α 合成 |

| 任意角度旋转位图 | **应用自己** | 先例 `components/vinyl` | 320×320 → 6~12ms/帧 |
| 视频/摄像头独立层 | 框架 + 芯片 | disp 图层（`releaseLayer` 必做） | 与 UI 并行 |

> ⚠️ **芯片侧通道名（如 MI_DISP / G2D 等）本轮未取证**，上表只写**已验证的 API 主体**；
