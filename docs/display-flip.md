# 整屏 180° 翻转（"挂绳倒挂"）· 实现与实测

> 需求（2026-09-18 用户）：「因为我的屏幕挂绳在底部，**屏保和机器人界面**如果按下 **C 按键**
> 切换成倒 180 度显示。」
>
> 用户当面选定三条：① 生效范围**只这两页**；② 机器人页里**短按 C = 翻转**（长按仍是返回列表）；
> ③ 状态**落盘记住**（重启后仍是那面）。

## 0. 一句话结论

框架自带的能力，一行就够：`CONFIGMANAGER->setScreenRotate(180)` + `setTouchRotate(180)`
—— **实时生效、不用重启、连触摸坐标一起转**。本工程把它收口到 `src/platform/PgFlip.h`，
按"用户意愿（落盘）× 有没有环境页在显示"每拍算出该不该倒（`flipTick()`），
所以掉帧/漏报一拍都不会把屏幕留在错的角度。

## 1. 平台事实（反汇编 + 真机实测，都不是猜的）

| 事实 | 依据 |
|---|---|
| `ConfigManager::setScreenRotate(int)` **实时生效** | 反汇编 `libeasyui.so` 2.9.0：该函数存完静态量后**尾调 `zk_disp_set_rotate`**（`b 99884 <zk_disp_set_rotate>`） |
| `ConfigManager::setTouchRotate(int)` **实时生效**，触摸跟着转 | 同上，尾调 `zk_event_set_touch_rotate`；这两个符号在库里**没有导出**，只能走 ConfigManager |
| 旋转发生在**写 fb 之前** | 设 180 后抓 `/dev/fb0`，画面恰好是原来的 180° 旋转（**384000 像素 0 差异**）⇒ `/dev/fb0` 读到的是**转过之后**的内容 |
| `EasyUI.cfg` 的 `rotateScreen/rotateTouch` **只在开机读一次** | 之后由本模块托管；⚠️ **两个值必须一起改**（只转画面不转触摸 = 点哪儿都不对） |
| 视频层不保证跟着转 | 视频走另一个 disp 层（`ch0/lyl0`，见 `docs/disp-layer.md`）；本功能只作用在纯 UI 页 |
| 代价可忽略 | 屏保页 CPU：正向 **2%** → 倒挂 **5%**（8s jiffies 差分，静止基线 2%） |

## 2. 生效范围怎么算（`platform/PgFlip.h`）

```
want = (意愿 && (屏保在显示 || 机器人页在显示) && !被抑制) ? 180 : 0    // 只在变化时才下发
```

**抑制器（`flipSetSuppress`）= "必须正着读"的浮层**：目前只有**闹钟到点提醒页**。
它不是环境页，而是**弹在环境页之上**的模态浮层 —— 实测它在屏保显示中弹出时
（日志 `提醒页=1` 且 `环境页 saver=1`）如果不管，用户看到的就是**倒着的闹钟**，
根本没法读。规则：**"要人读/要人点"的页面永远正着，只有"拿来看的"环境页允许倒**。
上报位置与机器人页同一个位置（主循环每拍），所以闹钟收起后自动恢复倒挂。

- 屏保侧上报：`onUI_Timer` 顶部（**在那句 `if (!saverOn) return` 之前**）+ `onUI_quit`（退出侧只能挂它，
  因为屏保一退出框架就停掉本页定时器 —— 与"亮度恢复"是同一个坑）。
- 机器人侧上报：主界面主循环每拍 `pg::flipSetPageOn(FLIP_PAGE_PET, gMode==MODE_GAME && gGame && gGame->isFlipPage())`。
- 判据来源是 `Game::isFlipPage()`（`core/PgGame.h` 新增虚函数，默认 false ⇒ 既有游戏一字未改）。

## 3. 按键语义怎么变

| 位置 | 之前 | 现在 |
|---|---|---|
| 屏保显示中 · C 键（108） | 任意键都**唤醒**屏保 | **翻转 180°**，且**不唤醒**（连它的抬起事件一起吞掉） |
| 屏保显示中 · 其它键 | 唤醒 | 不变 |
| 机器人页 · 短按 C | 摸头（`onKey(PG_KEY_A)`） | **翻转 180°** |
| 机器人页 · 长按 C（≥700ms） | 返回列表 | 不变 |
| 机器人页 · 触摸 | 点=摸头 / 左右滑=换表情 / 长按=表情面板 | 不变（所以上面拿走"按键摸头"不丢功能） |
| 其它页面 | — | 不变（意愿记住但不下发） |

## 4. ★★ 三个真机踩出来的坑

1. **同一个按键事件会被投递 4 次（DOWN×2 + UP×2）**。
   屏保是 SysApp，与下面压着的 Activity **各有一次投递**，不是"谁先返回 true 就停"。
   第一版按"一次调用=一次按键"写，结果按一下 C 翻转**来回各切一次（净效果为零）**，
   而且抬起那一侧因为"看见第一次就把标志清掉"，第二次投递被放行 → 变成"任意键唤醒"，
   **按一下 C 屏保就没了**。现在：DOWN 用 60ms 去重窗、UP 一律吞掉且**不清标志**。
   诊断日志（常驻）可以一眼看出投递次数：

   ```
   屏保: C 键投递#1 down=1 long=0（t=1562481ms）
   屏保: C 键投递#2 down=1 long=0（t=1562482ms）   ← 同一次按下的重复投递
   屏保: C 键投递#3 down=0 long=0（t=1562566ms）
   屏保: C 键投递#4 down=0 long=0（t=1562567ms）
   ```

2. **"退出这一侧"的逻辑只能挂 `onUI_quit`**：屏保一退出框架就把本页定时器停掉，
   写在 tick 里的"每拍自愈"在退出侧根本轮不到（亮度恢复踩过一次，这次是翻转）。
3. **模态浮层没纳入考虑**（本次第二轮补的）：闹钟提醒页会弹在屏保**之上**，
   而"要不要翻转"如果只按"环境页在不在显示"算，就会出现**倒着的闹钟**。
   ⇒ 凡"要人读/要人点"的浮层都要挂抑制器（可与"环境页"共用同一套每拍重算的机制）。
   教训：**加了一个全局副作用之后，要把"这期间还可能弹出什么"过一遍清单**。
4. **翻转后抓屏要转回来才能体检**：`/dev/fb0` 里是倒着的画面 ⇒
   验收工具加了 `tools/saver_qa.py --rot180`。不加会报一堆"砖台没上屏/数字认不出来"
   —— 那不是屏保坏了，是帧倒着。

## 5. 真机验收（`tools/flip_qa.py`，10/10 通过）

判据不用"读日志"（本板日志缓冲只有十几行，会被 SSDP 之类刷掉），而是**逐像素**：
同一页面抓"翻转关/开"两帧 A、B，比两个差异 —— `d_direct = diff(A,B)` 与 `d_rot = diff(rot180(A),B)`：

- **倒挂** ⇒ `B ≈ rot180(A)` ⇒ `d_rot` 远小于 `d_direct`（故障场景实测 `292253 → 2760`，差两个数量级）
- **正向** ⇒ `B ≈ A` ⇒ `d_direct ≈ 0`

| 场景 | 判据 | 实测 |
|---|---|---|
| ① 屏保里按 C | 帧变倒 + 黑 HUD 从顶挪到底 | `d_direct=292253 / d_rot=2760`；HUD 上 115.7 → 下 11.9 ✅ |
| ② 翻转**不唤醒** | 日志翻转后无"唤醒/收起" + 画面仍是倒着的屏保 | ✅ |
| ③ 再按 C | 翻回正向（与正向帧 diff=442） | ✅ |
| ④ 屏保倒挂时按键唤醒 | 唤醒帧 == 确定的"正向主界面"（diff=0），日志有"离开屏保后下发 0°" | ✅ |
| ⑤ 菜单里（意愿=倒挂） | flip on 前后两帧**逐像素一致**（diff=0） | ✅ |
| ⑥a/b/c 机器人页 | 自动倒挂 → 短按 C 翻回 → 长按 C 仍回列表 | ✅ |
| ⑦ 闹钟页抑制（`alarm test`） | 屏保倒挂中响铃 ⇒ 闹钟页**与正向参照帧逐像素一致**（diff=0，转 180° 后 diff=292376） | ✅ |
| ⑦b 停铃后 | 屏保仍在 ⇒ 自动恢复倒挂 | ✅ |

★ 这 10 项跑在 `tools/flip_qa.py` 里（一条命令全跑，约 100s）。

**触摸坐标跟着转**（黑盒判据，倒挂时同样两点结果**正好互换**）：

| 点的物理位置 | 正向时 | 倒挂时 |
|---|---|---|
| (240, 495)（宠物身体那侧） | `Pet: 点身体 -> 打招呼` | `Pet: 点头顶 -> 摸头` |
| (240, 304)（宠物头顶那侧） | `Pet: 点头顶 -> 摸头` | `Pet: 点身体 -> 打招呼` |

⇒ 倒挂时"点哪看到的就是哪"，用户不用反着摸。

## 7. 注入触摸的节点：拿 `/proc/<pid>/fd` 为准，别信 cfg

本次实测：`EasyUI.cfg` 里写的是 `touchDev: /dev/input/event4`，但设备上**根本没有 event4**
（`ls /dev/input` 只有 `event0` = gt9xx 触摸、`event3` = gpio-keys），
而框架进程里打开的是 **`fd 10 -> /dev/input/event0`**。

⇒ 注入触摸前先查真值（`ls -l /proc/$(pidof zkgui)/fd`），否则 `pginj tap /dev/input/event4 …`
报 `open: No such file or directory`，而现象只是"点了没反应"（又是一次"静默失败"）。

```bash
D=/dev/input/event0
adb push tools/pginj /tmp/pginj && adb shell "chmod 755 /tmp/pginj"
adb shell "/tmp/pginj proto $D"                  # 本板报 MT 协议 A
adb shell "/tmp/pginj tap $D 240 495"
```
