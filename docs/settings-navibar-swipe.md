## 1. 节奏游戏「最佳时机」标识线

| 项 | 钢琴 | 打鼓 |
|---|---|---|
| 判定线（画布 y） | 388 | 296 |
| Perfect 窗口 | 60ms | 60ms（入门档 100ms） |
| 窗口带高度 | `perfect × (judgeY+noteH) / fallMs` = 13px | 同式（用 `music::drumDiff()` 的 fallMs） |
| 实测亮线 | 画布 387..389 三行 `(255,240,192)`，均值 216 | 画布 295..297，均值 217 |

画的东西（`PgPiano::render` / `PgDrum::render`，**先乘后除**算窗口像素）：

1. **两层窗口色带**（画在音符**之下**，所以音符落进来还看得见）：
   内层亮金 `rgba(0xFF,0xC6,0x4A) @76` = Perfect 区；外层暗金 `@52` = Good 区。
   ⇒ 玩家读到的信息就是「音符落进这条带子里时按 = 最佳」。
2. **高亮判定线**：3px `(255,240,192)` 压过底图那条细木线，下面再补一条暗槽做立体感。
3. **每轨落点标记**：轨中心一个小方块（16×5）；该轨的音符**进入 Perfect 窗口**时变亮放大
   （22×11 亮金）—— 等于直接告诉玩家"现在按这一条"。
   `hotLane` 位图由音符循环里顺手统计（`|note.atMs - mtAll| <= win.perfect`）。

⚠️ 窗口像素必须用**与 `noteScreenY()` 同一套映射**算（分子 = judgeY + noteH）。
血案：2026-09-16 之前 `pxPerMs` 用整数除法算成 0 ⇒ 音符恒停在判定线（见 `docs/rhythm-games.md`）。

## 2. 系统设置页（新应用 slot 32）

`ui/settings.html` → `settings.ftu` → `settingsActivity`；逻辑 `src/logic/settings.cc`。
分类 = **系统**（与 WiFi 同列）。

| 项 | 数据来源（都不是新造的） | 真机判据 |
|---|---|---|
| 静音开关 | `pg::isMutedGlobal()/setMutedGlobal()`（**真静音** = codec 输出开关；与状态栏音量面板左侧那个可点图标**同一个开关**）★ 2026-09-17 用户定调：「音效开关就是等于静音按键了，就不存在音效开关的说法」 | `qa settings: muted=0/1` |
| WiFi 开关 + 状态 | `pg::WifiService`（enabled/connected/ssid/setEnabled/openSystemSettings） | `wifi=zkswe-soft_5G`；`选网` 按钮 → 框架内置 WiFi 页 |
| 音量 | `Host::volumePercent()/setVolumePercent()`（写 codec + 落盘 + `noteVolumePercent`） | `vol 60 -> 58%`（codec 档位取整） |
| 背光 | **`BRIGHTNESSHELPER`**（zkhardware `utils/BrightnessHelper.h`，0..100） | `bright 45` ⇒ `disp attr/sys` 的 `backlight(255) → backlight(120)` |

**背光为什么只能用这个 API**（本次实测排除的三条路）：
设备上 `/sys/class/backlight` **不存在**、`/sys/class/disp/disp/attr/` 下没有亮度节点、
`dispdbg`（debugfs）试了 7 个命令名（`lcd_backlight`/`backlight`/`lcd0_bright`…）都改不动
`backlight(255)`、12 路 PWM 通道全是 `period=0/en=0`（无人使用）。
**只有 SDK 的 `BRIGHTNESSHELPER->setBrightness(0..100)` 能真改**（有 `cur/max` 可读、可回读校验）。

UI：四张卡片（音效 / WiFi / 音量 / 背光），后两项**各只有一条进度条**（没有按钮，见 §3.2）。
进度条素材**按变体生成两套**（`vol_track.png` 200×10 给状态栏 OSD、`vol_track_448.png` 448×34 给本页）——
工程铁律：素材尺寸必须 == 控件尺寸，不能拉伸（`tools/gen_ui.py` 的 `VOL_BAR_VARIANTS`）。

### 3.1 两条进度条（2026-09-16 第二轮改版）

### 3.1.1 ★★ "音效开关"这个名字取消了（2026-09-17）

用户原话：「现在这儿设计就是音效开关就是等于静音按键了。就不存在音效开关的说法。」
（同一条需求还要求：状态栏音量面板的进度条左侧放一个可点的音量图标 —— 那部分见
`docs/statusbar.md` §2.0。）

**为什么这不是"改个名字"**：两者在底层根本不是一件事，之前被混着用：

| | `Host::setSoundOn()`（原来那个"音效"） | `pg::setMutedGlobal()`（现在的"静音"） |
|---|---|---|
| 底层 | `DeviceAudio::setEnabled()` | codec `SPK/LINEOUT Switch`（写输出开关） |
| 范围 | **只停音效 SFX**（日志原话："**流照旧，只改是否写音效**"）⇒ 在线流（IPTV/摄像头/投屏）照样出声 | **整机输出哑**，在线流一起停 |
| 落盘 | 会（`store.setSoundOn`） | 不落盘（进程内状态） |

⇒ 按用户的要求，**UI 上只保留"静音"**（= 真静音），原来那个 SFX 开关不再从界面暴露
（`Host::soundOn/setSoundOn` 的代码保留 —— 开机仍按存档恢复 `audio.setEnabled(...)`）。

**改动的落点**：
- `ui/settings.html` 第①行文案「音效」→「**静音**」（caption 仍叫 `BtnSetSound` ——
  改名要同步 fun 生成的 `settingsLogic.cc` 桩，而内部名界面上不显示，沿用最省）；
- `settings.cc`：`onButtonClick_BtnSetSound` / `syncAll` 改走 `pg::` 静音接口，
  变量 `sSoundOn` → `sMuted`，QA `dump` 打印 `muted=`；
- QA 命令：`sound 0|1`（1 = 有声）语义改为真静音，另加正向写法 **`mute 0|1`**（1 = 静音）；
- `PgAudio.cpp`：`setVolumePercentGlobal()` 补"调整音量自动解除静音"（`pct > 0` 才解除）。

### 3.2 两条进度条改成**直接拖动**（2026-09-17）

用户原话：「**进度条不需要按键，直接拖动就好了**」⇒ 删掉 4 个 ＋/－ 按钮，条自己就是操作面。

改动清单：

| 项 | 改前 | 改后 |
|---|---|---|
| 按钮 | `BtnSetVolDown/Up`、`BtnSetBrightDown/Up`（56×48 两个黑块） | **删除**（源稿 + logic 回调 + `stepBright()` 一起删） |
| 条宽 | 312（右边留给按钮） | **448**（左右各 16 边距，整行一条） |
| 控件盒高 | 10（盒 = 条） | **34**（胶囊在盒内 y=12..21，上下透明） |
| 素材 | `vol_track_312.png` | `vol_track_448.png` / `vol_fill_448.png`（旧 312 已由生成器清理） |
| 数据入口 | 按钮 `volumeStepGlobal(±1)` | 拖动 `pg::setVolumePercentGlobal()`（新增，**绝对设值**） |

**为什么要"盒 34 / 条 10"**：手指最小可拖区约 34px，而视觉上要保持手机那种细条
⇒ 把控件盒做高、胶囊画在盒内居中（`VOL_BAR_VARIANTS` 的第 3 个字段就是盒内 y 偏移）。
素材尺寸必须 == 控件盒，所以 448 那套是单独两张图（`check_stretch.py` 会抓）。

**★★ 拖动要落地，三个必须做对的地方**（每个都是真机踩出来的）：

1. **`html2json` 把 seekbar 的 `touchable` 与 `data-thumb` 绑死**
   （源码 1491 行：默认 `touchable=False`，只有写了 `data-thumb` 才置 `True`）。
   而我们的条**故意不加 thumb**（实测：thumb 画在进度位置 ⇒ 0% 也留一个 10px 白点）。
   ⇒ 源稿用 **`data-drag="1"`** 表达"这条要能拖"，由 `gen_ui.py` 后处理成 `touchable=true`。
   （与 `patch_edittexts` 补 touchable 是同一类"缺字段行为不可靠"的补救。）
2. **`setProgress()` 也会触发 `onProgressChanged`**：fun 的绑定走
   `disp.on(..., UI_EVENT_TYPE_PROGRESS, ...)`，是**事件队列异步派发**的
   ⇒ syncAll 每 500ms 回写一次条 = "假拖动"一次回调 = 反向再写一遍 codec。
   实测症状：没人碰屏幕，日志却打出 `拖动音量 -> 请求 88% 实际 87%`。
   ⇒ 记"最近一次程序回写"的时刻（`sBarProgSetMs`），回调在这个窗（300ms）内直接忽略。
3. **拖动期间别让定时器抢**：syncAll 的回写在拖动后 1.2s 内跳过
   （`sBarWriteUntilMs`），否则手指还在动、条被拽回真值，手感像"抢"。
   ★ 用**时间窗**不用布尔标志 —— 时间到自动失效，没有粘性状态泄漏的风险。

**拖动时的副作用（刻意压掉的）**：不能再弹全局音量 OSD（用户正看着本页这条）
⇒ 新增 `pg::suppressVolumeOsd(ms)`（同样是时间窗），拖动时开 1.2s，
`setVolumePercentGlobal()` 在这个窗口内不广播。按键那条路（`volumeStepGlobal`）**不受影响**，
按键弹 OSD 仍是它的语义。

**背光下限**：拖到 10% 以下会被**吸附到 10%**（完全熄屏会让用户以为死机，
与旧版按 － 到 10% 的行为一致），且吸附引发的回调也被回声窗忽略。

**真机验收（固化版，`pginj swipe` 模拟真手指拖动）**：
```
音量： swipe (420,313)->(250,313)  → 请求 66/64/62/…/54% → 实际 65/63/…/53%
       20 步拖拽只产生 7 次写入（节流：Δ≥2% 或 ≥80ms）✅
       条填充 241px（53% → 448×0.538）✅
背光： swipe (420,420)->(350,420)  → 请求 82/80/78/76% → 实际同值 ✅
       swipe (400,420)->(24,420)   → 请求 8% 实际 10% / 请求 5% 实际 10%  ← **下限吸附** ✅
OSD：  拖动期间屏幕 544..656 区**非黑像素 = 0** ⇒ 没弹全局音量面板 ✅
按键区：原来两个按钮的位置现在是页面底（按钮已彻底消失）✅
```
> ⚠️ **测试手法**：拖动要**从右侧往左拖**（或在 x≥48 起手）—— `pg::Swipe` 的右滑返回
> 判据是"**起手**在左边缘 48px 内"（`kEdgeX = 48`），从 x=8 起手拖条会直接退出设置页。

**主界面那颗「音效 开/关」按钮已按需求删除**（`grep -n mBtnSoundPtr src/` 应为 0 条）；
主界面标题与电量**整体下移 12~12px**，给顶部导航栏让位。

## 3. 全局导航栏（`navibar.ftu`）：WiFi 状态 + 右滑返回

`ui/navibar.html` → `navibar.ftu` → `navibar`（`APP_TYPE_SYS_NAVIBAR`）；逻辑 `src/logic/navibar.cc`。

### 3.1 它为什么能「常显而不吃触摸」

★★ **窗口尺寸就是解法**：root 写 `data-res="480x26"` ⇒ 窗口只有屏幕顶部那一条。
实测（真机注入）：导航栏显示着时点主界面 tab，列表区变化 **33214 个抽样像素** ⇒ **照常能点**。
反面教材是 statusbar 的整屏窗口（见 §5 的血案说明）。

内容包括：右侧 WiFi 图标（两张：亮青蓝=已连 / 灰=未连）+ SSID 文字（未连显示"未连接"、
WiFi 关显示"WiFi 已关闭"）；左侧是「右滑返回」的动效提示（默认隐藏）。

### 3.2 右滑返回（手势判定在 `src/platform/PgSwipe.*`）

| 参数 | 值 | 为什么 |
|---|---|---|
| **起手位置** | **屏幕左侧 ≤ 48px** | ★★ **这一条是关键，也是返工换来的**：第一版只判「水平位移 ≥90px」，真机上**推箱子里一次 140px 的拖拽直接把游戏退了**（日志 `右滑返回 -> 退出当前游戏回列表`）。画布游戏里有大量横向拖拽（推箱子滑格 / 消消乐交换 / 俄罗斯方块横移），**只靠距离阈值分不开** ⇒ 改成 Android 那样的**边缘起手** |
| 水平位移 | ≥ **120px**（屏宽 25%） | 与上一条构成双保险 |
| 纵向偏移 | ≤ 70px | 竖直滑动是列表滚动 |
| 时长 | ≤ 900ms | 慢悠悠拖不算手势 |

**归属分工**（两个人都收得到同一笔触摸，见 §7 踩坑 ③）：

- **独立 ftu 页** → 由 navibar（全局监听）调 `EASYUICONTEXT->goBack()`；
- **画布游戏** → 由 mainLogic 调 `exitGameToMenu()`
  （游戏是"主界面内的整屏 window"，`goBack()` 对它无效）；
- 两边都读 `pg::swipeTriggered()`（"这一笔是否被判成右滑"）而不是 `swipeUp()` 的返回值
  —— 谁先收到抬指都不影响结论。`pg::setGameMode()` 由主循环每帧同步（改 gMode 的路径多，漏一处就出鬼）。
- 动效：滑动时 navibar 上的「⌂ 返回主页」提示**跟手滑入**（x 由 `pg::swipeProgress()` 决定），
  触发后停留 400ms 再淡出。

⚠️ 动效只能在导航栏那 26px 里做（窗口就这么大）——与"导航栏常显"是同一个取舍。

### 3.3 ★ 扩成「完整状态栏」：电池 + 页面标题（v1.31.9）

用户原话：「**状态栏显示不完整，直接把电池，页面 title 都放到状态栏这样子改动最小**」。

**问题**：导航栏是**常显浮层**（不透明黑底，原高 26px），而各页自己的标题画在 `y=8~18`
（fs=20~22，墨迹约 10~42）⇒ **上半被盖、下半露出 = 半截标题**。实测（camera 页）：
栏下沿 `y=30..54, x=8..200` 的亮像素 = **507**（≈一整个标题露在外面）。

**做法**（改动面 = 状态栏 2 文件 + 主界面 2 文件 + 5 个页面各 1~2 个坐标）：

| 位置 | 改动 |
|---|---|
| `ui/navibar.html` | 高度 **26 → 30**；新增 `TextNbTitle`（左）、`TextNbBatt` + `ImgNbBattShell/Fill/Bolt`（右，**复用主界面那套 `batt_*.png`** —— 52x26 刚好塞进 30，不必另烘小图）|
| `src/logic/navibar.cc` | `refreshTitle()` 按 `EASYUICONTEXT->currentAppName()` 查**本地映射表**（14 个 Activity → 中文标题）写左标题；`refreshBatt()` 按 `pg::Battery` 画电量（低电红/充电琥珀/正常蓝，规则与主界面一字未改）；「返回主页」动效出现时**临时藏标题**（两者抢同一位置）|
| `ui/main.html` | **删除** `TextTitle` + 电池三件套（已搬到状态栏）|
| `src/logic/mainLogic.cc` | 随之**删除** `syncBatteryIcon()` / `tickBattery()`（控件没了 ⇒ 控件指针不存在 ⇒ 不删就编译不过）|
| 5 个页面（camera / radio / wifi / probe / ime） | 顶部标题 `data-y` 上移到 2~4，让 30px 状态栏**完全盖住**（原来 `y=18` 会露 10px）|

**为什么"标题统一到状态栏"才是最小改动**：反过来做（把各页标题下移到状态栏下方）要动
15 个页面的布局，而且页面里就有两层标题。用户的原话正是这个意思。

**验收判据（都可复现）**：
- QA `dump`（`/tmp/pg_navibarcmd`）：
  `show=1 | wifi kind=2 ssid=zkswe-soft_5G | act=cameraActivity title=局域网摄像头 | batt=95% 已充满 low=0`
- **残影**：量「栏下沿亮像素」——camera 页改前 **507 → 改后 200**；再发 `hide` 隐藏导航栏重抓，
  **两列差值全 0**（y=8..54 逐段对比）⇒ 证明剩下的 200 是**页面自身内容**（`BarCamTop` 顶栏条），
  不是残影。★ 这个"**隐藏浮层做对照**"是判「残影 vs 页面内容」最干净的手法。
- 标题随页切换：`导航栏: 标题 act=mainActivity -> 口袋游戏机` → `act=settingsActivity -> 系统设置` ✔

**⚠️ 状态栏高度只有 30px 的预算**（再多就把页面内容压掉）⇒ 各页顶部控件要么**被它盖住**
（标题类，信息由状态栏提供），要么得**下移到 `y≥34`**。这条取舍见 `RULES-DETAIL.md` §11.1。

**已知项（未做，属"改动最小"范围外）**：各页顶部还有 1~4 个**动态副标题**
（`SubCamName` 摄像头名 / `SubStaName` 当前电台 / `SubApSsid` / `SubChName` 频道名 / `SubDevRssi`），
多在 `y=4~6`，也落在状态栏后面 ⇒ 那些**信息暂时看不到**。要显示的话需搬到状态栏或下移到 `y≥34`。

### 3.4 高度对齐到标题栏 + 屏保隐藏（v1.32.0，**取代 §3.3 的 30px 方案**）

用户第二轮要求：「**navibar 的高度做成跟应用内页的 title 高度一样**。**屏保界面隐藏导航栏**。」
问到"52px 会盖住返回按钮"时，用户定下的方向是：**被盖住的 UI 整体下移**。

| 项 | 做法 |
|---|---|
| **高度 30 → 52** | 52 = 各页标题控件的**主流高度**（实测统计：`TextCalcTitle`/`TextSetTitle`/`TextPmTitle`… 共 12 个页面都是 `h=52`，另有 7 个 `h=44`、3 个 `h=36`）；状态栏里的标题字号同步 15 → **20**，视觉与页面标题一致 |
| **被盖的 UI 下移** | 7 个页面的顶栏按钮（`BtnCamBack`/`BtnCamRescanTop`/`BtnWifiBack`/`BtnWifiRefr`/`BtnRadioBack`/`BtnRadioReloadTop`/`BtnRescan`/`BtnSetBack`/`BtnKbClear`/`BtnKbHide`/`BtnRemoteModeS`/`BtnRemoteModeL` 共 **13 个**）从 `y=10~16, h=44` 统一移到 **`y=54, h=36`**（状态栏下沿 52 + 2px 间距）|
| **屏保隐藏** | `navibar.cc` 的定时器里判 `EASYUICONTEXT->isScreensaverOn()`：屏保中 → `hideNaviBar()`；退出 → 走原来的"收敛显示"分支。★ 在导航栏**自己**这里判、不去改 `screensaver.cc`：少改一个文件，也不会漏掉别的进屏保路径（`saver on` QA / 超时 / 按键唤醒）|

**⚠️ 为什么"下移"是必需的**（实测数据）：各页顶栏按钮原本在 `y=10..54`，而导航栏是**不透明浮层 + 窗口内会吃掉触摸** ⇒
- 30px 时按钮只剩 `30..54` 可点（实测点 `(445,25)` 无反应、点 `(445,45)` 能返回）；
- 若直接加到 52px 而**不动按钮**：只剩 `52..54`（2px）⇒ **等于废掉返回功能**。

**验收（真机）**：
- 按钮可点：`pginj tap /dev/input/event0 445 72 200` → 日志 `settings: 点返回` ✔；
  点状态栏区 `(445,25)` → **无反应** ✔（那里现在是状态栏，本就该点不到）。
- 屏保：`saver on` → `导航栏: 屏保中 -> 隐藏` + `qa navibar: show=0`；`saver off` → `show=1` ✔
- 全 33 应用冒烟通过（改了 navibar + 7 个页面的坐标之后必跑）。

**★★ 关键补充：光挪按钮不够 —— 它下面的内容会盖住它（v1.32.2 定稿）**

框架里**同容器的兄弟控件"后声明 = 更上层"**。各页顶栏按钮下方紧跟着内容控件
（`TextCamStatus` y=70 / `TextRadioStatus` y=72 / remote 卡片 y=72 / probe 的 tab 条 y=72 /
settings 首张卡片 y=76…），它们在 HTML 里**后声明** ⇒ 把按钮的 `70..90` 压掉。
实测：点 `(30,60)` **能返回**、点 `(30,72)` / `(30,85)` **毫无反应**。

**"整体下移"的标准三步（照抄即可）**：
1. 按钮 → `y=54, h=36`；
2. 紧跟其后的内容控件 → `y += 22`（从 `y≥92` 起，即按钮下沿 90 之后）；
3. **该页 List 控件 `y += 22` 且 `h -= 22`** ⇒ 列表**底边不变**、底部按钮/文字不出屏
   （camera 实测 `ListCam(120,576) → (142,554)`，142+554 = 696 = 原值 ✔）。

按这套改完的验证结果（**全部真机实测**）：

| 页面 | 判据 | 结果 |
|---|---|---|
| camera | 点 (30,60) / (30,72) / (30,85) | **3/3 全部"点返回"** ✔（改前只有 60 可点）|
| settings | 点 (445,78) → `settings: 点返回` | ✔ |
| wifi | 点 (30,78) → 画面变化 **26841** | ✔ |
| radio | 点 (30,78) → 画面变化 **31065** | ✔ |
| probe | 点 (30,78) → 画面变化 **28831** | ✔ |

★ **probe 要特别处理**：它有 **5 个**子模式窗口（WiFi / 蓝牙 / 局域网 / 嗅探 / 寻找），
每个都带一整套「顶栏 + tab 条 + 卡片」⇒ 共下移 **106 处**坐标。**只改当前可见的那个必漏**
（症状：切到别的子模式后按钮又点不动）。

★ **验收手段**：各页返回按钮的回调日志文案不同（有的页甚至没日志），所以**"点完是否离开本页"
用抓图对比最通用** —— 前后两张图差异 **> 2000 抽样像素**即算生效。

**★ 补充：次级顶栏也要下移（v1.32.1，同批共 32 个控件）**

第一轮只挪了 7 个页面的 **13 个"主顶栏"按钮**。复查时又扫出 **19 个"次级顶栏"控件** ——
它们在**子窗口 / 覆盖层**里，内容有意义、**不能**靠导航栏替代：

| 页面 | 次级顶栏 |
|---|---|
| `probe` | **5 个子模式窗口**（WiFi / 蓝牙 / 局域网 / 嗅探 / 寻找）各自的顶栏：返回 / 刷新 / 模式按钮 + 子标题（`TextBtTitle` / `TextLanTitle` / `TextSnTitle` / `TextHuntTitle`），原来也在 `y=10~54` |

⇒ 统一下移到 `y=54, h=36`。

★ **区分原则（本工程从此就按这条判）**：
- **主标题**（`TextCamTitle` / `TextSetTitle` / …）→ **保持被导航栏盖住**（信息由状态栏提供，这才是"最小改动"）；
- **子模式标题 / 播放层 / 视频层 / 输入框** → **必须下移**（语义与状态栏标题不同，盖住 = 丢信息）。

★★ **扫"还有哪些被盖住"时的两个坑**：
1. **`WinXxx` / `CamVideo` / `RowCard` 这类是容器/列表行模板，不是内容控件** —— 直接扫全表会列出一堆
   假的"会丢信息"。
2. **`ListXxx` 内部的子控件（`SubXxx`）y 是行内相对坐标**，跟浮层高度无关 —— 也要排除。
   ⇒ 有效判据 = **"顶层（不在 list 内）+ `y < 52` + 不是主标题"**。

**★★ 本轮踩的测试坑（三条都值得记）**：
1. **`pginj tap` 要给 `hold=200ms`** —— 省略时短按可能不被框架识别成点击（项目纪律早写过，这次忘了）。
2. **判据必须用该按钮自己的回调日志**：我先 grep `onUI_quit` 得到 0，误判成"按钮点不动"、白折腾几轮；
   settings 的返回按钮日志其实是 **`settings: 点返回`**（见 `onButtonClick_BtnSetBack`）。

## 4. 静音（「按键调整音量的默认去掉静音」+「弹框快速静音」）

真静音 = 写 codec 的输出开关（`SPK Switch` / `LINEOUT Switch`），**不是把音量调 0**
（开关可逆、恢复只差一次写；调 0 后从 0 往上按要一档档爬）。

| 入口 | 实现 | 真机判据 |
|---|---|---|
| **长按音量键** ≥700ms | `KeyRouter::longPressAction()` → `pg::setMutedGlobal()` | `长按音量键 -> 静音（成功）` + `SPK Switch Off` |
| **设置页** | 音量行（`vol` QA 同路径） | `qa settings: vol 60 -> 58%` |
| **音量弹框上的「静音」按钮** | `statusbar.cc::onButtonClick_BtnSbMute` | `状态栏: 点静音按钮 -> 静音（成功）` + `SPK Switch Off` |
| **按音量+ 自动取消静音** | `pg::volumeStepGlobal()`：静音时 `delta>0` ⇒ 先 `setMutedGlobal(false)` 并恢复上次音量 | `音量+ 时先取消静音（恢复到 58%）` + `SPK Switch On` |

系统**默认不静音**（启动时不动开关）；`pg` 层缓存 `sMuted/sLastPct`，`sLastPct` 未知时兜底 60%。

## 5. 音量弹框「能点」的三步改造（这一项踩得最多）

面板要能点，**三步缺一不可**（少一步都表现为"点了没反应、日志零输出"）：

1. **窗口从 480x800 收成 240x160**（`ui/statusbar.html` 的 root + `gen_ui.py` 里补 position=(120,520)）
   —— 整屏浮层会吃掉**全机控件级触摸**，连它自己的按钮都点不动；
2. **根节点 `touchable` false → true**（窗口已经很小，吃也只吃那一块）；
3. **中间那层 `WinSbVolume` 也要 `touchable=true`** —— *父窗口不吃触摸 ⇒ 子控件收不到*
   （本项目第三次栽在同一件事上：statusbar 根、ime 根、这次是中间层）。
   统一判据：**要能点的按钮，它的每一层祖先都得可触摸。**

还有第 4 个坑（坐标）：`控件 getPosition()` 给的是**窗口内**坐标，而 `MotionEvent` 是**屏幕**坐标
⇒ 面板内的触摸被误判成"面板外"，面板立刻收起（日志反而是 `触摸面板外 (186,646) → 收起`）。
修法：比较前加上窗口在屏幕上的位置（常量与 `gen_ui.py` 的 patch 交叉引用）。

## 7. 踩坑小结（都已写进 `RULES-DETAIL.md`）

1. **SysApp 要显式注册全局触摸监听**：`EASYUICONTEXT->registerGlobalTouchListener(mXxxPtr)` ——
   生成的宏只在 DESTROY 时 unregister，**没有配对 register**。漏了 ⇒ 右滑零响应（注册后即通）。
2. **`fun build` 会自动生成同名桩** `src/logic/<ftu名>.cc` ⇒ 手写 `navibarLogic.cc` 会与它
   一起注册两遍、链接期 undefined reference。**一个 ftu 只留一个 .cc**（本工程沿用 `statusbar.cc` 的命名）。
3. **回调必须定义在全局作用域**（放进匿名命名空间 ⇒ undefined reference）。
4. **fun 的隐式回调要补桩**：`onUI_show/onUI_hide/onUI_intent/onProgressChanged_*`
   少一个就是链接错（这次连挂两次；`upgrade_device.sh` 已加固成"编译失败当场中止、绝不刷旧包"）。
5. **触摸的每一层祖先都要 touchable**（见 §5）。
6. **控件坐标 vs 屏幕坐标**（见 §5）。
7. **进度条素材要多宽度**：`gen_ui.py` 的 `VOL_BAR_WIDTHS`（素材尺寸 == 控件尺寸）。
8. 注释里**不要用英文双引号包中文**（`genfont.py` 会当字面量收进画布字库；见 RULES-DETAIL §4）。
9. ★★ **手势只用距离阈值一定会误伤游戏**（v1.31.8 返工）：推箱子里 140px 拖拽被当成"右滑返回"
   把游戏退了。**正解 = 仿 Android 的边缘起手**（起点必须落在屏幕左侧 48px 内）+ 提高位移阈值，
   两条一起才有"用户想用时够灵敏、游戏里不误触"的效果。改手势阈值前先把这条读一遍。
