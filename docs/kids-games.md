## 2. 儿童游戏设计红线（改任何一款前先读）

低龄娃和成人游戏的差别几乎全在这几条上：

1. **无失败惩罚** —— 连错/点错/点空都只给"温和提示 + 晃动一下"，**不扣分、不重置、不限次数**。
   验证点：QA 断言"连错后 score 不变"。
2. **不限时** —— 一律没有倒计时。算术泡泡的泡泡只是**缓慢上浮**（30px/s，一个身位约 3 秒），
   目的是画面有生气，**不是**时间压力；找不同卡住只会给提示，不会催。
3. **不识字也能玩** —— 靠阿拉伯数字与图形，文字只做锦上添花。圆点上的数字、泡泡里的数字、
   找不同的差异都是图形/数字。
4. **难度分档** —— 5 岁和 10 岁不能吃同一套数值。
5. **手指友好** —— 可点元素 ≥ 18px 半径（≈36px 直径），判定再外扩 ~8px 容错。
6. **即时正反馈** —— 画完一个图案 → 填色 + "太棒了！" + 图案名；连对 ≥3 → 橙色赞语
   （真棒！/ 好厉害！/ 太强了！）。
7. **单指可玩** —— 不需要多点、不需要物理键。

## 3. 五个实测坑（都是这一轮踩出来的）

### ★★ 3.1 `stillFrame()` 返回 true 会**连 `update()` 一起跳过** —— 有计时器就不能报静止

「找不同」是静态场景（只有点中差异才变），很自然会想"静止时跳过重绘"，实测帧率也确实
**从 49 涨到 99**。但下一轮 QA 立刻抓到 **"找全后画面永远停在庆祝、永不进入下一关"**。

根因在宿主的调用顺序（`mainLogic.cc` MODE_GAME 分支）：

```
3403  { if (gGame->stillFrame()) { ... break; } }     // 报静止 → 直接 break
3415  gGame->update(loopDt);                          // ← update 在这之后！
```

⇒ 报"静止"= **render 与 update 都被跳过**。而「找不同」有两处状态靠 `update()` 推进：
`idleMs_`（卡住 16s 给提示）与 `celebMs_`（找全后自动进下一关）⇒ 全停。

**判据**：**只要游戏里有"靠时间推进的状态"（倒计时 / 自动切换 / 提示计时），就不能报静止。**
对照组：`GameConnect::stillFrame()` 只在 **所有计时器都归零** 时才返回 true，所以它是安全的
（连点、自动切换都靠非零计时器驱动 ⇒ 那些时刻必然返回 false ⇒ update 照常跑）。

### ★★ 3.2 画布文字调用把 `scale` 写成**变量** ⇒ 字库暴涨 2MB

`genfont.py` 对"**非字面量实参**"的 `text()/bigText()` 调用会退化成"**本文件全部短字面量**"
这个保守超集；而 `scale` 若是变量，档位会被展开成 **1..5**（中文 48/64/80px 每枚字形上千字节）。

实测：`int tScale = 2; c.textCenter(x, y, buf, tScale, c)` + `fitBigText(...)` 算出来的变量档位
⇒ 字库 **2.70MB → 4.67MB**（`CJK_C3` 79 → 174）。

**三条改法**（本工程现在的写法）：
- 数字一律走 **`number()/numberCenter()/bigNumber()/bigNumberCenter()`** —— 这些**不在
  `genfont.py` 的扫描名单里**，数字只靠 `ALWAYS_ASCII` 恒带的 0-9 ⇒ **一个字库字形都不加**；
- 运算符/标签用**字面量**（`c.bigText(x, y, "+", 3, c)` 而不是把整句拼好再传）；
- 实在要拼串时，**档位写死字面量**（`q, 3`），让 genfont 只收那一档。

对照实验结果记在案：同一批源文件，改法前后字库 **3.19MB vs 4.67MB**（基线 2.70MB）。

### ★ 3.3 QA 通道「**内容变化才执行**」⇒ 连发同样的命令只有第一条会跑

写验收脚本时最容易被这条骗：连发 3 次 `gdbg answer` 只有第一条执行 ⇒ combo 永远到不了 3 ⇒
**看着像"赞语没实现"**。

两种正确写法（`runAutoCmd` 支持）：
- **`cmd #序号`** —— `#` 之后整段是注释，会被统一剥掉，天然用来"每次都不同"（工程惯用法）；
- 我在 `tools/kids_qa.py` 里用的是给命令**追加一个被忽略的序号参数**（`gdbg answer 7`），
  因为游戏侧只取第一个词；**注意 `gscore` 这类"整串比较"的命令不能追加参数**。

### ★ 3.4 抓屏比动画慢（2.7s vs 1.0~1.8s）⇒ 计时类特效必须**并发抓**

赞语 1s、答错提示 1.5s、庆祝 1.7s，而 `tools/grab.py` 要 2.7s。手工抢拍必失败。
做法：**先起抓屏进程，再下发 QA 点击**（`cat /dev/fb0` 大约在 0.4s 发生，正好落在窗口内）。
赞语还有额外一招：combo 已经 ≥3 时，**之后每次答对都会再弹一次** ⇒ 可以重试抓拍。

### ★ 3.5 单点探针会被字形/抗锯齿打到 ⇒ 用"数面积"

判"这个圆点是不是某颜色"时，打圆点中心会打到数字字形；打边缘会打到 50% 混合色
（实测把 `wax(2)` 打成 `(196,149,72)`）。改成**在半径内数"接近该色"的像素个数**（>150 才算过）。

### ★★ 3.6 画布文案**超宽**：功能断言全绿，只有肉眼看得出被裁（用户报障）

**现象**：算术泡泡 READY 页的说明行「点破答案正确的那颗泡泡」左右被屏幕**各裁掉 24px**。
**根因**：11 个中文 × 档 3 的字格 **48px = 528px > 画布宽 480px**。

字档宽度表（`src/core/PgFontData.h` 的 `ASCII_FONTS` / `CJK_FONTS` / `BIG_FONTS`，
**改生成器就要改 `tools/check_textwidth.py` 里那张表**）：

| 档位 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| `text` 系列 ASCII | 8 | 16 | 24 | 32 | 40 |
| `text` 系列 CJK | 16 | 32 | **48** | 64 | **80** |
| `bigText` 系列（数字/符号） | 16 | 32 | 48 | — | — |

> 好记的估算法：**档 5 的中文 ≈ 80px/字 ⇒ 最多 6 个字**；**档 3 ⇒ 最多 9 个字**；
> **档 2 ⇒ 最多 13 个字**（画布宽 480，两侧还要留 16px）。

同一轮体检一共查出 **4 处超宽**（不止用户报的那一处）：

| 位置 | 原文案 | 档 | 宽 | 改法 |
|---|---|---|---|---|
| `PgBubble` READY | 点破答案正确的那颗泡泡 | 3 | 528 | 降**档 2**（352） |
| `PgConnect` 完成页 | 全部画完啦！ | 5 | 480 | 降**档 4**（384） |
| `PgConnect` READY | 从 1 开始，顺着数字连 | 3 | 504 | 降**档 2**（336） |
| `PgMatch3` READY | 4 连出方向炸弹 · 5 连出彩虹球 | 2 | 480 | 缩短文案（320） |
| `PgSpot` READY | 上下两幅图，点出不一样的地方 | 2 | 448 | 缩短文案（320） |

**修法优先级**：① 降一档（最小改动，且**不会缺字** —— genfont 按调用点档位收字）；
② 档 2 已是下限（档 1 只有 16px）时**缩短文案**。**别碰运行时自动缩档**：把档位写成变量
会让 genfont 退化成"本文件全部短字面量灌进每一档"，就是 §3.2 那个 +2MB 的坑。

**两道闸，缺一不可**：
- 静态：`python tools/check_textwidth.py -v`（扫全部画布文案的字面量档位，算宽度报超宽/贴边）；
- 真机：`python tools/kids_qa.py --only ready`（抓 4 款游戏的 READY 页，逐像素断言**左右各留边 ≥ 24px**）。

判据（踩过坑）：READY 的文字是**画在压暗层之后**的 ⇒ 是**原色**（白 255 / 浅灰 200,200,205）；
被判据用的"中性色"条件是 `max-min ≤ 8 且 max ≥ 185` —— 被压暗的纸底是 `(124,120,111)`
（B 比 R 低 13，**非中性**）所以不会误命中。**别用亮度阈值硬扫**：纸底压暗值 `(124,120,111)`
与白字压暗值 `(125,125,125)` 只差 14，第一版判据就这么写错、扫不到任何文字行。

## 4. 验收（`tools/kids_qa.py`，42 项断言，可复现）

```bash
python tools/kids_qa.py                 # 四段全跑（约 3 分钟）
python tools/kids_qa.py --only bubble   # 只跑一款（connect / bubble / spot / ready）
ADB=adb python tools/kids_qa.py
```

覆盖：进游戏标题 / 开局分数 / READY 压暗 / 纸底色值 / 当前目标点上色 / 未连点卡色 /
**连错不扣分 + 红色正向提示** / 连完 +1 / 完成时填色 / 6 个图案全连完 / 进 OVER /
**点对 +1 / 连对 3 次出赞语 / 点错不扣分 + 红色提示** / 上下两幅图底色不同 /
找到 +1 / 红圈标出 / **点空不扣分** / 找全自动进下一关 / `glyphmiss` 无缺字 /
**4 款游戏 READY 页文案左右各留边 ≥ 24px**（§3.6）。

三条 QA 钩子（都只加"让状态前进"的，不加"直接改分"的）：
`gdbg q`（打印题目/差异清单，让脚本能算出"该点哪里"）、`gdbg answer|wrong|next`、
`gdbg find|next`。

配套工具：`tools/asciiview.py`（PNG → ASCII 字符画，"看不了图也能验画面"）、
`tools/grab.py`（按 pan 抓帧）、`tools/check_textwidth.py`（画布文案宽度静态体检，见 §3.6）。
