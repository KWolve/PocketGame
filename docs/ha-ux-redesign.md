## 0. 先说清楚这个产品的能力边界

改交互之前必须先把"这块屏幕到底能做什么"钉死，否则交互会往错误的方向设计。

| 能力 | 屏幕端能不能做 | 依据 |
|---|---|---|
| 看 HA 里所有实体 + 状态 | ✅ REST `/api/states` | 实测 34 条，`parseFail=0` |
| 控制实体（开关 / 场景 / 按钮） | ✅ REST `/api/services/...` + 回读确认 | P2 已验收，端到端 197~210 ms |
| **接入新设备（配网/绑定）** | ❌ **做不到** | HA 的 config flow / 集成添加**只有 WS API 和前端有**，REST 没有；而且 MQTT 设备的配网在设备侧 |
| **按 HA 的「房间」分组** | ❌ 现在做不到 | 实测 4 个 area 存在，但 `entity_registry` **0/36** 有 `area_id`（房间建好了、设备没归位） |
| 实时推送（别处改了立刻同步） | ⚠️ 需 WS（P3） | 现在靠 3 秒轮询 |
| **让用户自由输入中文名字** | ✅ **可以，而且已经有了** | 工程自带**全拼输入法**：`src/logic/imeApp.cc` + `ui/ime.html`，是 `APP_TYPE_SYS_IME` 的 SysApp —— **任何 ZKEditText 聚焦时系统自动拉起**，业务页不需要 `showIME()`（2026-09-23 刚加了中文全拼） |

**结论（整个方案的地基）**：这个应用的"添加设备"，本质**不是 IoT App 里的"配网添加"**，而是
**"把 Home Assistant 里已经存在的设备，挑几台放到这块屏幕上当遥控器"**。
现在界面直接叫「添加设备」，用户点进去期待的是"配网加一台灯"，看到的却是一张 34 行的实体清单 ——
**预期落差就在这里**。改版第一步是把这个语义正过来，并显式告诉用户"新设备请先在 Home Assistant 里添加"。

## 1. 当前交互复盘

### 1.1 结构与动作

```
应用网格 →「智能家居」(haActivity, slot 37)
│
├─ WinHaHome 「我的设备」（默认页）
│    状态行：连接状态（左） + 实体数·数据新鲜度（右）
│    提示行：一句"该怎么办"
│    2×3 磁贴：点 = 开/关；**先开「管理模式」再点 = 进编辑页**
│    上一页 / 第 x/y 页 / 下一页
│    底栏：[添加设备] [刷新] [管理模式]
│
├─ WinHaScan 「添加设备」
│    "扫描到 N 个设备 · 已在我的设备里 M 个"
│    26~34 行列表：未添加 = **点一下立即加入**；已添加 = 点一下进编辑页
│    底栏：[重载配置] [重新扫描]
│
└─ WinHaEdit 「改名 / 删除」
     候选名列表（1 行「用 HA 原名」 + 32 个候选名）：点一下立即改名
     底栏：[从我的设备里删除] [返回我的设备]
```

### 1.2 做对的地方（改版要保留）

- 主页只显示"用户自己添加过的"，而不是把 34 条全铺出来 —— 方向正确（P2 需求 ② 的答案）。
- 点磁贴真能控制，且**控制结果有回执**（乐观态 → 回读 → 5s 回滚，提示行给原因）。
- 灰态（`unavailable`）禁点并说明原因，不制造"点了没反应的坏按钮"。
- 磁贴"域 × 状态"三档图，不同类型不同观感。
- QA 通道 + 心跳文件，可免触摸验收。

### 1.3 问题清单

#### P0 —— 概念性错误（用户第一眼就会困惑）

| # | 问题 | 现象 / 后果 |
|---|---|---|
| 1 | **「添加设备」语义错位** | 用户以为能配网加新设备；实际是"从 HA 已有实体里挑选"。没有任何一句话解释这件事，也没有"新设备去 HA 添加"的指引 |
| 2 | **点一下即加入，不可回溯** | 无勾选、无确认、无撤销。误触即写盘（`/data/ha_dev.txt`），用户只能去编辑页删掉 |
| 3 | **没有"完成"环节** | 加完停在扫描列表，用户不知道"加了几台、加完去哪看"。IoT App 一定有完成页/明确去向 |
| 4 | **首次进入无引导** | 新用户看到 6 个"空位"，没有空态说明、没有主动的"从 HA 导入"推荐 |

#### P1 —— 反模式 / 效率低

| # | 问题 | 现象 / 后果 |
|---|---|---|
| 5 | **编辑藏在「管理模式」里** | 改名/删除要"先开模式 → 再点卡片 → 进编辑页 → 改完返回（模式还开着）"。IoT App 里这是**长按卡片直接出菜单**，没有"管理模式"这一层 |
| 6 | **「重载配置」暴露在用户界面** | 这是调试动作（重读 `/data/ha.conf`）。真实 App 不会把"重载配置"给用户 |
| 7 | **「刷新」按钮** | 已 3 秒自动轮询，用户按它没意义；IoT App 是自动同步或下拉刷新 |
| 8 | **列表行暴露 `entity_id`** | 行内是 `switch · off · switch.z20_smart_panel_ke_ting_deng`。`entity_id` 是开发者的东西，用户要的是"图标 + 名字 + 房间/类型 + 状态" |
| 9 | **无分组 / 筛选 / 搜索** | 34 条里大半是只读传感器（`sun`/`backup`/`ulanzi`）。"添加设备"页应当默认突出**可控**的，而不是让用户滚一遍 |
| 10 | **改名做成一整页 33 行候选名** | 明明工程已经有全拼输入法（`div.input` 聚焦即拉起），却只能从 32 个通用候选词里滚着点选；「用 HA 原名」还混在候选里 |
| 11 | **删除无二次确认** | `BtnHaEditDel` 点一下即删。移除是破坏性操作，IoT App 必带确认 |
| 12 | **无排序入口** | `PgHaList::move()` 已实现但没有 UI，用户加的顺序就是顺序 |
| 13 | **无设备详情** | 点卡片 = 直接 toggle，没地方承载"亮度/色温/模式"（P3），也没地方放"改名/移除" |
| 14 | **状态文案工程化** | `「X」现在是「unavailable」，设备不在线 ⇒ 先别点（发了也不会变）` —— 应改为界面语言："设备离线，无法控制" |

#### P2 —— 打磨项

| # | 问题 |
|---|---|
| 15 | 翻页是桌面式"上一页/下一页"按钮；IoT 观感应为滑动或点状指示 |
| 16 | 底部信息层级拥挤：翻页行 + 三按钮 + 脚注（590~734px 共 140px） |
| 17 | 连接失败只有一行小字，没有**页面级**的"未连接 HA / 去设置"空状态 |
| 18 | 空位卡片文案是"空位 / 点「添加设备」加入一台"，6 个空格全一样，没有回答"我该做什么" |

## 2. 目标交互设计

### 2.1 四条设计原则

1. **语义要对**：屏幕端不做配网 ⇒ 动作叫「**添加设备**」，页面标题叫「**从 Home Assistant 添加**」，
   并常驻一句"这些是 HA 里已有的设备；新设备请先在 HA 里添加"。**把能力边界变成产品说明，而不是缺陷**。
2. **不可回溯的操作不进主路径**：加入 = 勾选 + 底部确认条 + 完成页；移除 = 二次确认。
3. **编辑就近**：长按一行 → 操作菜单（或行尾「⋯」），去掉「管理模式」这一层状态。
4. **状态永远说人话**：行上用"已开 / 已关 / 离线"，提示行用人话，不出现 `unavailable`/`entity_id`。

### 2.2 目标信息架构

```
L1 我的设备（遥控器面板）
    · 状态条：已连接 · N 台          失败时 → 整张**连接状态卡** +「去设置」
    · 设备卡片：**2 列 listview**（`ListHaMy`，cols=2 / colSpacing=8 / rowSpacing=8，item 224x148）
      ★ **行数 = 实际设备数**（0 台就一行都不画）—— 固定 8 格会露出空卡片 + 空域块
        点击卡片   = 控制（开关类；单向触发类=执行）
        长按卡片   = 操作菜单（改名 / 上移下移 / 移除）  ← 或卡片右上菜单热区
    · 页头右侧并排 **[+ 添加] 44x36 ｜ [设置] 88x36**（IoT App 做法：添加做成图标按钮）
      —— 底部**不再放 CTA**（原"全宽 + 添加设备"已删）
L2 添加设备向导（三步）
    ① 选择设备   段控「可控 N / 全部 N」，多选，已添加打勾；底部条「已选 N 台 · 下一步」
    ② 命名       **输入框（原生 ZKEditText：点它系统自动拉起工程自带的全拼输入法，
                 可自由输入中文）+ 按域推荐的快捷词片（点一下填入）**；可「跳过」
                 ★ 本页可交互控件必须全部落在 y<372 —— 输入法键盘面板占 372..800
                 （四条硬约束见 §4.7）
    ③ 完成       「已添加 2 台」→ [去我的设备看看] / [继续添加]
L3 设置（连接配置 / 重载配置 / 关于）—— 把调试动作收进来
```

### 2.3 关键流程：首次使用

```
进入「智能家居」
  └─ 我的设备为空 → 空态页：
       "还没有添加设备" + 一句解释 + [＋ 从 Home Assistant 添加]
       + 次选 [一键添加全部可控设备]（实测这台只有 4~8 台可控，这个按钮极实用）
  └─ 选择设备（默认「可控」段）→ 勾 6 台 → 下一步
  └─ 命名（可跳过）→ 完成
  └─ "已添加 6 台" → [去我的设备看看] → 面板 6 格满了
```

### 2.4 关键流程：控制（保持不变的部分）

点一行 → 乐观态（"开中…"）→ 回读确认 → 成功（状态文字落定）/ 5 秒超时回滚 + 提示行说明原因。
**离线行整体降透明（opacity .55）+ 状态显示"离线"，点它只给一句人话提示**，不发命令。

### 2.5 删除（改动）

```
长按一行（或点行尾「⋯」）→ 操作菜单 → [移除设备]
   → 确认条（半屏）："从屏幕上移除「客厅灯」？
       只是移出这块屏幕，Home Assistant 里的设备不受影响。"
       [取消] [移除]
```

## 2.6 主页两种状态的层级（★ 正常态 vs 连接失败态）

用户 2026-09-23 指出"连接提示词层级不对"。复盘后确认：原稿把
**"连不上 192.168.x.x:8123"做成了整条横幅的主句**，而真正该突出的"未连接 + 该怎么办"
反而被压成它上面的小字 —— **层级倒置**。修正为下表：

| 层级 | 正常态（A1） | 连接失败态（A3） |
|---|---|---|
| L1 发生了什么 | 一行小字：`已连接 · 3 秒前同步`（绿点） | **状态卡主句**（17px 橙）：`未连接 Home Assistant` |
| L2 上下文 | 状态行右侧：`6 台` | 12px 灰：`192.168.1.188:8123 无响应 · 数据停在 2 分钟前` |
| L3 影响 | 提示行 12px：`点一行开关设备 · 行尾「⋯」改名或移除` | 12px 灰：`未连接时不会发送控制命令，下面显示最后已知状态` |
| L4 动作 | 页头右侧 `[+]`（44x36，索引 IoT 习惯） | 卡内唯一按钮 `[去设置]`（92x40）；页头 `[+]` 点了只提示"先恢复连接" |

**两条原则**

1. **失败态要"升格"，但不能重复说**：正常态用户不需要做任何事，一行小字就够；
   失败态需要"原因 + 影响 + 动作"三件事，塞进一行必然倒置 ⇒ 升格成一张 456x96 的卡。
   同时**状态行与提示行合并进卡里**，一屏只在一处说这件事。
2. **动作永远只有一个、且放在同一处语境里**：失败态卡内只有「去设置」，
   页头的 `[+]` 在离线态改为"只提示不进页"，不再塞第二个"设置"按钮（它已在页头）。

> 落地对应：`CardHaOffline`（456x96 @12,104）+ `TextHaOfflineL1/L2/L3` + `BtnHaOfflineSet`；
> 正常态整卡隐藏（注意走 `HIDDEN_CONTROLS` + `patch_*` 那一套，别只 `setVisible`）。

## 3. 三个方案（按工作量递增）

| | 方案 A · 最小改动 | **方案 B · 标准 IoT 向导（推荐）** | 方案 C · 完整 App 化 |
|---|---|---|---|
| 定位 | 只修正概念与文案 | A + 添加向导 + 卡片菜单 | B + 底部 Tab + 房间分组 + 设备详情页 |
| 添加流程 | 仍是点一下即加，但改名页/文案正名 + 加完成提示 | **三步向导**：多选 → 命名 → 完成；段控分组；常驻确认条 | 同 B，另加"批量导入""推荐设备" |
| 编辑入口 | 保留管理模式（只把它挪到菜单里） | **长按行 / 行尾「⋯」→ 操作菜单**；去掉管理模式按钮 | 操作菜单 + 设备详情页 |
| 删除 | 加确认 | 加确认 | 加确认 + 批量管理 |
| 主页 | 空态引导 + CTA 正名 + 底栏精简 | 同 A + **改列表形态（滚动，去翻页）** | 底部 Tab（设备/房间/场景/我的） |
| 房间 | 不做 | 不做（HA 侧未分配 area） | 本机自定义分组 |
| 涉及 window | 复用现有 3 个 | 新增 1~2 个（向导步骤 / 完成页）+ 1 个弹层 | 再新增 Tab 与详情页 |
| 风险 | 低 | 中（新增窗口要过"三收一放 + 不透明 + 隐藏"三关） | 高（480×800 上 Tab 会再吃掉 ~60px 内容区） |
| 工作量 | ~0.5 天 | ~2 天 | ~4~5 天（含 P3 的 WS/分组） |

**推荐 B**：它把当前最刺眼的三个问题（语义错位、点一下即加、编辑藏在管理模式里）全部解决，同时不引入
Tab/房间这类需要 P3 支撑的结构。A 只治表象；C 在这个屏尺寸和当前 HA 数据状态下（房间 0/36 归位）
会做出"空的房间 Tab"，反而更糟。

### 4.5 ★ 为什么列表行里的"域"不能用图标图片

**listview 的 subItem 图片不按行区分**（本工程实测：运行时 `setBackgroundPic` 之后
所有行显示同一张图，与主界面图标必须用"21 个重叠控件"是同一个根因）。
⇒ 列表形态下做不出"每行一个不同的域图标"。

可行做法（**这就是选定方案**）：

| 元素 | 怎么实现 | 为什么可行 |
|---|---|---|
| 域块底 | **同一张**中性色圆角图 | 所有行同一张 ⇒ 不违反"不按行区分" |
| 域汉字 | 逐行 `setText("灯"/"开"/"景"…)` | `setText` 本来就是按行的 |
| 域颜色 | 逐行 `setTextColor(域色)` | `setTextColor` 按行生效（扫描页的"已添加/可添加"已验证） |
| 状态文字 | 逐行 `setText` + `setTextColor` | 同上 |

**替代方案**（若一定要域图标图片）：放弃 listview，用"每行一套独立控件"堆叠
—— 那样就**没有滚动**，行数一多就得回到翻页，等于把刚去掉的翻页又请回来。
本轮选前者。

### 4.7 命名环节与输入法的四条约束（★ 落地前必读）

> 2026-09-23 修正：原先我以为"本机没有中文输入法、改名只能选候选词"，
> **这是错的** —— 工程自带 `APP_TYPE_SYS_IME` 全拼输入法（`src/logic/imeApp.cc` +
> `ui/ime.html`），任何 `ZKEditText` 聚焦时**系统自动拉起**。命名页放一个 `div.input`
> 就能自由输入中文，成本几乎为零。下面是这件事的四条硬约束：

1. **可交互控件必须落在 y<372**。输入法键盘面板占 **y=372..800**（`ui/ime.html` 的 `KbPanel`；
   注意它已从 424 上抬到 372），压在下面的按钮**点不到**。
   ⇒ 命名页没有底部按钮："跳过"放页头，"提交"交给键盘。
2. **提交输入靠键盘自己的「完成」键**（第 45 键 → `doneIMETextUpdate(整串)`）；
   「收起」= `cancelIMETextUpdate()`。页面不要另做"确定"按钮（两个入口会打架）。
3. **`div.input` 必须写 `data-bg="#1C1C1E"`**。框架画 `.9.png` 会跳过 1px marker 边，
   控件最外那 1px 露的是**控件自己的底色**；`div.input` 有引擎默认白底 ⇒ 不写就露一圈白框。
   另外 `gen_ui.py` 的 `patch_edittexts()` 会给它补 `touchable/visible`
   （html2json 生成 edittext 时**不写**这两个字段，不补就不吃触摸）。
4. **输入的字必须落在字库子集里**。本工程 `font/*.ttf` 是完全替换系统字体的子集、
   没有逐字回退 ⇒ 缺字形是**整字消失**（不是方框）。IME 的中文候选已按
   `font/pocketgame.ttf` 的 cmap 过滤；用户自由输入的字由 `tools/gen_font.py` 的
   GB2312 一级汉字兜底保证。
   QA 走 `/tmp/pg_imecmd`：`type <串>` / `cand <n>` / `page up|down` / `done` / `dump`。

### 4.8 ★ 交付前必跑：文案字符自检（本轮靠它抓出 3 个"整字消失"）

**判据不能靠"猜 GB2312"，要用真字库的 cmap**（本工程 `font/*.ttf` 是**完全替换**系统字体的子集、
没有逐字回退 ⇒ 缺字形 = **整字消失**，不是方框）：

```python
from fontTools.ttLib import TTFont
import re
cmap = set()
for t in TTFont('font/pocketgame.ttf')['cmap'].tables:
    cmap |= set(t.cmap.keys())
s = open('ui/ha.preview.html', encoding='utf-8').read()
texts = [m.group(1) for m in re.finditer(r'>([^<>]+)<', s)]      # HTML 文本节点
texts += [m.group(1) for m in re.finditer(r"'([^'\n]*)'", s)]   # JS 字符串（会渲染的那些）
bad = {ch for t in texts for ch in t if ord(ch) > 127 and ord(ch) not in cmap}
print('缺字形（设备端会整字消失）:', sorted(bad))
```

再叠加 **html2json 黑名单**（构建期直接丢字符）：
`⌫ ℃ ■ ● ‹ － ＋ – … → ★ ◆ ▶ ▷ ①`

**本轮实测**（字库 4,209 个字形）：设计稿全部文案里只有 3 个字符有问题，均已规避 ——

| 字符 | 问题 | 处理 |
|---|---|---|
| `⋯` U+22EF | 字库无字形 | 卡片右上菜单的"三个点"改为 **CSS 画**（`.dcard .dg i` × 3）；落地用 PNG 图标 |
| `✓` U+2713 | 字库无字形 | 勾选框与完成页大勾改为 **CSS 画**（`.tick` 旋转边框）；落地用两态 PNG |
| `恺` U+607A | 字库无字形 | 从拼音候选表删掉，换成「卡」 |

还有一处不是字库问题、而是**黑名单**问题：设计稿原来到处写全角 `＋`（U+FF0B），
它**在黑名单里**，落地后按钮文字会少一个加号 ⇒ 已全稿换成 ASCII `"+"`。

**顺带确认**：`·`（U+00B7）**有**字形 ⇒「灯 · 客厅」「已连接 · 3 秒前同步」这类文案可以放心用。

### 4.5.1 ★★ 圆角素材的"底"到底该烘什么色（2026-09-24 第二轮**更正**，早先的结论是错的）

**结论（现在的正解）**：**静态九宫格素材烘"透明底"**，圆角外交给**控件的 `bgColorTab`**，
而 `bgColorTab` 由 `gen_ui.inject_rounded()` 按**该控件所坐容器的底色**自动填。

```
静态套（ios_btn_* / ios_panel* / ios_seg* / ios_card_row*）：
    圆角外 α=0  →  露出 bgColorTab（= 容器色）  ✅ 一种素材适配任意容器色
运行时套（ios_rt_*.png，setBackgroundPic 那条路）：
    不保留 alpha，必须烘**不透明底**           （否则渲染成白块/白线）
```

**早先（P4/P5）的两条错误结论，已作废**：
- ❌「圆角九宫格的四角是透明的，坐到卡片上就露窗口黑底 ⇒ 必须换成不透明烘底 PNG」
  —— 当时的素材其实**圆角外烘的是不透明黑**（不是透明），所以"换图"能解决，
  但把原因说反了，导致后续修法跑偏；
- ❌「给坐在卡片上的按钮补 `bgColorTab = 容器色` 就能消黑角（`CARD_FILL` 白名单）」
  —— `bgColorTab` 只影响**最外 1px 那一圈**，圆角里侧 4~5px 的黑**是图里的像素，补色救不回来**。
  而且白名单必然漏（新增按钮忘登记就复发）。

**判据工具**：`python tools/audit_resources.py`（第【1】节，全量；直接校验每个挂图控件的
`bgColorTab` 是否等于它所在容器的底色）。历史脚本 `check_rounded_on_card.py` / `check_ha_assets.py`
的"黑角"部分已被它取代，勿再用旧判据。
