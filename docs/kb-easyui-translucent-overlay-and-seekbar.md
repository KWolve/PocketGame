# 半透明浮层 + ZKSeekBar 进度条：四条实测结论

> 🔍 **检索导引（命中条件）**：用户问「**EasyUI 怎么做一个半透明的弹窗/浮层**」
> 「**音量条/进度条填充端为什么不是圆的**」「**进度条 0% 还有一小段颜色**」
> 「**为什么给 seekbar 设了 thumb 就变成可拖了**」「**整体半透明的 PNG 被工具/清理规则吃掉/报错**」
> 且平台为 **全志 V85X + FlyThings(EasyUI 2.9.0)** → **本篇就是答案**。
> 实测环境：V851s 480x800 竖屏，`easyui 2.9.0`，真机抓帧逐像素核对 + `pginj` 真触摸注入。

## 一句话
EasyUI 里做"真半透明浮层"**只能靠带 alpha 的 PNG 挂在 `button.picTab` 上**
（JSON 背景色的 alpha 链路上不可控）；而 **ZKSeekBar 的 `progressPic` 是按进度"缩放"整张图、
不是裁剪** —— 知道这一条，进度条的所有圆角/端点问题都能一次做对（且**不要加 `thumb`**）。

## 1. ★★ 半透明浮层：`button + picTab` 的 alpha PNG，不是 JSON 背景色

| 做法 | 结果 |
|---|---|
| `data-bg="#RRGGBBAA"` / JSON `backgroundColor` | ❌ 不可控。`html2json` 的 `to_dec()` 只认 `#RRGGBB`/`0xRRGGBB`/十进制，8 位 hex 会被当 `0xRRGGBBAA`（**字节序还不是 ARGB**）；且 SDK 那侧是 `setBackgroundColor(uint32_t /*0xAARRGGBB*/)`，中间任何一层按 int 解析，>2^31 的 A 通道就没了 |
| 运行期 `setAlpha(uint8_t)` | ⚠️ SDK 里**确实有**（`control/ZKBase.h`，0=全透/255=不透明），但它作用于**整个控件**（含子控件），做"面板半透、字仍要实"会连文字一起变淡 |
| **`button` + `picTab.pic0` = 一张 RGBA 圆角 PNG** | ✅ **正解**。alpha 混合正确、圆角天然、文字用后续控件叠在上面不受影响 |

要点：
- 面板底做成**面板同尺寸**的 button（240x112 → PNG 240x112），`data-bg` 不要写（写了不透明底会盖掉 alpha）；
  它在 html 里**第一个定义**（= 最底层），内容控件写在它后面。
- ⚠️ **装饰件要不要 `setTouchPass(true)` 看语义**：MCP `uicontrols/touch-events.md` 的通例是
  "装饰件要放行"；但**面板底不能放行** —— 放行了点面板空白处会穿到下层页面（实测会把下面的
  卡片点了直接进应用）。面板底应当**吸收**触摸。
- 实测透明度（同页抓 OSD 关/开两帧，逐像素算亮度比）：
  ```
  面板内 2408 个亮点采样  B/A 中位数 = 0.278  ⇒ 实测 alpha ≈ 72%
  设计值 184/255 = 72.2%  → 完全一致
  例：背景 #A0A0AA(160,160,170) → 面板上 #2D2D2F(45,45,47)，160×0.279 ≈ 45
  四角两帧完全相同 ⇒ 圆角外的页面内容未被覆盖 ✓
  ```
  > 判据比"看着像"硬得多，且能直接反推 alpha。无模糊可用时**别做太透**，小字压在花背景上会难读。

## 2. ★★ ZKSeekBar 的 `progressPic` 是**缩放**，不是裁剪

文档（含 CircleBar 的说明）只说"有效图会被裁剪显示进度"，seekbar 没写清。**实测四档定论**：

| 进度 | 填充实测宽（控件 200 宽） | 期望 `200×p` |
|---|---|---|
| 0% | **0 px** | 0 |
| 6% | 12 px | 12 |
| 42% | 84 px | 84 |
| 100% | 200 px | 200 |

⇒ **严格 1:1，且两端保持圆角** ⇒ 唯一自洽的解释是"把整张 `progressPic` **缩放到 `w×p`**"。
（若是裁剪，低进度时右端会是**硬切口**，而实测两端都是圆弧。）

**推论（设计的直接依据）**：
- 想要手机风格的**圆头条**：`progressPic` 直接画**胶囊**（两端半圆）即可，不需要额外控件；
- ⚠️ 副作用：缩放会把圆角**横向压扁**（源半径 5px 在 50% 进度时约 2.5px）——10px 细条上肉眼可忽略。

## 3. ⛔ 不要给 seekbar 加 `thumb`（两个独立的坑）

| 坑 | 现象 | 判据 |
|---|---|---|
| **0% 仍有颜色** | `vol=0` 时填充实测宽 **10 px**（期望 0） | thumb 被画在"进度位置"上（**左边缘对齐**），于是 0% 也留一个钮宽的白点 |
| **变成可拖控件** | `html2json` 见到 `data-thumb`/`data-thumb-pressed`/`data-thumb-size` 会**自动置 `touchable=true`**（源码注释："可拖滑块"） | 与"进度条只负责显示"的设计冲突；若 `onProgressChanged_<Caption>` 没落地业务，会出现**"看着能拖、值不变"的假交互** |

⇒ 结论：**显示用的进度条 = 只用 `backgroundPic`(轨道) + `progressPic`(填充) 两张图**，
再显式 `data-untouchable="1"` 把意图写死。要真做可拖，用
`ZKSeekBar::ISeekBarChangeListener`（带 `onStartTrackingTouch/onStopTrackingTouch`，
能实现"拖动中只跟手、松手才生效"）。

> 顺带：`pixel-analysis-ai.md` 那条"**滑块被裁成扁方 = 控件高 < 滑块图高**"仍然成立；
> 圆钮**不要加描边环**（会在屏幕上留一圈暗环）也仍然成立 —— 但按上面的结论，
> 显示型进度条根本不需要圆钮。

## 4. ★ 整体半透明的素材会被"幽灵像素"检查/清理**误伤**（工具链级坑）

"幽灵像素"判据是 `α < 阈值 且 8 邻域内没有浓像素 ⇒ 清掉`。它对**整张图都低于阈值**的
半透明素材（如 α 恒为 40 的轨道 PNG）**全图命中**：
- 清理侧：**整张图被清成 alpha 全 0**（实测：音量条轨道图生成后被擦掉，表现是"进度条只剩填充、
  轨道整条消失"，而且**不报错**）；
- 检查侧：报出上千处"幽灵像素"并 FAIL。

⇒ 两侧都要加同一条前置判断：**先看全图最大 α，若它本身就低于阈值（= 整张图是故意半透明的），跳过。**

## 5. 可复现的验收脚本片段

```bash
# ① 半透明定量（同页两帧）
adb shell "echo 'hide #a'>/tmp/pg_statusbarcmd"; <grab> out_off.png
adb shell "echo 'vol 65 200000 #b'>/tmp/pg_statusbarcmd"; <grab> out_on.png
# 逐像素：alpha ≈ 1 - median(亮度(on)/亮度(off))，只取背景亮度够高的采样点
# ② 填充比例（四档）
for v in 0 6 42 100; do adb shell "echo 'vol $v 60000 #v$v'>/tmp/pg_statusbarcmd"; <grab>; done
# 判据：填充宽 == 控件宽 × v/100（±1px）
# ③ 真触摸（按钮/拖拽）
adb shell "/data/pginj tap /dev/input/event0 <x> <y> 200"
```
⚠️ 抓屏必须**按 `fb0/pan` 选半页**，否则会拿到上一帧（本项目为 480x1600 双缓冲）。
