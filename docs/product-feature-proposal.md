# 产品功能提案（2026-09-13）

> 定位：**随身便携的「瑞士军刀级」工具机** + 消遣小产品。
> 本文回答一个问题：**这台机器该加什么功能**。
> 结论先行 → 能力边界 → 10 条候选（分档）→ 建议先做哪几个。

---

## 0. 结论先行

**这台机器的天然强项是「网络 + 媒体 + 游戏」，短板是「传感器 + 存储 + 外设」。**

> ⚠️ **2026-09-13 更正**：本节初稿把「云服务」也列成了短板（理由是"没有 curl/openssl"）——
> **那条是错的**，HTTPS 完全可用（见 §1）。所以"离线工具包"这个说法也不准确：
> **联网类功能（天气/汇率/AI/在线内容）都做得了**，只是需要把 `curl`/`openssl` 加进 Manifest。

所以它不该做成"什么都沾一点的手机替代品"，而应该做成
**一台口袋里的网络测试仪 + 离线工具包 + 复古掌机**——这三件事它的硬件都刚好够，而且
**"手持独立设备做网络排障"比手机 App 更专业**（专机专用、不占手机、能长时间挂现场）。

**如果只做 5 条，就是这 5 条**（详见 §2 第一梯队）：
**网络工具箱 / 二维码分享 / 网络收音机 / WiFi 热点 / 时钟套件**。

---

## 1. 能力边界（先看这个，避免做不了的需求）

### ✅ 能做，而且做得不错

| 能力 | 依据 |
|---|---|
| 480×800 触摸屏 + **喇叭** | 已有 |
| **WiFi 扫描**（周边 AP / 信道 / 信号强度） | `zknet` 的 `WifiManager.startScan()/stopScan()/setScanInterval()` |
| **WiFi 热点 SoftAP** | `zknet` 的 `SoftApManager.setSsidAndPwd()/start()`；且设备有 **wlan0 + wlan1 双接口**（wlan1 = AP/P2P 用口，MAC 是 wlan0 +2） |
| **IP / DHCP / 网卡控制** | `zknet` 的 `NetUtils.enableIfc/dhcpRequestIp/getIp/getMacAddr` |
| **NTP 校时** | 平台有 `ntp` 包 |
| **局域网 HTTP 服务器** | 平台有 `civetweb` |
| **原始 socket**（TCP/UDP/ICMP） | Linux + zknet，应用跑在 root |
| **音频输出**（音乐/电台/音效） | 已做（常开流 + codec 开关） |
| **视频硬解 ≤960×544** | 已做（在线流 / DLNA 投屏） |
| GPIO / ADC / **I2C** / **串口 ×2**（ttyS0、ttyS2） | `zkhardware` |
| 视频/图像解码库 | `ffmpeg` / `jpeg` / `png` / `utf8conv` / `z` |

### ❌ 做不了，或代价过高（**提案里不会出现这些**）

| 想做的事 | 为什么不行 |
|---|---|
| 蓝牙类（BLE 扫描 / 蓝牙遥控 / 传文件） | **当前完全没有蓝牙设备**：无 `/dev/hci*`、无 `/sys/class/bluetooth`（内核 BT 子系统没启用），`/lib/firmware/aic8800DC/` 还是空目录。芯片是 AIC8800（WiFi+BT 二合一）、平台有 `btstack` 包 → **不是没救，但要先解固件/内核，属于"前置投入"** |
| ~~天气 / 汇率 / AI / 在线内容等云服务~~ | ✅ **2026-09-13 纠正：HTTPS 是支持的，这条不该排除** —— 包仓库里有 **`curl 8.12.1`（HTTP 客户端）/ `curl-cxx 9.0.0` / `openssl 1.1.1-g`（SSL/TLS）/ `cares 1.17.2`（异步 DNS）**，用 `flythings_add_package` 加进 Manifest 即可；`zknet` 自身的描述也是"网络能力（Socket/**HTTP** 等）"。**云服务类功能全部可做** |
| 相册 / 电子书 / 漫画 / 大文件传输 | `/data` **只剩 528 KB** 可写（jffs2），`/tmp` 19 MB 但掉电即失；内存 56 MB 总 / 约 16 MB 可用 |
| USB 外设（U 盘 / 键鼠 / UVC 摄像头） | 只有 `4100000.udc-controller`（**Device 模式**，已被 adb 占用），**没有 Host 控制器** |
| 重力/姿态类（水平仪、计步、摇一摇） | **无传感器**（已知） |
| 声音类（分贝仪、录音、调音器、语音助手） | **无麦克风**（已知） |
| 依赖硬件时钟的离线闹钟 | **无 RTC**（无 `/dev/rtc*`）→ 时间靠 NTP，断电后需联网校准 |

> ⚠️ **两个待实测确认项**（会影响 §2 的 #4）：
> ① `wlan1` 能否**独立开热点**、同时 `wlan0` 保持 STA 连接（同芯片并发的常见限制）；
> ② `SoftApManager` 在本板固件上是否真能起来。
> 这两条建议**先做一个 30 分钟的实验再决定要不要立项**。

## 2. 候选清单（10 条，分三档）

> 成本口径：**低** ≈ 1~2 天；**中** ≈ 3~5 天；**高** ≈ 一周以上（含真机联调）。

### 第一梯队 —— 最值得做（强推荐）

#### 1. 网络工具箱 ⭐⭐⭐【成本：中】

**是什么**：一个应用里装下"网络排障"的全套家伙。参考市场标品（Network Analyzer Pro
被称作 *network Swiss Army knife*，功能几乎完全重合，且**全部是本地/明文协议、不依赖云端**）：

| 子工具 | 说明 | 可行性 |
|---|---|---|
| **WiFi 扫描分析** | 周边 AP 列表、信道占用图、信号强度、加密方式、隐藏 AP、**推荐最空闲信道** | ✅ 已有 `wifiprobe.py` 探针基础 |
| **谁在用我的网**（局域网设备发现） | IP / MAC / 厂商 / 主机名，按 IP·MAC·厂商排序 | ✅ |
| **端口扫描** | 常见端口开放探测（自己做 socket connect 超时判定） | ✅ |
| **Ping / 连续 Ping** | 含丢包率、时延抖动曲线 | ✅ 自实现 ICMP |
| **DNS 查询 + DNS 速度** | 指定域名查 A/AAAA，比较多个 DNS 服务器谁快 | ✅ UDP 53 |
| **子网 / IP 计算器** | 掩码、网段、可用地址范围 | ✅ 纯计算 |
| **Wake On LAN** | 发魔术包唤醒局域网里的电脑 | ✅ UDP 广播 |

**为什么值得做**：
- 这是"瑞士军刀"定位的**正中靶心**——市场标品就是这个形态；
- **全部是本地/明文协议**（不需要云端，所以不依赖任何外部服务）；
- **手持独立设备 = 差异化**：手机 App 要占着手机，我们的机器可以挂在机柜边一直跑；
- 已有 `wifiprobe.py`（信道占用探针）做过验证，不是从零。

**风险**：范围容易膨胀 → **建议拆成 2~3 个应用**（"网络分析"/"设备发现"/"网络诊断"），
每个都小、都能独立交付。

---

#### 2. 二维码分享（WiFi / 文本 / 网址） ⭐⭐⭐【成本：低】

**是什么**：输入文本 → 屏幕显示二维码。三个高频用法：
**① 把当前 WiFi 名+密码变成二维码**（客人/同事扫一下直接连，不用念密码）；
② 文本 / 网址 / 名片转二维码；③ 反向：扫码？**做不了**（无摄像头）。

**为什么值得做**：
- **极高频刚需**，而且**纯本地计算、零依赖、不联网**；
- 成本全线最低（QR 编码算法几百行 + 一个画布页面）；
- 和"随身"定位天然契合 —— 别人问 WiFi 密码时掏出来给他扫。

**风险**：几乎没有。唯一注意：**二维码必须用矢量/原生控件画**，别用点阵（清晰度）。

---

#### 3. 网络收音机（在线电台） ⭐⭐【成本：低-中】

**是什么**：内置一批电台，点一下就出声，可收藏、可换台。屏幕显示台名 + 当前曲目信息（若流里带）。

**为什么值得做**：
- 直接回答"**消遣**"那半句定位；
- **复用度极高**：在线流播放链路（含声卡独占、爆音处理、内存红线）**已经趟平**，
  这里主要是做 UI + 电台源管理；
- 不需要看屏幕 → 适合当"背景音"。

**风险**：① 电台源要选**长期稳定且明文 HTTP** 的清单，否则会变成维护负担；
② 内存红线仍在（≤960×544 的音视频流才安全，纯音频流没问题）。

---

#### 4. WiFi 热点 / 网络中转（SoftAP） ⭐⭐【成本：中】

**是什么**：把这台机器连着的网络，共享成一个热点给别人用；或者纯直连——
**"扫码连热点 → 手机浏览器打开设备上的网页"**，实现**不装 App 的传文字/小文件**（`civetweb`）。

**为什么值得做**：
- `SoftApManager` 的 API **已经齐备**（`setSsidAndPwd` / `start` / `getIp`），
  而且设备**有专门给 AP 用的 wlan1**（参考工程名就叫 `V851ExtendedScreen_ap_p2p`）；
- "无 App 直连传文字"是很有记忆点的功能；
- 和 #2 二维码联动（**扫码即连**）体验闭环。

**风险**：⚠️ **先做 §1 末尾那两个实测**（wlan1 能否独立开热点 / SoftAP 能否起来）。
如果同芯片不支持并发，那"中继/共享"就做不了，**只剩"纯直连传文件"**——仍是好功能，但价值打折。
另外 `/data` 只有 528 KB，**大文件传不了**，只能传文字和小图。

---

#### 5. 时钟套件（世界时钟 + 闹钟 + 校时） ⭐⭐【成本：低】

**是什么**：多时区世界时钟；闹钟（可多个）；开机/NTP 自动校时；秒表计时已在（可并进来做统一入口）。

**为什么值得做**：
- **这台机器没有 RTC**，断电后时间会不准 → **"自动校时"不是加分项，是必需品**（`ntp` 包已有）；
- 床头钟 / 桌面钟是很自然的使用场景（竖屏 + 常亮 + 有喇叭）；
- 现有秒表/定时器/番茄钟已是同类，**并成一个"时钟"应用更顺手**。

**风险**：闹钟的可靠性取决于 RTC/休眠策略（无 RTC 时，深度断电会丢时间）→ 需确认休眠行为。

---

### 第二梯队 —— 值得做，但不是第一优先

#### 6. 文本工具箱【成本：低】

编码转换（UTF-8/GBK，平台有 `utf8conv`）、Base64、URL 编解码、大小写、去重排序、
字数统计、JSON 格式化/校验。**纯本地、成本低、开发者与日常都用得上**。

#### 7. 随机与密码工具【成本：低】

强密码生成（长度/字符集/可读性）、随机数、抽签/掷骰、决策转盘。小而美，几分钟能上手。

#### 8. 设备信息 + 硬件自检台【成本：低-中】

CPU / 内存 / 温度 / 固件版本 / 运行时长 / 电池健康 + **屏幕坏点检测**（纯色轮播）
+ **触摸校准** + **串口终端**（ttyS0/ttyS2 收发）+ **GPIO/I2C 查看器**（`zkhardware`）。
面向**工厂产测、维修、二次开发**——也是"专业仪表"属性的一部分。

#### 9. 语音/音频小工具（无麦克风前提）【成本：低】

**节拍器**、**计时训练器**（HIIT：运动/休息循环，语音报数靠喇叭）、**白噪声助眠**
（配合定时关闭）。都只用喇叭，规避了"没麦克风"的短板。

#### 10. DLNA 进阶：让这台机器当"接收端"【成本：中】

现在它能**推**（投屏到电视），反过来让手机**投到它**上（当小电视）。
复用已有 DLNA 栈，但要做 renderer 侧。

---

### 三档之外：**明确不建议做**

- 任何"需要更清晰硬件才能做"的：蓝牙类、云 API 类、相册/阅读器、USB 外设类（原因见 §1）。
- 把游戏继续堆数量：**已有 13 款**，边际收益已很低；要做就做**玩法深度**（难度档、排行榜），不是数量。

## 3. 建议的落地顺序

| 顺序 | 做什么 | 为什么排这个位置 |
|---|---|---|
| **第一步** | **先花 30 分钟做 §1 的两个实验**（wlan1 独立热点 / SoftAP 能否起来） | #4 的整个价值取决于它；**先证伪再立项**，别做完了发现硬件不支持 |
| **第二步** | **#2 二维码分享** + **#5 时钟套件** | 两条都是**低成本 + 零依赖 + 当天能上机**，先把"工具机"的骨架立起来 |
| **第三步** | **#1 网络工具箱**（建议拆 2~3 个应用分次做） | 定位正中靶心，但工程量最大；放前面会被拖住 |
| **第四步** | **#3 网络收音机** | 消遣那半句的答案，且复用现成播放链路，性价比高 |
| **第五步** | **#4 WiFi 热点**（看第一步实验结果） | 有硬件风险，所以先实验后立项 |
| 之后 | 6 / 7 / 8 / 9 / 10 按需插入 | 都是"低成本独立小应用"，适合当填空档 |

---

## 4. 需要你拍板的三件事

1. **先做哪几条**（我建议：二维码 + 时钟套件 + 网络工具箱起步，收音机跟上）；
2. **#4 值不值得先做那个 30 分钟实验**（涉及热点能力，做成了功能很亮，做不成不亏太多）；
3. **蓝牙要不要提上日程** —— 它**不是硬阻塞**（芯片 AIC8800 是 WiFi+BT 二合一、平台有 `btstack`），
   但需要**内核启用 BT 子系统 + 拿到固件**，属于"要找模组厂配合"的事。
   如果能推通，**蓝牙遥控/传文件/BLE 扫描**这一整片都打开了。

| 结论 | 证据 |

| ~~平台无 curl / openssl~~ ❌ **这条是错的** | 当时只看了 `flythings_list_packages`（它给的是**当前可用子集**，25 个包），漏了用 `flythings_package_search` 搜仓库全量 —— 一搜就有 `curl / curl-cxx / openssl / cares`。**教训：判断"某能力有没有"两个都要查** |

| 内存紧 | `MemTotal 56632 kB`，可用约 16 MB |
