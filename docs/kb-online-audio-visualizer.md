# 在线音频（网络电台 / 直播伴音）的频谱可视化：取点、参数与实测成本

> 🔍 **检索导引（命中条件）**：用户问「**播放界面太素 / 想加个频谱或波形**」
> 「**音乐播放的指针摆动、FFT 波形怎么在嵌入式屏上做**」「**频谱动画是假的吧 / 怎么让它跟着声音动**」
> 「**静音了频谱还在动**」「**没有第三方音频库怎么算频谱**」「**片上 CPU 能不能扛住 FFT**」
> 且平台为 **全志 V851s / V853 / V85X（FlyThings / EasyUI）** 或任何"**音频最终灌进一条常开 PCM 流**"
> 的嵌入式方案 → **本篇就是答案**。
> 相关：`../devflow/stream-switch-and-qa-traps.md`（换源竞态与验收时间陷阱）、
> `../devflow/nocanvas-ui-animation.md`（原生控件怎么做出"像动画"的效果）

## 一句话

**频谱要"真的跟着音乐动"，取点只有一个是正确的：PCM 出口（= 喇叭里真正要放的那块数据）。**
在解码器出口、在码流层、或在 UI 层"自己编一个随时间变化的图案"，都会得到
"**静音/没声音时还在动**"或"**和听到的没关系**"的东西 —— 那不是可视化，是装饰。
取对点之后，一个 **512 点 FFT ≈ 2.3 万次浮点、30 次/秒**，在 V85X 上开销 **≪1% CPU**，
完全不需要第三方 DSP / 音频库。

## 0. 实测环境（换板请逐项重测，别照抄量值）

| 项 | 实测值 |
|---|---|
| 平台 | 全志 V851s（ARM Cortex-A7 + 硬浮点），FlyThings / EasyUI 2.9.0 |
| 音频出口 | **一条常开的 PCM 流**（片内 codec，22050Hz / 单声道 / S16），音频线程按周期不停写（空闲写静音） |
| 在线音频格式 | 解码后**统一重采样到 22050Hz 单声道 S16** 再灌这条流 |
| 面板 | 480x800 / 60Hz |
| 可视化更新率 | **30ms 一次**（≈33 帧/秒；UI 定时器 100ms 一拍时靠它自己刷新） |

## 1. 取点：为什么必须选"真正出声的那条路"

```
解码器（软/硬解） → 重采样 → [★ 这里取点] → 常开 PCM 流 → 声卡 → 喇叭
```

| 取点位置 | 静音时行为 | 结论 |
|---|---|---|
| **PCM 出口**（灌给声卡的函数） | 没有数据流过 ⇒ 频谱**不动** | ✅ 唯一正确 |
| 解码器输出 | 解码照跑（只是被静音开关吞掉）⇒ 频谱**照样动** | ❌ 用户一眼看穿 |
| 码流层（按包大小/时间戳估算） | 与音量、静音、重采样都无关 | ❌ 完全没关系 |
| UI 自己生成图案 | 永远在动 | ❌ 装饰 |

★ **副产品**：取在 PCM 出口还顺带解决了三件事 —— ① 音量/静音天然生效；
② 频率轴不需要知道源采样率（永远是重采样后的那个采样率）；③ 与"真的在放"同源，
可以作为"**链路还活着**"的判据。

★★ **但"音量不在 PCM 里"要单独想一遍**（用户会提的问题：「**幅度跟着系统音量走**」）：
很多平台的音量写的是 **codec 的数字音量**（或功放/输出开关），**PCM 数据本身不含音量信息** ——
这正是"静音后频谱不动"能成立的原因，同时也是"**把音量调小、柱子还顶到天花板**"的原因。
⇒ 如果希望"视觉幅度跟系统音量走"，必须在**显示侧**乘一个系数（不要改测量值，否则你就没法再回答
"原始电平是多少"）：

```
系数 = 静音 ? 0 : (音量% < 0 ? 255 : 音量% * 255 / 100)     // 读不到音量按"满"处理：宁满勿空
柱高 = 底(minH) + 段值 * 系数/255 * (满格 - 底)
```

三条经验：
1. **"连接中/缓冲中"那种状态动画不要乘这个系数** —— 它表示"正在连"，不是音频幅度；
   否则音量调小之后，等待动画会比播放时的柱子还高，看着像坏了；
2. 系数一变要**强制重画**（否则"变了才 setPosition"的优化会让柱子停在旧高度）；
3. 留一个 QA 开关（`follow 0|1`）—— **单变量对照**（同一段音乐、同一音量，只切开关）
   是证明"系数真的生效"最快的方式：实测同一 28% 音量下柱高峰值 **128px（关）→ 38px（开）**，
   比值 0.30 ≈ 28% ✓。

## 2. 最小实现（骨架，可直接照抄结构）

```cpp
// ① 音频写线程调用：只搬样本 + 限速触发计算（不加锁）
void Viz::notePcm(const int16_t *pcm, int frames) {
  for (int i = 0; i < frames; ++i) { ring[wr] = pcm[i]; wr = (wr + 1) % N; }
  have += frames;
  if (have < N) return;                       // 没攒够一轮
  if (nowMs() - lastMs < 30) return;          // 限速：最多 33 次/秒
  lastMs = nowMs(); have = 0;
  lock(); compute(); unlock();                // 只有这里加锁
}

// ② 取最近 N 点 → Hann 窗 → radix-2 复数 FFT → 幅度
// ③ 幅度 → 30 段对数分频（段内取峰值），dB 映射 + 快起慢落（0.55 / 0.13）
// ④ UI 线程按段取值：snapshot(uint8_t out[30])，每段 0..255
```

要点：
- **加锁只在计算那一段**（≤33 次/秒），灌数据路径（100+ 次/秒）上零额外开销；
- **环形缓冲只有写线程动**，读者只读"最近 N 点"的快照数组（写快照时加锁即可）；
- **`reset()` 只能清"给 UI 看的"那几份**，不要去清环形缓冲/写指针（那是另一个线程的东西，
  属于数据竞争；读者只用"最近 N 点"，不清也自然会被覆盖）。

## 3. 参数怎么定（附实测）

| 参数 | 取值 | 为什么 |
|---|---|---|
| FFT 点数 | **512 @ 22050Hz** | 分辨率 43Hz；再小（256）低频段会挤成一格，再大（1024）没必要 |
| 窗函数 | **Hann** | 单音泄漏低、实现一行；不加窗会有明显栅栏效应 |
| 段数 | **30 段**，对数分频 60Hz~9kHz | 人耳/观感都是对数；线性分频低音只占 2~3 根柱子 |
| 段内聚合 | **取峰值**（不是平均） | 平均会把窄带信号抹平（音乐里大量窄带成分），峰值更"跳"、更接近直觉 |
| 归一化 | 幅度 /(N) 再 /32768 | 满幅单音 = 0.5（Hann 相干增益 0.5）⇒ **-6dBFS**，符合 dB 直觉 |
| 显示增益 | 零点 **-70dB**、动态 **50dB** | 电台流普遍比 CD 低 10~20dB；这组值实测能把响的台打到 200+、轻的台仍留层次 |
| 平滑 | 上升 0.55 / 下落 0.13 | 快起慢落：鼓点跳得起来，又不闪 |
| 更新率 | 30ms | 与 60Hz 面板 / UI 定时器的比值合适；更快没有信息量 |

**实测开销**：一轮 ≈ `5·N·log2(N)` ≈ **2.3 万次浮点**；33 次/秒 ≈ 76 万次/秒
⇒ 在 Cortex-A7 上**远低于 1% CPU**（同屏还有 30 个控件 `setPosition` 的成本，合计只涨几个百分点）。

**实测数据长什么样**（`viz` 快照，播一个 64k MP3 电台）：
```
电平=250 增益=-70dB 段数=30 FFT次数=255 已灌帧=1104034
段=[203,203,235,234,237,233,233,224,214,206,193,187,165,155,148,158,144,132,131,118,113,114,...]
```
⇒ 低音重、高音轻的典型音乐包络。**如果打出来是一串 0 或一串 255，说明增益没标定或取点错了。**

## 4. UI 侧怎么画（无自绘画布的工程）

| 手法 | 做法 | 代价 / 注意 |
|---|---|---|
| **竖排频谱柱**（推荐） | N 个 `textview + 背景图`（`class="icon"`），每拍**只改高度**：`setPosition(x, bottom-h, w, h)` | 图按控件盒缩放 ⇒ 纯色/渐变柱**可以**改尺寸；**初始盒 == 素材尺寸**，静态检查工具才不会报"拉伸" |
| **模拟指针表（VU）** | `div.pointer`（`ZKPointer`）**每只表一个控件**：`setTargetAngle(角度)` | 见下面"指针表"一节；**比"预烘 N 帧切 visible"省一个数量级的内存** |
| 横向电平条 | 1 个控件改宽度 | 同上 |
| 点阵环形均衡器 | 一圈小圆点按频段**切 `visible`** | 不拉伸、最稳，但读数弱 |
| 指针表（退路） | 预烘 N 张角度图，**按 visible 切换** | 一个 200x200 的图层解码就是 160KB，45 帧×2 表 = **14MB** —— 小内存板别走这条路 |

### 4.1 ★★ 用 `ZKPointer` 做"真实仪表"（VU 表）——本工程实测口径

（字段权威：MCP 知识库 `uicontrols/pointer-fields.md`；下面是**在 ftu 页里把它当仪表用**的落地要点）

| 要点 | 做法 / 判据 |
|---|---|
| 控件 | `<div class="pointer" data-pointer-pic="images/needle.png" data-pointer-w/h="200,200">`；html2json 认 `pointer`/`gauge`/`dial` |
| 圆心 | `rotationPoint`（**控件系**）+ `fixedPoint`（**指针图系**铰点，可超界）；两者配套否则绕错圆心 |
| 控件位置 | **控件左上 = 表盘圆心 − 指针图尺寸/2**（例：图 200x200、圆心在表盘 (113,176) ⇒ 放 +(13,76)） |
| 驱动 | `animatable=0` + 调用方定时器 `setTargetAngle(度)`；**仪表用 25ms（40fps）**——20fps 能看出台阶 |
| ★ 素材基准 | **指针图必须用"0°（针尖朝正上方）"画** —— 控件旋转的就是"图片原样"。若把"0 VU 的 +16°"烘进素材，上机后所有角度整体差 16°（本工程踩过） |
| 表盘底 | 刻度弧/数字/红区/读数窗全烘成**一张 1:1 PNG**（`class="icon"`）；**数字读数必须是 text 控件**（动态） |
| 表针观感 | 指针别做成"跟着瞬时电平抖"：给 **VU 弹道**（上升 ~55ms / 回落 ~320ms）才有"甩上去、慢慢落"的仪表味 |
| 视图切换 | 两组控件**同区域互相显隐** + 两枚"亮/暗两态"页签（暗的那枚可点，亮的 `touchable=false`）；切回来要**作废"变了才写"的缓存**，否则第一拍是旧几何 |

#### 4.1.1 ★★ 表针做出来"看着像坏了"的三种症 —— 全是**零点/兜底/换源**问题，不是控件问题

上机实测（2026-09-19）踩到的三种，症状很像"控件/素材坏了"，实际都不是：

| 症状 | 真因 | 修法 |
|---|---|---|
| **针不动（冻住）** | 电平是**别的线程喂**的，停流后没人喂 ⇒ 弹道变量保持在最后值 | 表必须**自己推回落**：自己的定时器里做"**静音 >400ms 后按回落弹道归零**"（幂等，可无脑每拍调）。**不能指望数据源发"我停了"** |
| **针顶死在刻度末端** | **0VU 零点标定错了**（数据没错） | 先用"读数=绝对值"的口径（把零点设成 0dBFS ⇒ 读数即 dBFS）**采一批真数据**，再按分布定零点。**别用眼睛调表** |
| **换台后立刻"打不开"** | 原流的**收尾是异步的**（实测 ~1500ms），这之前起新流被拒 ⇒ 被当成"源坏了" | 见 §4.1.2 |

**标定要采分布，不要采单点**：同一台在几十秒内会波动 4~6dB（内容/广告/静音段）。
本工程实测（连采 18 次，单台）：均值 **−10.5dBFS**、范围 **−8.0 … −13.6**；
跨台分布：响的音乐台 −9…−11、说话台 −15…−16、安静台 −22…−24。
⇒ 零点应让**响的那一档落在 0VU 标记附近**（峰值刚够到红区），整条弧才有用。

#### 4.1.2 ★★ 换源/换台：**"请求停止" ≠ "已经停止"**

`stop()`/`stopForSwitch()` 这类接口通常只是**登记请求**，真正的收尾（"解码器放空"）由
解码线程异步做 —— 实测 **~1500ms**。这期间调 `start()` 会被**直接拒绝**，
而拒绝的表现与"这个源坏了"**完全一样**（起流失败 ⇒ 界面弹"打不开"）。

★ 规则：**任何"停止 → 立刻开始"的序列，中间都必须有一个可观测的"已停止"状态**
（`running()==false`）。两种实现里选后者：
- ✗ 在 UI 线程 `while (running()) sleep(20)` —— 界面僵 1.5s；
- ✓ **两段式**：请求时只登记（记下"欠一次起流"），交给页面定时器等 `running()==false`
  （+超时兜底）再真正起。

副作用（好的那种）：连按换源时，中间的请求会**自然被最后一次顶掉** —— 正是用户期望的行为。

#### 4.1.3 这板子的日志不可依赖 ⇒ "数字证据"要**同时落文件**

日志服务被 SSDP/扫描之类的噪声刷爆后会**整块卡住**：`logcat -d` 只回最后一次 flush 的内容，
`logcat` 流也只 flush 一次就断（实测：常驻收集器 3 秒后 841 行，之后**再也不增长**）。
⇒ 凡是"要拿来做判据"的自检命令，**顺手把同一份快照写一个文件**（读文件比抢日志稳）。
⚠️ 只在**按需调用**时写，**不要每拍写**（`/data` 在 NAND 上，别为了诊断磨闪存）。

#### 4.1.4 验收手段：从像素里**反读表针角度**

仪表类改动的终局判据是"**针停在哪**"，而这本来就是画面上的事实：
按"**径向覆盖率**"粗定位（沿每个候选角度从铰点向外找指针色像素，贯穿半径最多的就是针），
再用**针尖坐标精修**（小半径处 1px 横向偏差顶好几度 ⇒ 只用覆盖率精度只有 ±2°，精修后 <1°）。
搜索角要**排除表盘上其他深色构件**（本例是右下角的数字读数窗 —— 一块大色块，会盖过针）。
★ 与页面自报的角度**互相印证**（本例实测差 <1°），这才叫"验收判据落到画面上"。

### 4.2 三条纪律（画的时候）

1. **变了才 `setPosition`** —— 无脑每帧写 N 个控件 = 重绘风暴（实测：49 个控件/拍没问题，
   但那是 25ms 节拍下"变化才写"的成本）；
2. "连接中/停止时"的等待动画必须由**绝对时钟**推导（相位不漂），
   **不要**用"累加 dt / 帧计数"做相位（会漂，甚至在跳帧设计下永久冻住）；
3. 停止/退出页面要**把快照清零** —— 快照是"最后一块 PCM"的值，不清会留一屏柱子。

## 5. 标定：用数字，不要用眼睛

- 给一条 QA 打印（段值数组 + 总电平 + 增益 + 已算次数）；**先看数字再调**：
  - 全是 0 → 增益零点太低（流太轻）或取点没接到数据；
  - 长期贴 255 → 零点太高（削顶，看不出动态）；
  - 只有低频几段有值 → 正常（流行乐/语音就是这样）；
- 增益做成**现场可调**（一条 QA 命令改 dB），别写死在代码里等重新编译。

## 6. 验收：两条证据缺一不可

1. **数字证据**：QA 打出段值快照（上面那行）。判据：段值**随音乐变化**、总电平在动。
2. **像素证据**：**连抓若干帧，量同一根柱子的高度序列**。
   ⚠️ 抓一帧要 1.2~2.4s，而柱子每 30ms 就变 ⇒ **"抓到的帧一定是不同状态"**，
   所以"三帧高度序列互不相同"就能证明它是数据驱动（而不是一张固定图案）。
   实测序列（同一台、连抓 3 帧、量柱顶 y）：
   ```
   86 86 107 107 131 131 132 131 125 105 ...   ← 帧1
   88 88  93  90  99  96 100  96  94  92 ...   ← 帧2
   77 77  84  80  86  82  82  77  80  86 ...   ← 帧3
   ```
   ★ 反面判据：三帧**字节级相同** ⇒ 要么没在放音，要么你在看一张静态图（或抓错页）。

## 7. 一页速查

| 现象 | 第一嫌疑 | 立即验证 |
|---|---|---|
| 频谱一直不动 | 取点不在 PCM 出口 / 没在出声 / 快照没刷新 | 打"已灌帧数"；对照是否真的在播 |
| **静音后频谱还在动** | 取点在解码器出口（旁路了静音开关） | 把取点挪到"灌声卡"那个函数里 |
| 柱子全是 0 | 增益零点太低 / 未标定 | 打段值 + 逐档调增益 |
| 柱子长期贴满 | 增益零点太高 | 同上，往低调 |
| 柱子闪烁、抖动大 | 平滑系数太小 / 段内用了平均值 | 上升 0.55 / 下落 0.13；段内取峰值 |
| 动画"一顿一顿" | **帧率**问题（不是 CPU）：60Hz 面板跑 20fps | 量"本页 tick 间隔 / 单拍耗时 / CPU / 面板 fps"，时基降到 25ms |
| 停止后留一屏柱子 | 没清快照 | 停止/退出时 `reset()`（只清 UI 那份） |
| **音量调小了柱子还满格** | 取点在 PCM 出口（**音量不在 PCM 里**） | 显示侧乘音量系数（见 §1 末尾；静音/0 音量 → 系数 0） |
| 音量调小后"等待动画"反而比柱子高 | 把状态提示也乘了音量系数 | 只对音频驱动的部分乘系数 |
| **指针整体偏一个固定角度** | 指针素材不是"0° 原样"（把某 dB 的姿态烘进去了） | 素材按"针尖朝上"重画；dB→角度只放在调用方 |
| 指针绕错圆心 | `fixedPoint`/`rotationPoint` 没配套 | 图铰点在正中 ⇒ 两个都设 (图宽/2, 图高/2)，控件放"圆心 − 图尺寸/2" |
| 指针"抖"而不是"摆" | 没做 VU 弹道（直接跟瞬时电平） | 上升 ~55ms / 回落 ~320ms |
| 抓到的三帧一模一样 | 抓错页（双缓冲）/ 页面本来就是静态 | 读 `fb0/pan` 选半页；抓完再读一次 pan 确认没翻页 |

## 8. 换板 / 换工程对照清单

- [ ] 音频出口的**采样率与声道数**（本板 22050 / 单声道）→ 频率轴与分频表都要跟着改；
- [ ] 出口是不是**常开流**（空闲写静音）→ 决定"取点在写函数里"是唯一位置；
- [ ] CPU 主频 / 有无硬浮点 → 重测 FFT 开销（无 FPU 的板子要换定点或降点数）；
- [ ] UI 刷新率与控件重绘成本 → 定更新率（本板 30ms）；
- [ ] 有没有"改尺寸不拉伸"的限制 → 决定用柱子（可缩放纯色）还是点阵（切 visible）。
