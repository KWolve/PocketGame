# 摇骰子（3 颗骰子 · 离线 3D 烘帧 · 触摸优先）

> 2026-09-15 新增。第 **24** 个应用、第 **15** 款游戏（slot 23）。
> 用户需求原文：「帮我写一个摇骰子的游戏，基于 FlyThings UI 框架，3 个骰子，要模拟 3D 效果和声音」，
> 参考产品 = App Store《简易骰子 － 朋友聚会摇色子模拟器》。
> 实现：`src/core/PgDice.cpp` / `PgGames.h` 的 `GameDice`；素材生成 `tools/gen_game_art.py` 的 dice 段。

## 1. 玩法

| 项 | 内容 |
|---|---|
| 操作 | 点屏幕（或按暂停键 A）摇一次；一次点按 = 一次摇 |
| 动画 | 三颗同时翻滚 **约 0.9s**，然后**从左到右依次停定**（间隔 150ms）+ 落定下沉回弹 |
| 结果 | 结果板显示三颗点数 + **和值大字** + 评语 |
| 彩头 | **豹子**（三同，最大彩头）/ **顺子**（123·234·345·456）/ **大**（和值 ≥11）/ **小**（≤10） |
| 计分 | 得分 = 本次和值；最高分 = 历史最大和值（HUD「最佳」）；HUD「第几次」= 累计摇动次数 |
| 结局 | **没有输赢**（这就是"聚会比大小"的用法），可以一直摇 |

音效（新增 `resources/audio/dice.wav`，见 §5）：翻滚中每 120ms 一拍"骰子碰撞"，
每颗停定各一声"落地"，豹子/顺子各有一声彩头音。

## 2. ★★ 3D 是**离线烘出来的**（不是在画布上现画）

画布（`core/PgCanvas`）没有多边形贴图、也**不做运行时缩放**（工程铁律：所有东西 1:1）。
所以"把点数纹理贴到斜面上"这件事**在运行时做不到**，只能离线算完烘成 PNG。

`tools/gen_game_art.py` 的 dice 段做的事（纯 Python + PIL，不需要 numpy）：

1. **正交投影**：立方体 8 顶点 → 旋转矩阵 → 屏幕坐标（`y` 翻转）。
   选正交而不是透视的理由很实际：**正交投影下每个面的投影是平行四边形**，
   于是"把方形点数纹理贴上去"是一条**精确的仿射变换** —— `Image.AFFINE` 直接能算，
   不用解 8 元单应矩阵；观感上等轴方块也正是骰子游戏常见的画法。
2. **背面剔除**：`R·n` 的 `z ≤ 0` 丢掉（观察者在 +z 无穷远）。
3. **光照**：面亮度 `k = 0.66 + 0.34·max(0, n·L)`，`L` 是**世界坐标里固定**的光源方向
   ⇒ 骰子一转，三个面的明暗就跟着变（立体感的主要来源）。
4. **贴面**：对每个可见面算 `p00/p10/p01`（投影后的三点），解 2×2 逆矩阵得到
   "屏幕 → 纹理"的仿射系数，交给 `tex.transform(..., Image.AFFINE, ...)`（C 实现，快）。
5. **倒角**：面纹理四周一圈用**模糊的内缩圆角矩形当 mask 压暗**。没有它，三个面拼起来
   就是"三块平板"（像魔方不像骰子）；有了它，棱线附近有明暗过渡，像实体骰子。
6. 4 倍超采样再 `LANCZOS` 缩回 ⇒ 斜边和点数圆自带抗锯齿。

### 帧表（共 19 张 + 整屏桌面 1 张）

| 素材 | 张数 | 说明 |
|---|---|---|
| `dice/face1..6.png` | 6 | **静止帧**：值为 v 的面朝上。视角 = `Rx(25°)·Ry(-35°)`（右上前方俯视，同时看到顶/前/右三面） |
| `dice/roll0..11.png` | 12 | **翻滚**：绕斜轴 `(1,1,0.35)` 每帧 30°，**12 帧转满一圈 ⇒ 首尾相接、可无缝循环** |
| `dice/shadow.png` | 1 | 接触阴影（半透明椭圆，锚点=中心） |
| `dice/bg.png` | 1 | 绿毡桌面 + 木框 + 暗角 + **结果板**（整图不透明 ⇒ 走 memcpy 快路径） |

- **所有帧的锚点都是图中心**（= 立方体中心的投影，旋转不改变中心）⇒ 换帧不会跳位，
  这一点比"每帧各自的包围盒中心"省心得多（打地鼠的三帧锤子就因为锚点不同而必须逐帧导出锚点）。
- 图尺寸 152×152：立方体边长 78 ⇒ 最大投影半径 `√3/2·78 ≈ 67.5 < 76-2`（自检要求不贴边）。
- 点数色：**1 和 4 用红点**（中式骰子），其余深墨。

### 生成器里的自检（`check_dice_face`）★

渲染出一个"挺像骰子"的东西很容易，**点数画错却看不出来**（视角改一点、`u/v` 轴写反，
照样是个立方体）。所以生成器强制验证一条不变量：

> **朝上的那个面，画出来的点数必须正好等于面值。**

做法：用同一套投影函数拿到"顶面四边形"（`dice_quad`，几何只有一处实现），内缩 6px 避开棱边描边，
**数里面的深色连通块**（= 点数），必须 == 面值。六个面全部 ×√。
翻滚帧不做这项（斜着的面上点数会互相贴边，连通块计数不具备判据效力）。

另外每帧都查"可见面数 ∈ {2,3}"——视角算错（比如只看到一面）会被直接拦下。

## 3. 运行时的动态部分（只有这些留在代码里）

- 翻滚帧切换：`frame = (animMs_/55 + i*4) % 12` —— 每颗加 **相位偏移**，否则三颗动作一模一样。
- 位移抖动：`y += 7·sin((animMs_ + i*110)·0.028)`；落定阶段整体下沉 `4px` 再归位。
- 阴影浓淡：翻滚中 `alpha=120`（骰子离地）、停定后 `190`。
- 结果板的文字（点数行 / 和值大字 / 评语）：和值用画布大字库 `bigNumberCenter(scale=3)`。
- **不做缩放**：所有"弹跳感"都只靠位移 + 阴影 + 音效（缩放会重采样发糊，工程明令禁止）。

`stillFrame()` 返回 `phase_ == PH_IDLE`：停定后画面一动不动 ⇒ 宿主跳过重绘（省掉整屏桌面
+ 3 颗骰子的重贴）。翻滚/落定期间必须返回 false，否则骰子会冻在半空。

## 4. QA 通道（`gdbg <...>`）

| 命令 | 作用 |
|---|---|
| `roll` | 摇一次（**走与触摸完全相同的入口** `startRoll`） |
| `force a b c` | 指定**下一次**摇出的点数（各 1..6）。豹子/顺子靠随机摇几乎复现不出来，用它把分支固定住；从摇动到结算仍走完整流程，**不改分数**，所以验收仍然有意义 |
| `state` | 打印 次数 / 三颗点数 / 和值 / 评语 / 阶段 / 最佳 |

## 5. 新增音效 `dice.wav`

- `tools/gensfx.py` 加一段：**四个短噪声脉冲首尾相接**（0.20s，16bit/22050Hz 单声道）。
  做成一串而不是一声，是因为游戏侧按 120ms 节拍**重复播**它（`GameDice::update`），
  单个脉冲太单薄，连播像敲钉子。
- 登记两处（漏一处就静默无声）：`core/PgGame.h` 的 `SfxId`（**追加在表尾**，
  否则 `kSfxFiles[]` 的对应关系会整体错位）+ `platform/PgAudio.cpp` 的 `kSfxFiles[]`。

## 6. 坑（都是这次真踩的）

### 6.1 ★★ `ScoreStore::MAX_GAMES = 16` ⇒ **slot ≥ 16 的应用最高分永远是 0**（静默失败）

接入骰子时 `gdbg state` 打出 `best=0`（明明刚摇出 15）。根因：`setHigh(23, 15)` 被
`index >= MAX_GAMES(16)` **直接 return** —— 不报错、不打日志、不落盘。

受影响的**不止新游戏**：slot 16~23（五子棋 / 反应计时 / 时钟套件 / 网络电视 / 信号探针 /
消消乐 / 摇骰子）的最高分**一直都没存上**。已把 `MAX_GAMES` 扩到 32；
对老存档**向下兼容**（`load()` 按行顺序读分数，旧文件只有 16 行，其余默认 0，`save()` 时自然补齐）。
实测：修复后 `best=12`（force 4 4 4）。

> 教训：**"查表越界就 return"是静默失败的温床**。这里的表是"按 slot 存分"，
> 而 slot 会随着加应用一直涨 —— 两边必须在同一处约定（或干脆让越界能打日志）。

### 6.2 光照下限太低 ⇒ 暗面"发黑"

第一版 `k = 0.50 + 0.50·dot`：背光面只有 0.5（白 250 → 125），三颗骰子的右侧面糊成一片脏灰。
改成 `0.66 + 0.34·dot`（顶点 0.99 / 最暗 0.66）。判据来自 **ASCII 缩略图**（把 152×152
降到 76×38 打字符，按亮度分档）—— 不靠肉眼盯原图，也能一眼看出"右侧整片偏暗"。

### 6.3 结果板与背景对比度不够

结果板填充 `(28,34,44)` 与暗角背景本来就很接近，第一版 2px 的描边缩到整屏看几乎分不出边界。
改成**填充更暗 + 3px 亮描边**。

### 6.4 触摸注入 `hold` 太短会只剩"抬手"

`pginj tap <dev> x y 60` 实测只产生 `action=2`（抬手），框架不认点击；
用 **140ms** 就正常（`action=1` + `action=2` + `list click`）。
另：`/tmp` 上 `chmod +x` 无效（执行被拒），把 pginj 放 `/data/` 即可。
