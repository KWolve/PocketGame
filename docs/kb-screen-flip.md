# 运行时整屏 180° 翻转（挂绳倒挂）+ 全局显示变换的验收方法

> 2026-09-18 入库（来源：某 V85X 竖屏掌机工程，用户需求「屏幕挂绳在底部 ⇒ 屏保/机器人界面按 C 键
> 切换成倒 180° 显示」）。此前 knowledge 里没有"运行时改屏幕方向"的口径，也没有
> "同一个按键事件被投递多次"这条平台事实 —— 后者坑掉了一整轮调试。
> 检索词：屏幕旋转/整屏翻转/倒过来显示/180 度/setScreenRotate/setTouchRotate/rotateScreen/rotateScreen rotateTouch/
> ConfigManager 旋转/运行时改方向/zk_disp_set_rotate/zk_event_set_touch_rotate/触摸坐标跟着转/点哪看哪/
> 挂绳倒挂/横竖屏切换/按键被投递两次/按键重复投递/一次按下触发两次/幂等按键处理/
> 抓屏倒着/fb 内容旋转/旋转验收/触摸节点不固定/touchDev 不存在/pginj 点了没反应。

## 0. 一句话口径

**整屏旋转是框架自带的实时能力，一行就能用；但"翻转"是全局副作用，必须收口成
"用户意愿（落盘） × 哪一页正在显示"每拍算一次的状态，且它会让 `/dev/fb0` 变成"转过之后"的画面。**

```cpp
// 画面与触摸必须一起改（只改一个 = 点哪儿都不对）
CONFIGMANAGER->setScreenRotate(180);
CONFIGMANAGER->setTouchRotate(180);
```

## 1. ★★ 这是**实时**接口，不用重启（有反汇编依据，不是"试试看"）

`libeasyui.so`（2.9.0）里：

```asm
0005c404 <_ZN13ConfigManager15setScreenRotateEi>:
    ... str r1,[r2]            ; 存静态量 sScreenRotate
    ... b 99884 <zk_disp_set_rotate>        ; ← 尾调用：立刻改显示
0005c42c <_ZN13ConfigManager14setTouchRotateEi>:
    ... b a28d8 <zk_event_set_touch_rotate> ; ← 尾调用：立刻改触摸映射
```

- `zk_disp_set_rotate` / `zk_event_set_touch_rotate` 在这份库里**没有导出**
  （`nm -D` 查不到）⇒ 只能走 `ConfigManager` 这对 setter，不要去找底层符号。
- 两者都自己把角度归一到 `0/90/180/270`；传别的值不会报错，会被规整（`90/270` 会换宽高）。
- `EasyUI.cfg` 的 `rotateScreen/rotateTouch` **只在开机读一次**；进程起来之后由应用托管。
  ⇒ 两个值**永远成对改**，否则出现"画面转了、触摸没转"这种最难查的错位。
- 视频若走**独立 disp 层**（`ch0/lyl0` 之类），不保证跟着转；纯 UI 页没有这个问题。

## 2. ★★ 旋转发生在"写 fb 之前" ⇒ 抓屏拿到的是**倒着的画面**

真机实测：设 180° 后抓 `/dev/fb0`，画面恰好是原来的 180° 旋转（**384000 像素 0 差异**）。
所以：

- **验收工具必须先转回来**（本次给体检脚本加了 `--rot180`）。
  不加的现象是"报一堆版式错误"（砖块没上屏、数字认不出来）—— 那不是页面坏了，是帧倒着。
- 也意味着**"用户看到的 = fb 里的内容"**，所以"翻转到底生效没生效"可以用抓屏逐像素证明，
  不必靠肉眼或"读日志"。

## 3. ★★★ 同一个按键事件会被**投递多次**（本次最大的坑）

在这块板上（屏保是 `SysApp`，下面还压着 Activity）：

```
屏保: C 键投递#1 down=1 long=0（t=1562481ms）
屏保: C 键投递#2 down=1 long=0（t=1562482ms）   ← 同一次按下的重复投递
屏保: C 键投递#3 down=0 long=0（t=1562566ms）
屏保: C 键投递#4 down=0 long=0（t=1562567ms）
```

**一次物理按下 = 4 次投递（DOWN×2 + UP×2）**，间隔只有 1ms —— 是"两条链各投一次"，
不是按键抖动，也不是 repeat。已知"链内短路"（某个 listener 返回 true 就停止往下发）成立，
但**跨链不短路**。

### 后果（两个症状，都在同一次改动里踩到）

1. **有状态的切换被切两次**：`toggle()` 收到两次 DOWN ⇒ 转过去又转回来，**净效果为零**
   （现象："按了没反应"）。
2. **"用一次就把标志清掉"的写法会漏**：为了吞掉后续的抬起事件设了 `seen=true`，
   第一次抬起时清掉 ⇒ **第二次投递的抬起被放行**，于是"顺手执行了该键的默认动作"
   （本次现象："按一下翻转键，屏保直接被唤醒关掉了"）。

### 口径（写按键处理时的纪律）

- **单次动作（返回/唤醒/音量）**：天然幂等（"已经在菜单了再返回一次"无所谓），可以不特殊处理。
- **状态切换（开关、翻转、静音）**：必须**幂等去重** —— 常用做法是
  `if (now - lastDownMs < 60) return;` （60ms 远小于人手连按间隔）；
- **配对事件（DOWN/UP）**：抬起侧**一律吞掉、不要用"消费即清"的标志**；
  让标志只被"下一次 DOWN"覆盖（或配合上面的时间窗）。
- 调试时**每次都打一行投递日志**（含序号/状态/时间戳），这类问题一分钟就能看穿。

## 4. 全局显示变换的"作用范围"怎么收口

需求常常是"只在某几页倒过来"。**不要**在各页里各自 `setScreenRotate`（迟早互相打架、退出不还原），
而是收口成一个小模块，每拍算一次：

```cpp
// want = 用户意愿 && 有没有"环境页"在显示；只在变化时才真的下发
int want = (wanted && (pageOn[PAGE_SAVER] || pageOn[PAGE_PET])) ? 180 : 0;
if (want != applied) { CONFIGMANAGER->setScreenRotate(want); CONFIGMANAGER->setTouchRotate(want); }
```

要点：

- **每拍重算 = 自愈**：漏报一拍、掉帧、从别的页面跳回来都不会把屏幕留在错的角度；
  状态没变时它就是空操作（不会反复下发）。
- **各页只负责上报"我在显示"**（幂等布尔，随便调）；退出侧要保持警惕：
  `SysApp`（屏保那类）**退出后就收不到 tick 了** ⇒ 退出侧的上报必须挂生命周期钩子
  （`onUI_quit`）。这与"退出时恢复亮度"是同一类坑。
- 组件只要一句 `virtual bool isXxxPage() const { return false; }` 由需要的页面覆盖即可
  （纯增量，既有页面零改动）。
- ★★ **模态浮层要能"抑制"它**：环境页之间互相叠加还好办，但**"要人读/要人点"的浮层**
  （闹钟提醒、来电、倒计时到点这类）会弹在环境页**之上** —— 实测它在屏保显示中弹出时
  `环境页 saver=1` 仍为真，只按"环境页在不在显示"算就会给出**倒着的闹钟**。
  ⇒ 加一路抑制器：`want = 意愿 && 环境页在显示 && !被抑制`；
  上报位置与页面显隐同一处（每拍重算 ⇒ 浮层收起后自动恢复）。
  **判据**：把浮层在"正向"下抓一帧当参照，再在"倒挂意愿 + 环境页在显示"下抓一帧，
  两者应**逐像素一致**（实测 diff=0；与"转过 180°"比 diff=292376）。
  经验：**加了全局副作用之后，要把"这期间还可能弹出什么"过一遍清单。**
- **意愿落盘**（`/data/...`，jffs2 重启不丢）：挂绳/车载这类"设备长期以某种姿势存在"的场景，
  用户不希望每次重启都重按一遍。
- 开机只读状态、**不要立刻转屏**（此刻还没有环境页在显示，转过去只会让开机首页倒着）。

## 5. 验收方法（不要只靠"读日志"）

本板日志缓冲只有十几行、会被无关日志刷爆 ⇒ 用**逐像素**做判据：

```
同一页面抓两帧：A（变换关）、B（变换开）
d_direct = diff(A, B)              // 变了多少（逐像素差 > 阈值的个数）
d_rot    = diff(rot180(A), B)      // 把 A 转过去再比
· 生效   ⇒ B ≈ rot180(A)  ⇒ d_rot 远小于 d_direct（实测 292253 → 2760，两个数量级）
· 没生效 ⇒ B ≈ A          ⇒ d_direct ≈ 0
```

**触摸"跟着转"的黑盒判据**（不用读坐标，用"行为分区"）：找一个**上下分区有不同语义**的界面
（例：宠物上半=摸头、下半=打招呼），在**同样的两个物理点**上分别于"正向/倒挂"两态各点一次：

- 若触摸跟着转 ⇒ 两态的结果**正好互换**（点上方：正向=摸头，倒挂=打招呼）；
- 若没转 ⇒ 两态结果相同（用户就得反着摸）。

这比"读日志里的坐标"更强：它同时证明了"坐标被镜像了"和"镜像方向是对的（点哪看哪）"。

## 6. 顺带一条硬事实：注入触摸的节点**以框架进程的 fd 为准**

`EasyUI.cfg` 里的 `touchDev` 可能**根本不存在**（本次实测：cfg 写 `/dev/input/event4`，
而设备上只有 `event0`）。注入工具打开失败只报 `open: No such file or directory`，
在应用侧看起来就是"**点了没反应**"（又一例静默失败）。

```bash
ls -l /proc/$(pidof zkgui)/fd          # 真值：框架实际打开的是哪个 event
ls /proc/bus/input/devices             # 名字↔event 的对应（能力位可交叉验证）
pginj proto /dev/input/event0          # 本板报 MT 协议 A；再 tap
```
