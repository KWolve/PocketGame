# IPTV 频道表：PC 侧实测筛选（2026-09-14）

> 目标：把 **国内可用的源** 加进 `resources/iptv/channels.m3u`，入库前在 **PC 侧实测**：
> 编码必须是 **H264**（本板只硬解 H264），分辨率 **≤720p**，帧率 **≤30fps**。
> 工具：`tools/iptv_probe.py`（纯 Python，**不依赖 ffmpeg** —— 自己解 TS/SPS）。

## 一、为什么要新写一个探测工具

原来的 `tools/hls_filter.py` 只看 m3u8 里声明的 `RESOLUTION`（media playlist 根本没有），
而且**不看编码、不看帧率**。本板三个硬条件它一个都覆盖不到：
只硬解 H264、直接解上限 960x544（720p 要走硬件播放器 1/2 缩放解码）、帧率 ≤30。

`iptv_probe.py` 的做法（**真拉码流自己解**）：

1. 拉 m3u8 → master 挑最低码率档 → media 清单拿分片 URL；
2. 真下最后一个分片（限 1.5MB），首字节必须是 TS 同步字 `0x47`；
3. 自己解 TS：PAT → PMT → 视频 PID + **stream_type**（`0x1B`=H264 / `0x24`=HEVC→淘汰）；
4. 从 PES 里攒 H264 ES，找 SPS（NAL `0x67`），按规范解出**宽/高（含 frame_cropping）
   与 VUI 里的 time_scale/num_units_in_tick → 精确帧率**；VUI 没写 timing 的退化成
   "数 AUD/首片个数 ÷ 分片时长"估帧率，估不出来的直接淘汰。

⚠️ 探测用的 UA **必须与设备端 `PgHls.cpp` 的 `kUserAgent` 逐字一致**，
否则"PC 通、设备 403"这类差异会让这次实测白做。

### 踩过的两个 TS 解析坑（症状都是"PMT 里找不到视频流"）

1. **PSI section 前面有 `pointer_field`**，要先跳过再读 `table_id`；
2. **`section_length` 含末尾 4 字节 CRC** —— program/ES 循环必须在 `3+seclen-4` 收尾，
   否则 CRC 会被当成一条 program 表项，把刚解出的 PMT PID 覆盖掉。

## 三、★ 设备端回验：720p 起播静默崩 → 已定位并修复（2026-09-14）

抽新表里的 **720p 源**（浙江萧山 `l.cztvcloud.com`、CCTV-1 `74.91.26.218:82`）在真机上回验，
发现它们在默认硬件链路上**起播瞬间静默重启**（zkgui 被 init 拉起、pid 变、无任何报错输出），
日志停在 `[HW] 起硬件播放器：源 1280x720，旋转 90°，缩放解码 1/2` 之后。

**根因**：本工程**从来没设 `ZKMEDIA_H264_VBVSIZE`**（码流缓冲），库用的是默认的小值；
720p 的 I 帧几百 KB，喂进太小的 VBV 就出事。参考工程 `src/media/audio_context.cpp` 的
`init()` 里一直设着 **`1048576`（1MB）**，旁边还留着 2MB/3MB 的档位注释。

**修复**：`PgH264` 在第一次 `zk_h264_player_preload()`（即 dlopen）**之前**设好这个环境变量，
文件播放与在线流两个入口都覆盖（`ensureZkmediaEnv()`）。

排查过程中排掉的假设（都留着记录，避免以后再试）：

| 假设 | 实验 | 结论 |
|---|---|---|
| 内存不够（OOM） | 加 `drop_caches` 后可用内存 10.3MB→**26.7MB** 再试 | ❌ 照样崩 |
| `init` 里传旋转有问题 | 改成 init(rot=0) + 起播后 `set_rot` | ❌ 照样崩（文件路径同样写法却不崩） |
| crop 发早了（旋转前） | 顺序改成 `pos→show→set_rot→crop` | ❌ 照样崩 |
| 旋转+缩放组合不支持 | 960x540（不缩放）+rot90 → **正常**；720p+1/2+rot90 → 崩 | 只能说明与缩放解码有关 |

**修复后实测**（两条 720p 源、rot=90、1/2 缩放解码）：

```
PgH264: zkmedia 环境 —— ZKMEDIA_H264_VBVSIZE=1048576
PgH264: zk_h264_player_init(1280,720,rot=0,flag=0x11) -> 0；缩放 1/2，旋转 90°(起播后下发)
PgH264: 解码回调 #240 —— fmt=5 640x384 crop(0,0,640,360)
PgStream: [HW] 已喂 300 包（硬件解码出帧 252，丢 0，媒体时间 12080ms / 播放 11573ms）  ← pid 全程不变
```

⇒ **49 条里那 14 条 720p 现在能播了**（走硬件播放器 1/2 缩放解码）。
`docs/h264-direct.md` 里也补了这条环境变量的说明。

### ★ 两条失败的教训（都别只看 PC 结论）

1. **CCTV-9 那条是"PC 通、设备不通"的典型**：`xykt-fix.github.io/Y77.m3u8` 只是**跳转壳**，
   真源在 `livehwc4.com` 的 CDN 上。**PC 的 OpenSSL 能握手，本板 ffmpeg 不行**：
   ```
   PgHls: 打开失败 https://v4-…livehwc4.com/play.kankanlive.com/live/….m3u8?…
   PgFf[ffmpeg]: error:14094410:lib(20):func(148):reason(1040)   ← sslv3 alert handshake failure
   ```
   ⇒ **PC 侧探测过不了"设备 TLS 栈"这一关**。凡是"跳转到别的域名的壳源"，都要在设备上回验一次。
2. **农安那条是源真失效**（PC/设备都 404）。区别对待：PC 也挂 = 源死了；只有设备挂 = 多半是
   设备侧 TLS/竞态（也可能是"刚停止上一条流、应用正在复位"的竞态，隔 5 秒重试即可）。

## 标准格式与规范化脚本（2026-09-14）

用户反馈"列表里的描述很乱"。原来的表（`tools/iptv_probe.py` 产物）有三个问题：
① 名字是英文 + 分辨率括号 + `[Geo-blocked]` 标记；② 同一频道多个源**重复出现**（CGTN 4 条）；
③ 分组带内部后缀（`国际·可播`）且没有频道号。

### 现在的格式（`resources/iptv/channels.m3u`）

```
#EXTM3U
# 实测 1280x720@25.00fps · 1030kbps          ← 探测脚本的实测值，列表副行显示
#EXTINF:-1 tvg-id="cctv-1" tvg-name="CCTV-1 综合" tvg-chno="1" group-title="央视",CCTV-1 综合
http://…
```

| 字段 | 说明 |
|---|---|
| `tvg-id` | 英文标识（同名频道的稳定 key，**全表唯一**） |
| `tvg-name` / **逗号后那截** | 频道名（**中文**）。⚠️ 设备端解析器读的是**最后一个逗号之后**的名字（见 `iptvLogic.cc` 的 `iptvLoadChannels`） |
| `tvg-chno` | 频道号（列表里的序号） |
| `group-title` | 分组：**央视 / 地方 / 国际 / 新闻 / 影视 / 其他** |
| `tvg-note` | 源的限制：`仅限国内`(=Geo-blocked) / `非全天播出`(=Not 24/7)，列表右侧琥珀色显示 |

⚠️ **那行 `# 实测 …` 必须写在对应 `#EXTINF` 的上面**：解析器是"遇到 `#EXTINF` 时用累积的注释"，
写在下面会**配错到下一个频道**（实测踩过：全表实测数据整体错位）。

### 生成链（两段，都可重跑）

```bash
python tools/iptv_probe.py -i cand.m3u -o resources/iptv/channels.m3u   # ① 实测（慢，真拉码流）
python tools/gen_channels.py                                            # ② 规范化（中文名/去重/排序）
python tools/gen_font.py                                                # ③ 字库（它会自动扫本表收字）
```

`tools/gen_channels.py` 做四件事，且**对"自己输出的表"幂等**（可以反复跑）：

1. 名字：拆 `[...]` → `tvg-note`；去掉 `(...)` 分辨率后缀；查 `NAME_MAP` 换中文（未命中会提示补映射）；
2. 去重：同一中文名只留一条源（默认取像素数最大；`PREFER_URL` 可显式钉住，如 CGTN 选 Rakuten 官方 CDN）；
3. 排序：分组顺序 → 组内按像素数降序；
4. 输出标准字段 + 重编 `tvg-chno`。

⚠️ **脚本的输入解析必须能吃自己的输出**（`# 实测 A · B` 与 `tvg-note="…"` 两种写法）。
第一版只认探测脚本的写法，结果**重跑一次就把实测数据/备注洗掉了**（都踩过）。

### 字库：频道表里的字必须进子集（否则**整个字消失**）

工程的 `font/*.ttf` 是**完全替换**系统字体的子集、没有逐字回退 —— 表里出现子集里没有的字，
那个字在列表里直接消失。实测：`嵊州综合` 的"**嵊**"不在 GB2312 **一级**字库（3755 字）里，
显示成"州综合"。

修法：`tools/gen_font.py` 增加 `collect_from_channels()`，**把整张频道表扫一遍收字**
（表随时会换，靠白名单必漏）。换表后重跑 `gen_font.py` 即可。
