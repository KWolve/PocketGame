# UI 改版：iOS 深色风格（圆角 + squircle 图标 + 分段控件）

> **检索命中条件**：问「界面怎么改成手机那样 / 圆角怎么做 / 图标要不要用汉字 / 按钮为什么
> 有一圈白边 / 运行时 setBackgroundPic 为什么把透明渲染成白 / 圆角图要不要烘底 /
> .9.png 九宫格在按钮上为什么不生效 / 一套配色怎么在 13 个页面里不漂移」→ 本文。

**落地时间**：2026-09-14 　**版本**：`v1.14.0` → **`v1.15.0`（第二版）**
　**范围**：13 个页面（main/wifi/remote/iptv/clocksuite/screensaver/calc/pomodoro/stopwatch/
timer/react/ime/statusbar）

> ⚠️ **第二版（v1.15.0）务必一起读 §8** —— 第一版有 3 个"看着改完了其实没生效"的陷阱
> （工具页第二份色表、运行时缺图会掉色、烘底与所坐底不匹配），以及主界面从"设置列表"
> 改成"桌面图标网格"。只看 §1~§7 会重复踩。

## 0. 一句话

**改版前**：全工程零圆角（285 个按钮、21 个图标、卡片、tab 全是直角矩形），
图标是「渐变正圆 + 中文单字」，130 处按钮共用同一个 `#26313F`。
**改版后**：iOS 深色令牌 + 全部控件上圆角 + 21 个 squircle 图标（白色符号）+ 三段式分段控件。

关键不是"画得好看"，而是**把形状做成基础设施**：`tools/ios_theme.py` 是色值与圆角的
**唯一真值**，`tools/gen_ui.py` 按"控件底色 → 九宫格资源"自动挂图 —— HTML 里一个
`data-pic` 都不写，285 个按钮一次到位。

## 2. 圆角的三条实现路径（★ 最重要的判断）

FlyThings 没有 CSS 引擎。实测（2026-09-14）**三条路径的行为完全不同**，用错就是白边或方角：

| 路径 | 谁用 | 能不能用九宫格 `.9.png` |
|---|---|---|
| **JSON `picTab`**（`data-pic0/1`） | 静态按钮（底色从不变） | ✅ 九宫格正确消费 marker 边，**四角真透明**，自带宽高两态 |
| **JSON `backgroundPic`**（`data-pic`/`data-bgpic`） | 窗口/面板；listview 子项（行卡片） | ✅ 同上 |
| **运行时 `setBackgroundPic()`** | 动态改底色的按钮（tab / 工具页按键 / 开关） | ❌ **九宫格的 1px marker 边会被渲染成一条 1px 白线** |

### ★★ 血案：为什么会有"一圈白边"

**现象**：tab 胶囊、音效按钮的最外圈恒为 `#FFFFFF`；圆角的羽化过渡是"白→实色"的糊边。

**排查**（对照实验，同一张 `ios_btn_select_r14.9.png`）：

| 控件 | 挂图方式 | 边缘实测 |
|---|---|---|
| 段容器 `BarSegTab` | JSON `picTab` | `x14..#000000  x17..#1C1C1E` —— **干净** |
| tab 胶囊 / 音效按钮 | 运行时 `setBackgroundPic()` | `x352..#FFFFFF` —— **恒白** |

**根因**：运行时那条路径**不保留 alpha**（透明像素渲染成白），而且
**九宫格四周那 1px 的 marker 边画在内容之外** —— 所以"把图里烘上底色"也盖不住它。

**修法（两条一起做）**：

1. **所有圆角图都烘底**（不再留透明）：四周烘上它**实际坐落的底色**
   （`_c` 后缀 = 烘面板底 `#1C1C1E`，无后缀 = 烘页面底 `#000000`），
   `gen_ui.py` 会按"这个按钮是不是在面板里"自动选。
2. **运行时挂的图必须是普通 PNG，不能用九宫格**：没有 marker 边就没有白线。
   代价是"一种 (样式, 尺寸) 一张图"，尺寸由 `gen_ui.py` 扫源稿的
   `data-noround` 自动收集（标注即生效，不会漏）。
   命名：`ios_rt_<style>_<W>x<H>.png`，由 `pg::roundedAssetFor(color, w, h)` 拼出来。

> ⚠️ 因此**不要**把这两类混起来：静态按钮走九宫格（省资源、自带宽高态），
> 动态按钮走普通 PNG（尺寸必须严格相等）。

## 3. 三个源稿标记（`gen_ui.py` 靠它们决定谁上圆角）

| 标记 | 写在哪 | 作用 |
|---|---|---|
| `data-noround="1"` | 按钮 | 该按钮**运行时会被逻辑改底色**，不许挂静态两态图（`setBackgroundColor` 会把 `backgroundPic` 清掉）。它的圆角由 `pg::applyRoundedBg()` 在"设底色"的那一刻顺手挂 |
| `data-round="panel"｜"panel2"` | 窗口 / 面板 / 输入框 | 挂圆角背景图（`ios_panel.9.png`）。**只给小面板**——整屏页面窗口是页面底，圆了会把屏幕四角切掉 |
| `data-untouchable="1"` | 纯装饰层 | `touchable=false`（如分段控件的容器底，别去吃分段的间隙点击） |

> ⚠️ 标记必须**从源 html 读**（`parse_marked`），因为 html2json 会丢掉不认识的 `data-*`。
> 比在 gen_ui.py 里硬编码 caption 清单抗漂移得多。

### 列表行卡片 = 一个静态子控件，**不是**行底色

行卡片写成 `item` 模板里的第一个子控件（`RowCard`，`data-bgpic="ios_card_row.9.png"`）。

* ⚠️ 子项分支只认 `data-pic` / `data-bgpic` / `src`，**`data-pic0` 会被静默丢掉**。
* ⚠️ 行卡片的九宫格**所有行长相相同**，所以"一张静态图"就够 ——
  不需要像图标那样"每行一个控件"（那是旧版为了"每行不同图标"才被迫做的）。
* ⚠️ **逻辑层必须删掉 `pListItem->setBackgroundColor(...)`**：它画的是直角矩形，
  而且会把图的四角填成方的（"底色与图片互斥"）。已改：mainLogic / wifiLogic /
  remoteLogic / iptvLogic。
* ⚠️ 列表行高必须取整：`row = (h - (rows-1)*spacing) / rows` 要整除，
  否则卡片与行错位 1px。改版时用脚本统一规范化了所有列表的 `data-h`。

## 4. 图标体系：squircle + 白色符号

`tools/gen_icons.py` 重写：

* **超椭圆（squircle）底**：`|x/a|^n + |y/b|^n = 1`，`n=5` —— 比"圆角矩形 rx=30%"
  更接近 iOS（四角过渡更鼓、边上没有明显直段）。
* **竖向双段浅渐变**（上亮 16% → 下暗 12%），不做对角渐变、不做噪声。
* **21 枚白色矢量符号**：每枚用几何图元（圆角矩形 / 圆 / 多边形 / **带圆头端点的直线**）
  在 4x 画布上画完再 LANCZOS 缩回 —— 天然满足 MCP「PNG 防锯齿五要素」。
* 为什么不用 emoji / 内置图标名：`gen_res` 内置的 46 个名字全是**通用操作**图标
  （play/back/settings…），没有"贪吃蛇""五子棋"这类应用符号；emoji 的风格与 iOS 不搭。
* 自检三件套：四角 `alpha==0`、中心有白色墨迹（**数一小块，不能判单点** ——
  中空符号如"五子棋"中心是洞）、不透明覆盖率 ≈0.95。

## 5. 改色板 / 改圆角的标准操作

```bash
# 1) 改 tools/ios_theme.py 的 TOKENS / RADIUS（唯一真值）
# 2) 若新增了"运行时按钮尺寸"，在源稿给它标 data-noround（gen_ui 会自动多出对应普通 PNG）
# 3) 重跑流水线（会重建全部圆角资源 + 转 json + 打 ftu）
python tools/gen_ui.py
# 4) 编、部署、抓帧验收
./fun.exe build && ./fun.exe launch
```

⚠️ **`PgSkin.cpp` 的 `kStyles` 是与 `ios_theme.py` 的跨语言对照表**（设备端没有 Python），
改色值必须两边一起改；漏了不会报错，只会"那几个控件退回直角"（`PgSkin` 会打一条 LOGD 提示）。

## 6. 验收（真机像素判据）

```bash
adb shell "echo 'saver to 900\nenter <行号>' > /tmp/pg_autostart"   # 进页面
adb shell "cat /dev/fb0 > /tmp/f.bin" && adb pull /tmp/f.bin .
```

* 帧缓冲几何：480×1600 双缓冲，`pan` 在 `0,0`/`0,800` 间翻；读 `rows[pan.y, pan.y+800)`；
  32bpp，**解码用 `Image.frombytes(..., 'BGRA')`**。
* **圆角判据**：从控件左上角沿 45° 对角采样，前 6~9px 应是页面底（黑），再进控件色。
* **白边判据**：控件最外 1px 不应出现 `#FFFFFF`（除图标符号的墨迹）。
* ⚠️ `data-noround` 之外还踩过：**主界面 QA 文件必须用设备端 `echo` 写**
  （`adb push` 一份 PC 生成的文件不会被识别）；`enter <n>` 的 n 是**分类内行号**（0 基），
  要先进分类：`cat 1` → `enter 3`（= 计算器）。

## 7. 一次性踩过的坑（本次改版新增）

1. **运行时 `setBackgroundPic` 不保留 alpha + 九宫格 marker 边会画成白线** → 见 §2。
2. **`html2json` 给没写 `data-bg` 的 `div.btn` 默认底色 `#374457`** —— 想"透明"必须显式写一个
   与背景同色的值（本项目用 `#1C1C1E`，与分段容器同色 ⇒ 视觉上等于隐形）。
3. **`ZKBase` 没有"清除背景图"的 API**（只有 `setBackgroundPic(path)`）⇒
   `PgSkin` 对识别不出的颜色**保持原样、不主动清空**（传 nullptr/"" 行为未定义、有崩溃风险）。
   纪律：**任何运行时颜色都必须在 `kStyles` 里查得到**。
4. **`LayoutPosition` 的成员是 `mWidth/mHeight/mLeft/mTop`**，不是 `width/height`。
5. **薄色条不要圆角**：阶段强调色条只有 8~10px 高，套 r8 会变成胶囊且角区重叠失真
   ⇒ `applyRoundedBg` 里加了 `h < 24 直接返回`。
6. **一次把 4 个源稿写坏的教训**：给列表批量插入子控件时把
   "相对下标"当"绝对下标"用了（`item_m.end()` 是相对 `txt[m.end():]` 的），
   结果插到了文件头的注释里并复制了一段正文。**批量改文件的脚本，下标必须用绝对位置，
   并且要按"从后往前"应用编辑**。事后靠"去掉重复块 + 补回文件头"修回来了 ——
   但这件事本身说明：**改源稿前先确认能回滚**（本项目没有 git）。

## 8. 第二版（v1.15.0）：桌面网格 + 渲染精细度

> **为什么有第二版**：第一版上机后用户反馈「还是有很多锯齿、不够简洁大方、希望至少像个手机 UI」。
> 排查发现**三个"看着改完了其实没生效"的陷阱**（都是"改了 A，实际跑的是 B"这一类），
> 外加主界面形态本身不像手机（是"设置列表"而不是"桌面"）。

### 8.1 ★★ 陷阱一：**第二份色表**（最贵的一个）

UI 改版时我改了 `src/logic/mainLogic.cc` 的 `toolBtnBg()`，但工具页实际用的是
`src/ui/ToolPage.cpp` 里的**另一份**：

```cpp
// ToolPage.cpp（改版前的旧值，我没扫到）
const uint32_t kBtnBg[4] = {0xFF26313F, 0xFF2E7D5B, 0xFF3A4250, 0xFF3A5A6E};
```

⇒ 番茄钟 / 计时器 / 秒表 / 计算器 / 反应计时**整片还是旧配色 + 直角**，
而那正是"最不像手机"的一批页面。**真机证据**：抓帧里出现 `#26313F`、`#3A5A6E`。

**修法**：把 4 档色表收成唯一真值 —— `platform/PgSkin.h` 的 `pg::toolBtnColor(style)` /
`toolBtnFg(style)`，`mainLogic.toolBtnBg()` 与 `ToolPage` 都转发过去。

**教训**：批量换色不能只 `glob('src/logic/*.cc')`。**要扫 `src/**/*.{cpp,h}`**，
并且**先用"改前独有的色值"反查**（例如搜 `26313F`）—— 有命中就说明还有漏网的色表。

> 语义（iOS 计算器同款）：`0 普通键 #2C2C2E / 1 主行动 #30D158 绿 / 2 次要 #3A3A3C / 3 强调 #FF9F0A 橙`，
> 亮底用**黑字**保对比度。

### 8.2 ★★ 陷阱二：运行时"只挂图不设色" ⇒ 缺图就掉色

第一版里 ToolPage 是 `setBackgroundColor(c)` 然后 `applyRoundedBg(v, c)`；
我改成"只调 `applyRoundedBg`"（想着它会连底色一起管），结果：

```cpp
applyRoundedBg()  // 找不到该 (样式,尺寸) 的资源时会直接 return —— 什么都不做
```

⇒ 计算器的**橙（运算符）/绿（=）键整片变成灰色**（沿用了 html 里的静态底色）。
真机症状：四个层级只剩两个。

**铁律**：**先设底色，再尝试挂圆角图**。
`applyRoundedBg` 是"锦上添花"，不是"设色的唯一入口"：

```cpp
btn->setBackgroundColor(c);
btn->setBgStatusColor(ZK_CONTROL_STATUS_NORMAL, c);
pg::applyRoundedBg(btn, c);   // 有资源就升级成圆角（内部会清底色）
```

### 8.3 ★★ 陷阱三：烘底必须匹配「**控件所坐的底**」

第一版给运行时按钮统一烘**页面黑底**，理由是"运行时控件都在页面上"。漏了一种：
**分段控件的选中胶囊坐在段容器（`#1C1C1E`）上**，烘黑底 ⇒ 胶囊四周一圈黑，
肉眼就是**锯齿 / 脏边**（这也是"锯齿感"的来源之一，不只是图形边缘）。

**修法**：给运行时资源加一维"所坐底"，`PgSkin` 显式传：

```cpp
enum OnSurface { ON_PAGE = 0, ON_CARD = 1 };   // 资源名后缀："" / "_c"
pg::applyRoundedBg(tabs[i], on ? 0xFF3A3A3C : 0xFF1C1C1E, pg::ON_CARD);
```

真机判据（改好后）：

```
容器→胶囊: 1C1C1E 1C1C1E 1C1C1E 343436 3A3A3C      ← 有 343436 这个中间色 = 抗锯齿正常
改前:       1C1C1E 000000 000000 3A3A3C 3A3A3C      ← 夹着黑 = 脏边
```

**口诀**：**烘底 = 把"圆角抗锯齿像素"和底色绑死。图坐错底，边缘必露异色。**

### 8.4 ★★ 陷阱四：**拆页后的遗留窗口**（改了没用的那份）

`ui/main.html` 里躺着 `WinClock`(8 键) / `WinCalc`(20 键) / `WinReact`，
`mainLogic` 里也还有 `syncToolButtons(page)` 在引用 —— 但**拆页后真正生效的是独立 ftu**
（`ui/pomodoro.html` / `ui/calc.html` / …，由 `pg::ToolPage` 驱动）。

真机判据是日志：`ToolPage: 就绪 slot=11 计算器（calcActivity，按钮 20）`。

⇒ 我一度把 `data-noround` 标在 `main.html` 的 `BtnK*`(106x68) 上，
而**真正要标的 `ui/calc.html` 按键是 108x64** —— 尺寸对不上 ⇒ 还是没有圆角。

**教训**：**先看日志确认哪份源稿在跑**，再动手。判断口径见 `docs/page-split-plan.md`。

### 8.5 主界面：设置列表 → **桌面图标网格**

原来每行一张圆角卡片 + 图标 + 标题 + 副标题 + 最高分（"设置页"观感）。
改成 **4 列 × 5 行桌面网格**：

| | 改版前（列表） | 改版后（网格） |
|---|---|---|
| 行卡片 `RowCard` | 每行一张九宫格卡 | **删除**（图标直接坐纯黑底） |
| 图标 | 64x64，靠左 | **72x72 居中** |
| 文字 | 标题 26 + 副标题 14 + 最高分 20(橙) + "最高分"标签 11 | **名称 14（居中）+ 最高分 11（灰）** |
| 格几何 | 1 列 × 5 行，行高 104 | 4 列 × 5 行，格 **112×107**，行距 6 |
| 黑色留白占比 | 32% | **71.8%**（留白 = "简洁大方"的来源） |

实现要点：
- `data-cols="4" data-rows="5"` —— listview 的多列模式；**`index` 自然变成"格序号"**，
  所以 `categorySlot(gCategory, index)` 与 `syncRowIcon(pListItem, slot)` **一行都不用改**。
- 21 个图标仍是"同位置重叠、按 slot 只显示一个"，坐标必须完全一致。
- `data-drag-max="0"`（20 格一屏放得下，不需要拖拽）。
- 删控件要**同步删逻辑引用**：`ID_MAIN_SubGameDesc` / `ID_MAIN_SubGameBestTag`
  随 html 消失后，`mainActivity.h` 里不再生成这些宏 ⇒ 逻辑层留着就编译失败。

### 8.6 渲染精细度：能改的与不能改的

| 项 | 结论 |
|---|---|
| 图标尺寸 | **必须 == 控件尺寸**（72==72）。不等 ⇒ 框架自己缩放 ⇒ 立刻锯齿。 |
| 图标超采样 | `SS 4 → 8`，再 LANCZOS 缩回（斜边/圆角更干净）。 |
| `json resolution` | 必须是 `480x800`。**不等于设备屏 = 整屏缩放 = 全糊**（本项目已是 480x800）。 |
| **文字抗锯齿** | **框架行为，SDK 无开关**（`ZKTextView` 只有 `setFontFamily`）。实测边缘过渡像素仅 4%~11%（良好 AA 应 15%~30%）。⇒ 只能从设计侧缓解：**减少小字号、少用纯白大对比**。 |
| 运行时挂图 | 不能用九宫格（marker 边会渲成白线）⇒ 普通 PNG + 烘底，见 §2/§3。 |

### 8.7 第二版验收（真机像素）

## 9. 第三版补丁（v1.15.2）：**整屏窗口是透明的**

> 用户报「桌面的背景覆盖上来了」—— 进游戏后，屏幕上方露出**主界面的一整行彩色图标** +
> 顶栏 + 分段控件，下方露出底部提示。

### 9.1 根因：html2json 把窗口的 `#000000` 变成了 `-1`

| 源稿写法 | 生成的 `backgroundColor` |
|---|---|
| `<div class="screen" data-bg="#000000">`（根） | **0** ✓ 正常 |
| `<div class="modal" data-bg="#000000">`（窗口） | **-1** ✗ 透明 |
| `<div class="modal" data-bg="#010101">`（窗口） | 65793 ✓ |

**html2json 把合法的"纯黑 0"当成了"没设置"**（`0` 是 falsy），于是给窗口写了 `-1` = 不画背景。
而 `-1` 在框架里就是"透明" ⇒ **整屏窗口盖不住下层**。

**为什么现在才暴露**：主界面原来是"列表"，窗口下方露出来的是深色行卡片边缘，看不出来；
改成 **4×5 图标网格**后，露出的正好是**一整行彩色图标**，一眼就看见了。

### 9.2 修法：白名单兜底（**不能"凡 -1 就填黑"**）

`gen_ui.py` 里新增 `fix_window_bg()`：只对 **`OPAQUE_WINDOWS`** 白名单里的整屏窗口，
把 `backgroundColor == -1` 兜底成 `0`（纯黑，与根节点一致）。

⚠️ **必须白名单，不能用"-1 就填"** —— **iptv 的视频播放页 `WinIptvPlay` 故意是透明的**：
视频是独立 disp 图层、在 UI 层**之下**，靠窗口透明才看得见画面；填黑 = 视频全黑。
（同理 `ime.html` 的 `KbPanel` 也保持透明。）

受影响并已修正的窗口（12 个）：`main` 的 WinGame / WinClock / WinCalc / WinReact /
**WinAlarmRing**（响铃页）/ **WinCast**（投屏页）；`wifi` 的 WinProbe / WinWifiPwd；
`remote` 的 WinRemoteLearn；`clocksuite` 的 WinClockSuite / WinWorld；`iptv` 的 WinIptv。
⇒ 响铃页与投屏页之前也会露出桌面，一并修好了。

### 9.3 真机判据

进游戏后扫描顶部区域（y 0..170）：

```
修复前: 分段控件色(#3A3A3C) 大量 + 彩色图标像素一片（y125..165 是黄/红/金图标）
修复后: 彩色图标像素 0 点，y75..170 全部 #000000 ✓
```

### 9.4 通用纪律

- **窗口类节点的背景色不要在源稿里依赖 `#000000`** —— 会被 html2json 丢掉。
  真要纯黑就写 `#010101`（肉眼无差），或者依赖 `fix_window_bg` 的白名单兜底。
- 判断"这个窗口该不该透明"的唯一依据是**它下面有没有东西要露出来**：
  盖在桌面/主页上的整屏页 → 不透明；**视频/键盘这类"贴在下层之上的叠层" → 透明**。
- 新增整屏窗口后，**抓一帧看上方/下方有没有露出上一层**（这是最容易漏的回归）。
