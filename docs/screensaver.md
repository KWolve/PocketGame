# 屏保大时钟（超级玛丽砖块钟）

> **需求演变**（本页改过三代，坑都留在本文档里）：
> - 2026-09-13：「30 秒不用回屏保，显示一个大时钟走时，要有很高级的翻页质感」→ 翻页钟。
> - 2026-09-14：加每日诗词 + 喜欢/不喜欢（联网抓取，见 §10）。

>    做一个超级玛丽的动画从屏幕左边走出来，然后到了分钟的小数据的位置跳起来顶一下砖块，
>    然后砖块的数字像金币一样弹出，再出来一个新的数字。整个屏保时钟的诗词，喜好按键都删掉，
>    背景风格采用超级马里奥游戏背景风格。」

## 0. 一图看懂

| y | 内容 | 说明 |
|---|---|---|
| 0..56 | 顶部黑条 HUD | SMB 计分板风；日期 / 星期白字直接写在上面 |
| 180..320 | **4 块砖 + 4 位金色数字 + 冒号** | 砖块与数字是**两层**（砖块能单独上顶、数字能单独飞出去） |
| 320..540 | 天空 / 星月 / 山丘 | ★ **金币飞行走廊**：云与月亮一律不许放进来（金币要飞 130px） |
| 540..600 | 悬空砖台 | 马里奥走在这上面（脚底 y=540） |
| 690..800 | 地面砖 | 白天=橙砖，夜空=深蓝砖 |

动画时间轴（每个整分一次，全部以"距整分的毫秒数 msToFlip"为自变量）：

| 时刻 | 画面 | 实现 |
|---|---|---|
| T-3.0s | 马里奥从屏幕**左外**走进来 | `x = f(msToFlip)`，走 3 帧循环 |
| T-0.7s | 走到第 4 块砖（分个位）正下方 → 起跳 | `h = JUMP_H*(1-(t/700)²)` |
| **T-0.0s** | 头顶到砖块（y=321 vs 砖底 320）→ 砖块**上顶 10px** | `msToFlip≤JUMP_MS`，抛物线顶点正好在整分 |
| T+0.0s | **旧数字当金币飞出**（横向压扁=旋转，飞 130px） | 数字控件自身改宽度 + 上移 |
| T+0.4s | **新数字从上方落下** | 数字控件 y 从 -26 落回 0 |
| T+0.7s | 马里奥落地 | 同一条抛物线 |
| T+1.9s | 马里奥走出屏幕右边 → 隐藏 | `x = g(since)` |

### ★ 进场时机（2026-09-18 补：进屏保恰好落在时间轴中间怎么办）

30 秒超时进入屏保是**随机落在时间轴某处**的，所以有三种"非正常进场"要处理
（不处理的话他会**凭空出现在屏幕中间**，一眼就是 bug）：

| 进场时刻 | 表现 | 实现 |
|---|---|---|
| 空闲段（距整分 > 3s） | 完整 3 秒走进来（正常） | `sEnterPhase = -1` → `wStart = 3000` |
| 前 3 秒窗口内 | **压缩走路**，仍从屏幕左外走进来 | `wStart = sEnterPhase`（进屏保那一拍的 msToFlip） |
| 前 3 秒只剩 <0.9s | **这一分钟不出场**（勉强挤一段会像瞬移） | `span < MIN_WALK_MS` → `sMarioSkip` |
| 撞砖后 1.9 秒窗口内 | **这一分钟不出场**（他本该正在往右走掉） | 进场时 `sMarioSkip = (60000-msToFlip <= EXIT_MS)` |

⚠️ 注意：数字照常变、金币照常弹、音效照常响 —— 只有"马里奥出场"这一段被跳过。

## 1. 进 / 出屏保：**框架负责，我们零代码**（2026-09-13 定的，没变）

- 进入：`setScreensaverTimeOut(30)` 之后，**30 秒无触摸/按键**由框架自动把屏保页显示出来。
- 退出：触摸或按键，框架自动收起。
- 所以 `screensaver.cc` 里**没有一行**"超时计时"逻辑。

### ⚠️ 坑 1：框架**不读** `EasyUI.cfg` 的 `screensaverTimeout`

出厂那份（`/res/etc/EasyUI.cfg`）与工程那份（`/tmp/EasyUI.cfg`）都写了 30，
运行起来 `getScreensaverTimeOut()` 仍然是 **-1**。
⇒ **必须用 API 显式设**（`mainLogic.cc` 的 `onUI_init`）：

```cpp
EASYUICONTEXT->setScreensaverTimeOut(30);
EASYUICONTEXT->setScreensaverEnable(true);
```

### ★ 工作界面（游戏 / 工具 / 投屏）里**不进屏保**

`EASYUICONTEXT->setScreensaverEnable(true/false)` —— 置 0 后框架的超时计时**根本不派发**。
做法：在**主循环里按当前模式收敛**（不散落在各进出点）：

```cpp
bool working = (gMode != MODE_MENU) || gStreamPageShown;
if ((int)working != last) { last = (int)working; EASYUICONTEXT->setScreensaverEnable(!working); }
```

| 场景 | 判据 | 实测 |
|---|---|---|
| 游戏里停 40 秒（超时 30s） | `logcat -d \| grep -c performScreensaverOn` | **0** ✅ |
| 返回主界面后停 40 秒 | 同上 | 正常进屏保 ✅ |

### ⚠️ 坑 2：时区 —— `setenv` 只影响当前进程

本板**没有 `/etc/TZ`**、`TZ` 也是空的 ⇒ `localtime()` 返回 **UTC**，屏保会比北京时间**少 8 小时**。
⇒ 抽出 `PgTime::ensureTimezone()`（幂等），在 `mainLogic` 的 `onUI_init` **开机就调**。
POSIX 的 TZ 是「本地 = UTC + (-偏置)」，所以**东八区写作 `UTC-8`**。

### ★ 任意按键退出屏保（2026-09-14）

框架按键分发是**短路式**的（任何一个 `IKeyListener` 返回 true 就停止往下发），
而屏保显示时下面的 Activity 只是 hide、监听器还挂在链上 ⇒ 屏保页自己的监听器**可能收不到**。
⇒ 收口成 `pg::wakeSaverByKey()`（`src/platform/PgSaver.h`），**每个按键监听器入口第一句**都调它。
2026-09-18 复验仍正常（`pginj key /dev/input/event3 108 80` → `屏保: 任意键唤醒 -> 退出屏保` ✅）。

## 2. 为什么做成 SysApp（而不是自己画一页）

`ui/screensaver.html` 这个**页名**就是开关 —— `fun` 认它，自动生成
`REGISTER_SYSAPP(APP_TYPE_SYS_SCREENSAVER, screensaver)`，`getAppName()` 返回 `"screensaver"`
→ 框架去 `resPath` 找 `screensaver.ftu`。另外 `fun install` 会生成 `src/logic/screensaver.cc`
脚手架（逻辑写在那里，`INIT_UI_TIMERS` 注册定时器、`onUI_Timer` 驱动动画）。

> 对照：`ime` 这个页名 fun **不认**（它只认 `screensaver`/`statusbar`/`navibar`）。

## 4. 动画：**全部由绝对时钟推导**（本次最重要的设计决定）

```cpp
static void saverNow(long *msToFlip, int *hh, int *mm, int *ss);  // gettimeofday + localtime_r
// msToFlip = (60 - tm_sec)*1000 - tv_usec/1000    ∈ [0, 60000)
// since    = 60000 - msToFlip                     = 距上一次整分的毫秒
```

`saverMarioPose(msToFlip, &frame, &x, &y)` 是**纯函数**，分段：

| 条件 | 相位 |
|---|---|
| `msToFlip ≤ 700` | 起跳（顶点正好落在整分）+ `frame=3`（跳帧） |
| `since ≤ 700` | 落回（同一条抛物线） |
| `msToFlip ≤ 3000` | 走进来（`x` 从 -80 线性到第 4 块砖中心 367），走帧 `(帧计数/4)%3` |
| `since ≤ 1900` | 往右走出屏幕 |
| 其余 | **隐藏**（屏面静止，绝大多数时间） |

★★ **为什么不用"每帧累加 dt / 帧计数器状态机"**：本项目在宠物页栽过两次 ——
定时器被挂起或掉帧时累加式相位会**永久漂**；而"帧指纹跳帧"那套优化会把 `update` 一起跳掉，
最后表现为**永久冻帧**。改成绝对时钟推导后：**掉多少帧都自己对齐，不会漂**。

★ **唯一用"动画时间"的是"金币弹出"**（440ms 飞出 + 170ms 落下）：它必须与"整分那一刻"严格对齐，
而它的起点本身就是由整分事件（数字变化检测）触发的 ⇒ 用累积的动画时间反而更稳、还好抓帧（配合 QA `slow`）。
⚠️ 每步只推进 `SAVER_MS`（25ms）一小段，`slow n` 只是**把步距拉开**（n × 25ms），
所以慢放时仍然能逐档抓到中间状态（这是"能不能验收"的关键，见 §8.1）。

### 4.0 时基：**40fps（SAVER_MS = 25）**—— 这是"卡"的那次修复

用户原话：「**4 个数字变化的时候页面很卡**」。量下来**逻辑侧完全无辜**（见 §8.3）：
节拍稳定 50/51ms、本页单拍 ≤1ms、进程 CPU 只 4%。真因是**视觉台阶感**：
面板 60Hz，而动画只有 20fps —— 金币每 50ms **跳一档宽度**（88→50→18→50 离散 4 档）、
一帧位移 16px，四枚同时飞就是"一顿一顿的"。
⇒ 三处改动：① 时基 50ms → **25ms（请求 40fps）**；② 金币旋转从"8 档离散宽度"改成
**连续余弦**（上升 ease-out、落下 ease-in）；③ 各种按"拍数"计的时长同步翻倍（预热 12 拍），
**并顺手把冒号闪烁改成绝对时钟定相位**（原来数拍，会跟着定时器分辨率漂）。

★★ **实测框架把 25ms 的定时器跑成 ~20ms（≈50fps）** —— 定时器有分辨率量化（请求 25 实得 20）。
所以：
- 动画比计划**还要顺**（50fps）；代价 CPU 4% → **10%**（静止 2%），板上完全吃得下；
- **凡是"数拍"的时长都会跟着这个偏差漂**（冒号会变成 400ms 而不是 500ms）⇒
  能用绝对时钟定相位的（冒号闪烁）就别数拍；`slow n` 的实际步距是 **n × 实测节拍 ≈ n×20ms**。

### 4.1 时间变化的判定

每拍（25ms，40fps）读一次时钟，与 `sCur[]` 逐位比较，不同就 `saverPopStart()`。
★ `sCur` 在 `saverPopStart` 里**立刻更新成新值**：显示会晚 610ms（金币飞完 + 新数字落下），
但"时间的真值"立刻对齐系统 —— 否则下一次比较会再触发一次弹出。

### 4.2 白天 / 夜间背景自动切（用户选的方案）

`saverApplyBg(hour)`：**6:00-18:00 白天（地上关），其余夜空关**；两张整图叠在同一位置，按可见性切。
> 为什么要有夜空版：屏保大多在夜里跑，整屏白天蓝底在凌晨很刺眼。
> QA `theme day|night|auto` 可以强制，`dump` 会打印当前背景。

## 5. 为什么本页控件**全是 `class="icon"`（textview + 背景图）**

55 个控件，**一个 `btn` 都没有**。两条收益（都是实测/生成链路上验证的）：

1. **不需要任何点击回调**：生成代码里 `onButtonClick_*` 出现 **0 次**
   （GENERATED 的 `INIT_UI_EVENT_BINDINGS` 只给 button 绑 CLICK 回调，
   而每个 button 都**必须**有同名 `onButtonClick_<Caption>` 函数，否则链接失败）
   ⇒ 少写 55 个空函数。翻页钟时代是 82 个 btn + 82 个空回调。
2. **`touchable=false`**（textview 缺省）⇒ 不会吃掉"任意触摸唤醒屏保"的那一下。
   实测：`pginj tap $TOUCH 240 400` → `performScreensaverOff...` ✅、导航栏回归 ✅。
   ⚠️ 触摸节点**每次开机不一定是同一个**：`EasyUI.cfg` 里写的是 `/dev/input/event4`，
   但 2026-09-18 实测设备上**只有 `event0`**（gt9xx），框架进程里打开的也是 `event0`
   ⇒ **以 `ls -l /proc/$(pidof zkgui)/fd` 为准**，否则 `pginj` 报 `open: No such file or directory`
   而现象只是"点了没反应"。详见 `docs/display-flip.md` §7。

写法（源稿）：

```html
<div class="icon" data-caption="Dig0_0" data-x="35" data-y="180" data-w="88" data-h="140"
     data-pic="images/mc_dig0.png"></div>
```

`class="icon"` + `data-pic` → `textview` + `backgroundPic`（**不是** `data-bgpic`，那是 btn 的）。
`textview` 的 `backgroundPic` 与 btn 一样**按控件盒缩放** ⇒ 改宽度就是横向压扁（金币旋转靠它）。

### ⚠️ 初始可见性必须走生成器（`patch_flipcards` + `HIDDEN_CONTROLS`）

- `html2json` **不支持 `data-visible`**，而且对 textview **根本不写 `visible` 字段**；
- 所以"只留数字 0、只留 ColonOn、4 帧马里奥全藏、夜空背景先藏"由
  `tools/gen_ui.py` 的 `patch_flipcards()`（正则 `^Dig(\d)_(\d)$`）与 `HIDDEN_CONTROLS` 落地。
- ⚠️ 控件改名（FlipU/FlipD → **Dig<位>_<数字>**）时必须同步改这两处，否则**一屏数字叠在一起**。

## 6. 坑（都实测踩过）

1. **`onUI_init` 里的 `setText` 会丢** —— 首次进入屏保时窗口还没真正上屏。
   ⇒ 进屏保后的**前 6 拍（300ms）**持续清缓存 + 重设一次（`sWarm`），稳定生效。
2. **判据要用 `EASYUICONTEXT->isScreensaverOn()`**，不能用 `mscreensaverPtr->isShow()`
   —— 后者在屏保**已经显示**时仍返回 false，用它会把整个 tick 挡掉。
3. **屏保 App 常驻 + 定时器不停**：SysApp 实例不像页面那样随开随建
   ⇒ tick 开头按 `isScreensaverOn()` 挡掉，否则 24h × 40fps 空转。
4. **QA 文件会被重放**：实例重建时 `sQaTag` 归零 ⇒ `onUI_init` 里先把文件当前内容记为基线。
5. **`digitalclock` 不支持居中对齐** ⇒ 日期/星期用普通 `text` + logic 自己格式化。
6. **负坐标会被 `html2json` 钳到 0**（`data-x="-80"` → `left:0`）：马里奥的"从屏幕外走进来"
   靠**运行时 setPosition**，首帧必须先 `setPosition` 一次（`saverMarioHide` 里把
   `sMarioX/Y` 置 -999 就是为这个）。
7. ★★ **同一份几何不许两处手抄**（2026-09-14 血案）：一处是"静态布局"、另一处是"运行时
   setPosition"，就一定会漂 —— 要么读回来（本次做法），要么只留一份。
8. ★★ **退出屏保后框架会停掉本页的定时器** —— 所以"退出侧要做的事"**不能写在 tick 里**。
   实测日志顺序：`performScreensaverOff` → `unregisterGlobalTouchListener` /
   `unregisterProtocolDataUpdateListener` / `unregisterKeyListener` → `onUI_quit` → **之后再没有本页 tick**。
   血案：屏保亮度恢复第一版写成"每拍按 `isScreensaverOn()` 收敛"，结果进屏保能调暗、
   **退屏保永远恢复不了**（唤醒后屏幕一直停在暗档）。⇒ 退出侧挂 `onUI_quit`（实测每次退出都会触发）。
9. ★★ **SysApp 实例是跨"进/退屏保"复用的** ⇒ `onUI_init` **不是每次进屏保都跑**
   （只在进程里第一次显示屏保时跑一次）。所以"每次进屏保都要做"的事（如调暗）必须挂在
   **刚进屏保的那一拍**（tick 里 `!sReady` 那个分支），不能在 `onUI_init` 里等。
10. ⚠️ **`LOGD` 是宏，带 `if/else` 必须加花括号**（本工程老规则，这次又踩）：
    `if (!h) LOGD(..); else ...` 直接报 `'else' without a previous 'if'`。
11. ★★ **"用户说卡"要先量，而且要先分清"性能卡"还是"视觉台阶"**（§8.3 有完整数字）：
    这台板上"动画卡"的**真因是帧率**（20fps vs 面板 60Hz），不是 CPU/线程被占满。
    判据三件套：**本页 tick 间隔 / 本页单拍耗时 / 进程 CPU** —— 三个都正常就说明不是性能问题。

### 8.1 一个必须记住的验收坑：**grab 比动画慢**

一次 `tools/grab.py` 往返 **~1.2~2.4s**（`cat /dev/fb0` + `adb pull`），而金币弹出只有 **600ms**
⇒ 直接连抓**永远抓不到**（实测第一轮 26 帧里金币一张都没抓到）。
**解法：QA `slow 20`**（每步 500ms，610ms 的金币动画拉成 ~12s）⇒ 8 张里稳拿 4 张飞行帧。
Mario 的走/跳是**绝对时钟**推导的、不受 `slow` 影响（这是刻意的：能放慢的只有"与整分对齐的那一小段"）。

### 8.3 「4 个数字变化时页面很卡」的排查记录（2026-09-18）

用户报「**4 个数字变化的时候页面很卡**」。按"先量再改"走了一遍，结论和数字都留在这儿：

| 量什么 | 怎么量 | 实测 |
|---|---|---|
| **本页 tick 间隔** | 每拍记 `gettimeofday`，每秒打印 平均/最大 | 静止 50/51ms；**最重场景（4 位全变 + 马里奥跳 + 音效）仍然 49~51ms** ⇒ 定时器没被拖 |
| **本页单拍耗时** | tick 开头/结尾各取一次时间 | **≤1ms**（最多一拍照改了 **49** 个控件）⇒ 我的代码不是瓶颈 |
| **进程 CPU** | `/proc/<pid>/stat` 的 utime+stime 差分 | 静止 1.8%；**动画中 4.2%** ⇒ 板上完全吃得下 |
| **金币"卡"在哪** | 慢放抓帧、量金墨 bbox 的**宽度序列** | 旧：`88/50/18/50`（4 档离散 = 每 50ms 跳一档）；新：`30/66/51/13`（连续过渡） |
| 面板刷新率 | `cat /sys/class/disp/disp/attr/sys` | `fps:60.9` ⇒ **60Hz 面板跑 20fps 动画 = 台阶感** |

⇒ 真因：**不是性能，是帧率**（20fps）。修法：时基 50→25ms（40fps）+ 旋转/升降改连续曲线
（`cosf` 连续宽度、上升 ease-out、落下 ease-in）。
修后复测：40fps 下动画 CPU **10%**、慢帧日志一条没有；金币宽度序列变成连续值 ⇒ 视觉平滑。

## 11. 音效 + 屏保亮度联动（2026-09-18 追加，用户拍板）

### 11.1 音效：撞砖"咚" + 金币"叮"

| 事件 | 音效 | 说明 |
|---|---|---|
| 撞砖（时间变化那一刻） | `SFX_HIT`（`audio/hit.wav`） | 每个"撞砖事件"**只响一次**，4 位同时变也只"咚"一下 |
| 金币飞出 | `SFX_SCORE`（`audio/score.wav`） | **延后 2 拍（100ms）**再响，听感才是"咚-叮" |

- **复用现成音效**，不新增 wav（`src/core/PgGame.h` 的 `SfxId` 表 + `resources/audio/`）。
- 播放走 `pg::pgHost()->playSfx(id)`（与时钟套件同一个宿主；宿主为空会**打日志**，不留静默无声）。
- ★ **"跟设备的静音键走"是自动成立的**：本板静音是写 codec 的 `SPK/LINEOUT Switch`
  （见 settings.cc 的文件头），静音后喇叭整个不响 ⇒ 这里不需要判静音。
- QA `sfx off` 可整体关掉（默认 on）。
- 日志判据：`PgAudio: 播放 audio/hit.wav` / `audio/score.wav`（真机实测两条都出现）✅

### 11.2 亮度联动：进屏保轻微调暗

- 进屏保 → 降到**用户亮度的 70%**（下限 45，且**绝不比用户设的更亮**）；退出 → 立刻恢复。
- 只有 `BRIGHTNESSHELPER` 这一条路（本板没有 `/sys/class/backlight`）。
- 亮度**不会被越调越低**：下限写成 `min(DIM_MIN, 用户亮度)` 再夹一次上限 —— 否则用户本来
  就把亮度调到 40 时会被"下限 45"给**调亮**，那就荒谬了。
- 真机实测：用户 80 → 屏保 56（QA `dim` 回读 **56**，不是只写了值）→ 唤醒恢复 **80**。
- QA `dim [on|off]`：开关 + 打印当前亮度/记住的用户亮度。

### 11.3 ★★ 防"卡在暗"：凭据落盘 + 开机自愈

`/data/pocketgame_saverdim.dat`（退化到 `/tmp`）里存**"进屏保前的用户亮度"**。
为什么必须有：应用若在**屏保显示中**被自愈重启，内存里的 `sSavedBright` 会丢 ——
新进程会把"已经调暗的值"当成用户亮度记下来，于是**永远暗着**。
有了这个文件，重启后的第一拍就先恢复用户亮度、再用它当基准重新调暗（基准永不被污染）。
实测（屏保中 `setprop ctl.restart zkswe`）：

```
屏保亮度: 开机发现上次调暗没收尾 -> 恢复 80      ← 新进程先恢复
屏保砖块钟就绪：10:33 ...
屏保亮度: 调暗 80 -> 56（退出恢复 80）           ← 基准仍是 80，没有被降成 56→45
```

> 这条需求的实现**暴露了两个框架行为**（已并入 §6 的坑 8/9）：
> ① 退屏保后框架**停掉本页定时器** ⇒ 退出侧逻辑必须挂 `onUI_quit`；
> ② SysApp 实例**跨进/退复用** ⇒ `onUI_init` 不是每次进屏保都跑，进屏保侧要挂"首拍"。

## 12. 挂绳倒挂：C 键整屏翻转 180°（2026-09-18 用户需求）

需求原文：「因为我的屏幕挂绳在底部，**屏保和机器人界面**如果按下 **C 按键**切换成倒 180 度显示。」
用户选定：范围**只这两页**、机器人页**短按 C = 翻转**（长按仍返回列表）、状态**落盘记住**。

**本页要管的三件事**（全部细节见 `docs/display-flip.md`）：

1. **上报"我在显示"**：`onUI_Timer` 顶部（在那句 `if (!saverOn) return` **之前**）
   `pg::flipSetPageOn(FLIP_PAGE_SAVER, saverOn); pg::flipTick();`
   —— 退出那一侧另外挂在 `onUI_quit`（框架退屏保就停本页定时器，理由同 §11 的亮度恢复）。
2. **C 键（108）改判**：走 `pg::wakeSaverByKey(ke)` 这个"所有按键监听器的统一入口"
   ⇒ 屏保里 C 键 = **翻转且不唤醒**（其它键照旧唤醒）。
3. **验收**：`tools/flip_qa.py`（10 个场景，逐像素）+ `tools/saver_qa.py --rot180`
   （倒挂时 `/dev/fb0` 里是倒着的画面，体检前要转回来）。

★★ **本页踩到的新平台事实**：同一个按键事件会被**投递 4 次**（DOWN×2 + UP×2，SysApp 链
与下面的 Activity 链各有一次）⇒ **有状态的按键动作必须幂等去重**。第一版没去重，
现象是"按一下 C，屏保直接没了"（翻转来回切一次 = 净零，抬起那侧还被当成"任意键唤醒"）。
详见 `docs/display-flip.md` §4。
